第 6 集　ReAct、Plan-and-Execute、Reflection 三种范式有什么核心区别？实际项目中该如何选型？
============================================================

仁菜：第六集。今天是杏仁豆腐。
桑多涅：嗯。今天这题看着是对比题，其实第一句话没说对就全崩。
仁菜：第一句话？
桑多涅：你先按你的理解排一下，这三种范式是什么关系。
仁菜：ReAct、Plan-and-Execute、Reflection —— 三种不同的做法，按任务复杂度选一个？
桑多涅：崩了。
仁菜：这么快？
桑多涅：Reflection 不是一套独立的完整流程。它是可以叠加在 ReAct 或 Plan-and-Execute 之上的质量增强 buff，不改变原本的做事流程，只是在原有基础上加一层自我检查和修正。
仁菜：所以不是三选一，是「二选一，然后决定要不要加第三个」。
桑多涅：这个理解对了。回答这题第一步就得把 Reflection 的定位说清楚，很多人会搞错，一上来就并排列三个，面试官立刻知道你只是背了名词。
仁菜：那前两个的核心区别是什么？
桑多涅：看「决策和执行的关系」。ReAct 是边想边干，走一步看一步，单步迭代实时调整，灵活度最高；Plan-and-Execute 是先想全再干，先定完整计划再分步执行，适合长流程复杂任务，不容易跑偏。
仁菜：这个上一集讲过。
桑多涅：所以今天讲选型。但在选型之前，先分清两个词，你现在肯定是混着用的 —— 设计范式和推理模式。
仁菜：……不是一个东西吗？
桑多涅：不是。设计范式是搭 Agent 的顶层做事流程框架，定的是整个系统从头到尾按什么大逻辑跑。推理模式是 Agent 每一步干活时脑子里具体怎么思考，是底层的思考逻辑。
仁菜：有点抽象。
桑多涅：打个比方：设计范式是公司的管理制度，推理模式是员工的干活方法。制度定的是流程怎么走，方法定的是每个人手上那件事怎么做。两者是一一对应的两层。
仁菜：这个比方一下就清楚了。
桑多涅：这题里 ReAct 既可以当推理模式说，也可以当设计范式说，所以最容易混。你自己心里要分清在哪一层讲。
仁菜：那选型看什么？
桑多涅：三个维度：任务复杂度、流程确定性、输出质量要求。
仁菜：有没有更好记的？
桑多涅：口诀：任务简单用 ReAct，流程长且复杂用 Plan-and-Execute，输出要求高再加 Reflection。说完再补一句「别过度工程化，够用就好」，面试官会觉得你有实际项目经验，不是只会堆技术。
仁菜：那如果面试官继续追呢？
桑多涅：有两个进阶方向可以接。第一个是动态 Replan，解决 Plan-and-Execute「计划定死了、中途遇到意外怎么办」的问题 —— 每执行完一步就把当前结果和剩余计划交给规划模块，让它判断原计划还合不合理，需要就生成新的剩余步骤。
仁菜：第二个呢？
桑多涅：Reflexion。普通 Reflection 是「做完检查一遍、发现问题就重做」，Reflexion 多做了一件关键的事：它把每次失败的原因总结成一段经验教训，存进记忆，下次遇到类似任务时作为上下文传给模型。
仁菜：这不就是错题本吗？
桑多涅：就是错题本。不只是改答案，还在本子上写「这类题容易漏掉符号变化，下次注意」，下次做同类题先翻一遍。
仁菜：这个有效果吗？听起来有点玄。
桑多涅：有数据。在 HumanEval 代码生成基准上，Reflexion 把 GPT-4 的 pass@1 准确率从大约百分之八十提升到了百分之九十一，提升超过十个百分点。
仁菜：十个点很多了。
桑多涅：而且这个数字说明的问题是：同样的基座模型，仅仅加了「反思加记住教训」这个机制，代码一次写对的概率就大幅提高。代码生成天然适合 Reflexion，因为代码可以运行、可以测试，执行结果就是最直接的反馈信号。
仁菜：面试报这个数字会不会显得太细？
桑多涅：恰恰相反。大部分人只会说「Reflexion 效果更好」，你能说出具体基准和具体数字，可信度完全不一样。
仁菜：那三种范式的成本差多少？总不能只谈效果不谈钱。
桑多涅：……这个问题问得不错。
仁菜：嗯？
桑多涅：没什么。举个具体例子算给你听。假设一个任务需要五步工具调用，每步产生的推理和工具结果平均占两千 token。
仁菜：好。
桑多涅：用 ReAct 跑，因为每次调 LLM 都要把完整历史带上，第一步输入两千，第二步四千，第三步六千，依次递增 —— 光输入就是三万 token，增长曲线是线性的，步骤越多越吃钱。
仁菜：那 Plan-and-Execute 呢？
桑多涅：消耗集中在规划和汇总两个大头。规划调一次，输入是任务描述加工具列表，大约三千；执行阶段每步只带当前步骤指令和前面步骤的结果摘要，不是完整推理历史，每步一千五，五步七千五；汇总再调一次，大约四千。加起来约一万四千五，比 ReAct 的三万低了一半多。
仁菜：再加上大小模型搭配……
桑多涅：token 数量差不多，但执行阶段用便宜模型跑，实际花费还能再降七成以上。加 Reflection 的话，每个需要反思的节点至少多一次 LLM 调用，评估一次，不达标还要重做。
仁菜：所以选型不只是看效果，还得看付得起哪个。
桑多涅：这句话你要是在面试里说出来，会比背三个定义强得多。
仁菜：今天好像被夸了两次。
桑多涅：……杏仁豆腐还行。下一集讲什么。
仁菜：任务拆分。下一集我们讲复杂任务怎么拆、为什么拆、拆完效果能提升多少。我是仁菜，我们下集见。
