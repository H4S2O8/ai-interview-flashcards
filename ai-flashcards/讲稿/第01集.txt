第 1 集　什么是 Agent？与大模型有什么本质不同？
============================================================

仁菜：欢迎收听《Agent 面试课》。我是仁菜，Agent 方向在读研究生。这一季我请到了一位重量级嘉宾 —— 愚人众执行官第七席，「木偶」桑多涅。她是这个领域的资深研究员。
桑多涅：先声明，我不是来做客的。我是为了那盒马卡龙。
仁菜：还有蛋糕！草莓千层，我排了四十分钟。
桑多涅：……所以你最好问点值得的问题。别浪费我的时间，也别浪费那个千层。
仁菜：放心。今天第一集：什么是 Agent，它和大模型到底差在哪。这题几乎每场面试都问。
桑多涅：也几乎每场都有人栽。开始吧，先说说你的理解，我听听值不值一盒马卡龙。
仁菜：那我说了啊 —— Agent 就是给大模型加了插件嘛，能联网搜索、能调 API，它就成 Agent 了。
桑多涅：错。照你这个说法，一个聊天产品开了搜索功能，它就是 Agent 了？
仁菜：呃……好像哪里不对。那我改一下 —— Agent 是能调用工具的大模型？
桑多涅：还是错。你两次都绕着同一个词打转，就是没说出来 —— 自主。
仁菜：自主……就是它自己决定调哪个工具？
桑多涅：太浅。自主规划、多步执行、感知结果再调整，这才是闭环。你给它一个目标，它自己把任务拆成多步，一步步做，每一步的结果反馈回来再指导下一步。听清楚，是「反馈回来指导下一步」，不是「一口气做完」。
仁菜：啊我懂了，这跟强化学习里那个感知—决策—执行的循环有点像？
桑多涅：……嗯。这次方向对了。经典 AI 里叫 sense-plan-act，Agent 的闭环就是它的现代版本：感知、规划、行动、再感知。别以为我在夸你，只是这个联想恰好没错。
仁菜：那我刚才那两个答法，问题是不是都出在只停在「行动」这一环，前面没规划、后面没反馈？
桑多涅：总算说到点上了。工具调用只是闭环里的一个动作，不是闭环本身。
仁菜：那咱们从头捋。要讲清楚 Agent 强在哪，是不是得先说普通大模型弱在哪？
桑多涅：这个顺序你倒是懂。不然你说的自主是空的，没有参照物。普通大模型有三个局限，环环相扣。第一个最直观：知识被冻结。训练数据有截止日期，你问它今天的天气、最新的股价，它一无所知。
仁菜：这个我熟，就像一个人毕业之后再也不看新闻，你问他今天发生了什么，他只能给你背课本。
桑多涅：比喻还行，留着面试用。第二个比第一个更本质：它不能行动。你让它发邮件、查数据库、执行一段代码，它只能告诉你「你可以这样做」，自己做不到。
仁菜：因为它说到底就是个文本生成器嘛，吐出来的全是字。
桑多涅：对。它能给你写出一封措辞完美的邮件正文，但点那个发送按钮的事，它是真做不了的。
仁菜：第三个我猜是记忆？每次聊天都从头开始那种。
桑多涅：不精确。是没有持续状态。每次调用之间完全失忆，除非你手动把之前的对话塞回去，不然它根本不记得上一轮说了什么，更别提跨任务记住你的偏好。记忆是结果，没有状态是原因 —— 面试的时候别把这两个说反了。
仁菜：这三个连起来听着有点惨 —— 知识是死的，手是没有的，记性还是断的。
桑多涅：难得你概括得比讲得清楚。加在一起，普通大模型只能做一问一答，稍微复杂一点、需要多个步骤协作的任务就完全无能为力。
仁菜：那 Agent 就是拿三样东西去补这三个洞？
桑多涅：别急着一一对应，会说错。是三件事在撑着那个闭环。第一件是工具调用，让它从说话变成做事。这里有个最容易误解的地方 ——
仁菜：我知道我知道！是不是模型自己去联网、自己去执行？
桑多涅：……恰恰相反。
仁菜：啊。
桑多涅：是你的代码在执行。模型只负责输出「我要调哪个工具、参数填什么」这个决策，通常是一段结构化的 JSON；真正去跑函数、访问网络、查数据库的是你的宿主程序。模型始终是大脑，不是手脚。这个叫决策与执行分离。
仁菜：所以我刚才那个想法就是最典型的坑。
桑多涅：而且是面试官最爱抓的那个。不过你踩得及时，现在错，总比在面试间里错强。
仁菜：那我扳回一城 —— 一份工具定义里到底写了什么？
桑多涅：三样：这个工具叫什么名字、它能做什么事、需要哪些参数。比如一个查天气的工具，名字叫 get_weather，描述里写清它查的是什么数据，参数说明要传一个城市名。
仁菜：等等，那执行的逻辑写在哪？
桑多涅：不在里面。这份定义里没有一行真正执行的代码，它纯粹是一份说明书。模型读了说明书，自己决定该调哪个、参数怎么填，就这样。这一点想不通，后面全是白搭。
仁菜：哦——所以它是招聘启事，不是员工本人。
桑多涅：……这个比喻可以。面试的时候用，别说是我教的。
仁菜：那工具调用具体怎么补上前面那三个洞？
桑多涅：这次可以一一对应了。知识被冻结？接上搜索引擎，它就能拿实时信息。不能行动？接上邮件接口、代码执行器，它就能真做事。原来只能用嘴说话的人，现在配了手、脚和一整套工具。
仁菜：给我举个具体的，我脑子里得有画面。
桑多涅：你给它配两个工具，一个查天气一个发邮件，然后说：帮我查北京天气，发邮件给我老板。它会分两步真实执行 —— 先调查天气的工具拿到结果，再把结果填进邮件内容调发送工具。每一步都真的发生了，不是在演。
仁菜：懂了。那第二件事是记忆吧？我猜是短期长期那一套。
桑多涅：这次没猜错。短期记忆是当前任务执行过程中的中间状态，比如第一步搜到了什么、第二步算出了什么，都放在上下文里，保证它不会做到一半忘了前面。长期记忆是跨任务的，用户偏好、历史记录，通常用向量数据库存，要用的时候做语义检索拿回来。
仁菜：第三件呢？我猜不出来了。
桑多涅：猜不出来才正常，这一点最常被忽略 —— 多步推理和自我纠错。它才是 Agent 区别于一个自动化脚本的关键。
仁菜：脚本不也能一步步跑吗？
桑多涅：脚本跑错了就崩了。Agent 某一步失败，它能感知到、分析原因、换一种方式重试 —— 关键词 A 搜不到就换 B，接口报错就读报错信息调整参数重来。碰到障碍会绕路，而不是一条路走到黑。
仁菜：这么一说，跟死循环的区别就是它知道自己撞墙了。
桑多涅：勉强算说对了。三件事凑齐，和普通大模型的差距一句话概括：从生成文字，到执行任务。
仁菜：那我试试造个对比 —— 你让普通模型帮你发天气播报邮件，它给你写一段「你可以这样写代码」；Agent 是真的去把邮件发出去了。
桑多涅：就是这个意思。你现在的状态比开场强多了，那盒马卡龙勉强算没白拿。
仁菜：有个事我一直好奇。Agent 这个概念很早就有了，为什么偏偏这两年火？是不是模型变强了就自然会了？
桑多涅：模型变强只是三分之一。第一，模型能力跨过了「能用」的门槛。早期模型你让它做任务拆解、判断下一步调哪个工具，它根本做不好；从 GPT-4、Claude 3 这一代开始，推理和指令遵循能力有质的飞跃。
仁菜：第二个是什么？
桑多涅：工具调用被标准化了。2023 年 Function Calling 出来，让模型能以结构化 JSON 输出调用请求，很快被各家跟进。有了统一协议，开发者才好给模型接外部能力；不然每接一个工具都要自己写一套解析逻辑，工程成本高到没人愿意做。
仁菜：第三个我猜是生态？框架、向量库这些。
桑多涅：嗯。开发框架把门槛拉低，向量数据库解决了长期记忆的存储，可调用的接口服务越来越多。三个条件凑齐，Agent 才从论文概念变成工程实践。少一个都不成。
仁菜：顺着这个问 —— 我最近老看到 MCP 和 A2A，看着都跟 Agent 有关，但我一直没分清。
桑多涅：分不清很正常，面试分不清就完了。先说 MCP，模型上下文协议，Anthropic 在 2024 年底提的。它解决的是一个很具体的工程问题：在它之前，每个 Agent 框架接每个工具都要写一套适配代码。
仁菜：那假设有 5 个框架、8 个工具……就是 40 套？
桑多涅：算得倒是快。M 个框架乘 N 个工具，这就是所谓的 M 乘 N 适配爆炸。MCP 的做法是定义一套标准的 JSON-RPC 协议，工具方按标准把能力暴露出来变成一个 Server，任何支持 MCP 的 Agent 通过内置的 Client 直接发现和调用，不用再写适配代码。
仁菜：那不就是给 Agent 的工具世界立了个 USB-C 标准。
桑多涅：业界就是这么类比的。它的架构分三层，面试最爱追：最外层是 Host，用户直接交互的 AI 应用；中间是 Client，负责建连接、管通信；最里层是 Server，真正暴露工具能力的服务。这三层背不下来，就别说自己懂 MCP。
仁菜：那 A2A 是不是同一个东西的竞品？
桑多涅：不是。你要是这么答，面试官立刻知道你没搞懂。A2A 是 Google 在 2025 年 4 月推的 Agent 间通信协议。MCP 解决的是 Agent 怎么调用工具，A2A 解决的是 Agent 怎么和另一个 Agent 协作。方向都不一样，谈何竞品。
仁菜：那 Agent 之间靠什么互相认识？
桑多涅：核心设计叫 Agent Card。每个 Agent 有一张名片，写着它能做什么、正在做什么、需要什么输入，别的 Agent 读了就知道怎么跟它配合。
仁菜：我懂了 —— MCP 是让 Agent 伸手拿工具，A2A 是让 Agent 之间能说上话。
桑多涅：……行吧，这句可以直接搬到面试里用。两者互补，各管一层。
仁菜：最后帮我收个尾。这道题最容易踩的雷是哪几个？我今天好像一个不落全踩了。
桑多涅：你确实全踩了，所以记得会比别人牢。第一，把 Agent 等同于插件或工具调用 —— 工具调用只是能力的一部分，不是 Agent 本身。第二，停在「能调工具」这一层，没点出自主性 —— 关键不是有工具，而是自己决定用不用、什么时候用、用哪个。第三，忽略执行闭环 —— 感知、规划、行动、再感知这个循环，才是 Agent 区别于普通大模型的核心机制。
仁菜：那反过来，正面该怎么答？
桑多涅：点三件事。一，Agent 有自主规划能力，给它一个复杂目标能自己拆成多步。二，它能行动，通过工具调用跟外部世界真实交互。三，它有闭环，每步结果会反馈回来指导下一步，而不是一次性生成完就结束。最后补一句最容易混的：模型本身只是大脑，工具的真正执行是你的代码，模型只负责决策。这么答，这题就满分。
仁菜：记住了 —— 主要是被打脸打得比较深。桑多涅，下一集还来吗？
桑多涅：下一集讲什么。
仁菜：Agent 的四个核心组件。
桑多涅：……那得再加一份提拉米苏。
仁菜：成交！下一集我们拆 Agent 的四个核心组件，看看这套闭环内部到底由哪几块拼起来。我是仁菜，我们下集见。
