第 2 集　Agent 的基本架构由哪些核心组件构成？
============================================================

仁菜：《Agent 面试课》第二集。我是仁菜。桑多涅，提拉米苏在这儿。
桑多涅：……放那儿吧。
仁菜：不先尝一口？
桑多涅：讲完再说。上一集你把 Agent 是什么答明白了，这一集拆开看它里面有什么。说说，你觉得一个 Agent 由几块组成。
仁菜：LLM 和工具？大脑加手。
桑多涅：漏了两块，而且漏的正好是让它能跑复杂任务的那两块。四个：LLM、工具系统、记忆系统、规划模块。
仁菜：记忆和规划……对哦，上一集刚讲过闭环，我怎么又忘了。
桑多涅：因为你还在用「能调工具就是 Agent」的思路想问题。这四块可以类比成一家公司：LLM 是老板，所有决策它拍板；工具系统是外包执行团队，老板说去搜就去搜、说发邮件就发邮件；记忆系统是档案室；规划模块是项目经理，拿到大目标负责拆成任务单。
仁菜：这个类比我记住了，面试直接用。
桑多涅：用之前先把每一块讲清楚，不然只是背了个顺口溜。先说 LLM 核心。它是大脑，所有输入 —— 用户指令、工具返回、记忆调出来的内容 —— 最终都要经过它理解和决策：下一步该干什么，是继续想、调工具、还是可以给答案了。
仁菜：这个不难理解。
桑多涅：但有个东西很多人忽略：System Prompt。
仁菜：系统提示词？那不就是写个「你是一个助手」？
桑多涅：那是没写。System Prompt 相当于给老板的岗位说明书 —— 在 Agent 开工之前就定好它的角色、行为边界、输出格式要求。比如做客服 Agent，你要写清楚它只回答产品相关问题，遇到不确定的信息要说不知道、不要编。
仁菜：听起来是挺重要，但……有那么重要吗？
桑多涅：实际工程里，System Prompt 的调优往往占掉开发时间相当大的一部分。它是你能最直接控制 Agent 行为的手段。你把它当摆设，Agent 的行为就是失控的。
仁菜：那 LLM 本身选哪个模型有讲究吗？我以为选最强的就完事了。
桑多涅：典型的外行想法。看三个维度。第一，推理能力 —— 它直接决定模型能不能正确拆解任务、选对工具。第二，工具调用的稳定性。
仁菜：这个是什么意思？
桑多涅：有些模型生成的 JSON 经常出错、参数乱填，导致工具调用失败。在生产环境里，这意味着大量的重试和 token 浪费。这一项在评测榜单上看不出来，得自己跑。
仁菜：第三个呢？
桑多涅：上下文窗口大小。Agent 每一步的工具返回结果都要塞进上下文，一个复杂任务跑十几步下来很容易撑满；窗口太小，后面的步骤就「看不到」前面发生了什么。所以模型选择不是越贵越好，是按任务复杂度、延迟要求、成本预算做权衡。
仁菜：那现在很火的推理模型呢？o1、o3、DeepSeek-R1 这种，拿来当 Agent 的大脑是不是更好？
桑多涅：在复杂任务拆解和多步决策上确实更好。但代价是延迟更高、token 消耗更大，不是所有场景都适合。
仁菜：所以要挑场合用。
桑多涅：常见的工程做法是搭配：推理能力强的大模型做核心决策，比如任务规划、关键判断；更快更便宜的小模型做简单活儿，比如意图分类、格式提取。按环节分配，不是一刀切。
仁菜：懂了。第二块，工具系统，上一集讲过了吧？
桑多涅：讲过原理，这里只强调一句：它是 Agent 和外部世界交互的唯一入口。LLM 本身不能上网、不能读文件、不能执行代码，所有这些限制都只能通过工具突破。
仁菜：那第三块记忆系统。这个我有把握 —— 短期记忆放上下文，长期记忆用向量库。
桑多涅：答对了一半。你说的是「怎么存」，但长期记忆本身还能再分类。借认知科学的说法有三种。
仁菜：三种？
桑多涅：语义记忆，存事实性知识，比如「这个用户是 Python 开发者」。情景记忆，也叫情节记忆，存的是具体经历，带时间线和因果，比如「上次处理退款问题时我们查了订单系统，发现已经过期了」。第三种是程序性记忆，存的是「怎么做事」的方法论 —— 把 Agent 做事的行为模式沉淀下来，下次遇到类似任务直接套用高效流程，而不是每次从头摸索。
仁菜：程序性记忆这个有意思，它存的不是事实，是套路。
桑多涅：可以这么理解。不过要说清楚，这只是便于理解的类比，实际系统里的实现通常就是向量检索加 metadata 过滤，不一定真分这么细。你面试时提一句能加分，但别说成工程标准。
仁菜：记住了。那记忆是不是存越多越好？
桑多涅：又想当然了。什么都往向量库里塞，检索出来的噪音会非常多，反而干扰模型的决策；存得太少又失去长期记忆的意义。比较好的做法是存入之前先做一轮重要性评估，只把真正有价值的信息持久化。
仁菜：那存进去的东西会一直有效吗？三个月前的记录还准吗？
桑多涅：……问到点子上了。这个机制叫记忆衰减。
仁菜：衰减？
桑多涅：给每条记忆加一个时间权重，越久远权重越低，检索的时候自然就排在后面。常用的做法是指数衰减 —— 相关性分数等于语义相似度乘以时间衰减因子。
仁菜：那衰减多快合适？
桑多涅：按业务定。客服场景衰减可以快一些，因为大多数对话是一次性的；法律合规场景就要慢得多，历史记录可能在很久之后还会被引用。你要是把这两个场景用同一套衰减参数，两边都会出问题。
仁菜：这个我没想到过。最后一块，规划模块。
桑多涅：它决定 Agent 能不能应对复杂任务。简单任务一步搞定，但你让它「写一份竞品分析报告」，它得先拆：搜索竞品资料、整理关键数据、对比分析、撰写报告。规划模块就是干这件事的。
仁菜：那这四块凑在一起，实际是怎么转起来的？
桑多涅：节奏很简单：规划、决策、执行、结果存入记忆、再决策，循环往复直到任务完成。LLM 始终是做决策的那个角色，工具系统是执行者，记忆系统让它不失忆，规划模块把大目标拆成小步骤。
仁菜：市面上那些框架是不是也是照这个搭的？
桑多涅：LangChain、LlamaIndex、AutoGen，本质上都是围绕这四个组件设计的，只是封装方式和侧重点不同。你把四块想透，看任何框架都不会晕。
仁菜：那这题的雷区是什么？
桑多涅：第一，组件漏答，只说 LLM 和工具，把记忆和规划忘了 —— 你开场就踩了。第二，对记忆的理解太浅，「记忆就是上下文」这个说法不完整，正确的说法是分两层：短期记忆在 context window 里存当前任务的中间状态，长期记忆用向量数据库跨任务保存偏好和历史，两者机制和用途完全不同。第三，工具系统的分工搞错 —— 模型不执行工具，它只输出调哪个、传什么参数，真正执行是你的代码。
仁菜：最后那条是上一集的内容，你又提了一遍。
桑多涅：因为面试官会在这题上再追一次。上一集听懂不代表这一集能答对，知识点是会串场的。
仁菜：……你其实挺上心的嘛。
桑多涅：我只是不想听你在同一个坑里摔两次。提拉米苏我带走了。
仁菜：下一集我们聊 Tools、Agent、Workflow 这三个概念到底怎么分。我是仁菜，我们下集见。
