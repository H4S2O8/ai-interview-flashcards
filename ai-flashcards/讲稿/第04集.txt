第 4 集　了解哪些其他的 Agent 设计范式？Agent 和 Workflow 的区别是什么？
============================================================

仁菜：第四集。桑多涅，今天没有甜点。
桑多涅：那我走了。
仁菜：别别别 —— 今天有个更重要的事。下个月我有一场模拟面试，师兄安排的，据说会按大厂标准问。
桑多涅：……所以？
仁菜：所以我想把这一季当成备考。你能不能……按面试官的标准要求我？该怼就怼。
桑多涅：我一直是按那个标准。你只是之前没意识到。
仁菜：那今天这题，你直接问。
桑多涅：好。Agent 和 Workflow 的区别是什么？
仁菜：Workflow 是提前把流程写死的，Agent 是让 LLM 自己决定下一步。
桑多涅：可以。核心一句话就是「谁来决定下一步」。Workflow 是我提前定好第一步做 A、A 完了做 B、B 失败了走分支 C，每一步的逻辑都是硬编码进去的，LLM 只是其中某个节点的执行工具，不负责决策流程本身。
仁菜：好处是行为可预测、容易测试、出了问题好排查。
桑多涅：坏处呢？
仁菜：灵活性低，遇到没预料到的情况就走进死胡同。
桑多涅：Agent 反过来，把「下一步做什么」的决策权交给了 LLM。你只告诉它目标，它自己判断该调哪个工具、该不该继续、什么时候算完成。好处是能处理你事先没设计进去的情况，坏处是行为不确定，同样的输入可能走出不同路径，线上出了问题也很难复现。
仁菜：这个我上一集听懂了。
桑多涅：那说说设计范式。除了纯 Agent，你还知道哪几种。
仁菜：ReAct……然后呢？就这一个。
桑多涅：不够。ReAct 是最常见的，但 Plan-and-Execute 和 Reflection 也必须说得出来。
仁菜：这两个是什么？
桑多涅：Plan-and-Execute 是把规划和执行解耦 —— 先让一个 LLM 专门做规划，输出完整的步骤列表，然后再逐步执行。好处是复杂任务的整体结构非常清晰，你甚至可以在执行前让人工审核一下计划是否合理。
仁菜：那 Reflection 呢？听名字像是反思。
桑多涅：在前两种范式的基础上加一层质量保障。Agent 完成一步或者整个任务之后，再让一个 LLM 来判断做得好不好、结果是否符合预期，不通过就重试或者换策略。在代码生成、文案写作这种「质量要求高但一次做对很难」的场景效果特别明显。
仁菜：这个听起来像是调试用的？我可以在开发阶段开着，上线关掉？
桑多涅：错。而且这是这题的经典误区。
仁菜：啊，又错了。
桑多涅：Reflection 是正式的运行时机制，内嵌在 Agent 的执行流程里，不是调试手段。它的代价是增加 token 消耗和延迟 —— 这个取舍在面试里经常被追问，你要能主动说出来。
仁菜：所以是「上线之后一直开着，但要为此付钱」。
桑多涅：这个理解对了。三种范式各有适用场景，而且不是互斥的，实际系统经常混着用。
仁菜：那生产环境里，是不是应该首选 Agent？毕竟它最灵活。
桑多涅：……你是不是没听上一集。
仁菜：呃。
桑多涅：纯 Agent 模式在生产里用得很少。三个原因：行为不确定，同样输入走不同路径；难以调试，出了问题不好复现；成本容易失控，一个复杂任务可能要跑十几轮甚至几十轮 LLM 决策。
仁菜：那真正的工程答案还是 Agentic Workflow。
桑多涅：对。整体用 Workflow 框住主流程保证可控，在需要灵活判断的节点嵌入 Agent 能力。能主动说出「为什么纯 Agent 在生产里有局限」，是这道题拿高分的关键 —— 大部分人只会夸 Agent 灵活，说不出它的代价。
仁菜：有没有更简洁的判断原则？我怕面试紧张想不起来。
桑多涅：Anthropic 在工程博客里给过一句，你背下来：能用 Workflow 解决的问题，就不要用 Agent。
仁菜：这听着有点反直觉啊，Agent 不是更聪明吗？
桑多涅：因为在生产环境里，可控性比灵活性更重要。Workflow 的行为是确定的，出了问题你能精确定位是哪个节点，修复也快；Agent 的行为是概率性的，测试覆盖率天然就低。
仁菜：那具体该怎么落地这句话？
桑多涅：从最简单的 Workflow 开始，只有当你发现某个节点确实需要灵活决策、写死的逻辑覆盖不了所有情况时，才把那个节点升级成 Agent。这个「从简单到复杂、按需升级」的思路，在面试里说出来是很加分的。
仁菜：我记一下……那如果面试官让我把两者对比一遍呢？
桑多涅：五个维度。决策者：Workflow 是开发者硬编码，Agent 是 LLM 动态决策。确定性：Workflow 高，行为完全可预测；Agent 低，同样输入可能走不同路径。灵活性：Workflow 低，流程固定；Agent 高，能处理预料之外的情况。
仁菜：还有两个。
桑多涅：调试难度：Workflow 容易，链路清晰；Agent 困难，行为不确定。适用场景：Workflow 适合流程相对固定的业务，Agent 适合需要灵活判断的复杂任务。五个维度背下来，这题基本问不倒你。
仁菜：那这一集的雷是什么？
桑多涅：第一，设计范式说不全，只知道 ReAct。Plan-and-Execute 把规划和执行解耦，Reflection 在执行后加自我评估环节，这两个必须说得出来。第二，把 Reflection 当调试手段 —— 你今天踩了。第三，也是最重要的：以为 Agent 是生产环境的首选。
仁菜：这三个我今天中了两个。
桑多涅：比上一集少了一个。
仁菜：……这是在夸我吗？
桑多涅：这是在陈述事实。模拟面试是下个月几号。
仁菜：二十三号。
桑多涅：那还有时间。下一集你自己说。
仁菜：下一集我们讲 Agent 的推理模式，重点拆 ReAct 到底是怎么实现的。我是仁菜，我们下集见。
