第 5 集　Agent 推理模式有哪些？ReAct 是啥？具体是怎么实现的？
============================================================

仁菜：第五集。桑多涅，今天的报酬是可丽饼。
桑多涅：……还行。今天讲推理模式。你先说说，什么叫推理模式。
仁菜：就是让模型一步步想，别一口气给答案？
桑多涅：方向对，但你说的是现象不是原因。为什么非要一步步想？
仁菜：因为……直接给答案容易错？
桑多涅：为什么容易错。
仁菜：呃……
桑多涅：LLM 是逐个 token 往后预测的。你问它一个需要多步推导的问题，它「一口气」给答案时，中间的推导步骤全是隐式的，没有任何机制强制它每一步都推对。误差会在中间某个暗处悄悄累积，最后给你一个看起来很自信、其实是错的答案。
仁菜：所以把过程写出来，就是给它一个「不能跳步」的约束。
桑多涅：可以这么理解。类比心算和笔算 —— 让你心算一个三位数乘法，你可能算错；把每一步写在纸上，错的概率大大降低。不是你突然变聪明了，是写下来的过程本身让你没法跳步。
仁菜：模型也一样。
桑多涅：一样。所以推理模式存在的根本原因就一句话：把隐式的思考过程显式化，减少多步推理中的累积误差。这句你背下来，开头就用它。
仁菜：那推理模式具体有哪几种？
桑多涅：从简到繁三种。最基础的是直接输出答案，没有任何中间推理。然后是 CoT，思维链，让模型先把推理步骤写出来再给答案。最后是 ReAct，在 CoT 的基础上加了「行动」。
仁菜：加了行动是什么意思？
桑多涅：CoT 只能在文字里推理，它没法获取新信息。ReAct 让模型交替输出思考和工具调用 —— 每次行动之后拿到结果，再根据结果继续思考。
仁菜：所以 ReAct 的循环是……思考、行动、观察？
桑多涅：Thought、Action、Observation，然后回到 Thought，如此循环。Thought 是模型分析当前局势、决定下一步；Action 是它决定调哪个工具、传什么参数；Observation 是工具执行后的真实结果被填回去。
仁菜：那这个循环一直转到什么时候？
桑多涅：转到模型在某一轮 Thought 里判断「信息够了，可以给最终答案」。
仁菜：等一下 —— 这个循环，是模型自己在循环吗？
桑多涅：……你居然主动问到了这个。
仁菜：因为上一集你说过「模型只负责决策」，我就想这里是不是也一样。
桑多涅：是一样。这是这题最常踩的误区：模型每次只输出 Thought 加 Action，然后就停了。是你的代码负责解析它的输出、执行对应的工具、把 Observation 填回历史，再把完整历史传给模型进入下一轮。循环是你的代码框架驱动的，不是模型在自己转。
仁菜：那我有个疑问。上一集讲的闭环是感知、规划、行动、再感知，这一集是 Thought、Action、Observation —— 这是两个循环吗？
桑多涅：不是。是同一个闭环的两个抽象层级。规划对应 Thought，行动对应 Action，感知对应 Observation。
仁菜：那为什么顺序看起来不一样？
桑多涅：入口不同。通用闭环从「感知环境」起步，那是机器人学 sense-plan-act 的传统；ReAct 从「思考」起步，因为模型拿到任务先推理。同一个圈，从不同的点开始数而已。
仁菜：这个我要是不问，面试的时候大概会当成两个东西背。
桑多涅：很多人就是这么背的，然后被追问一句「它俩什么关系」就答不上来。
仁菜：那 ReAct 有什么问题吗？听着挺完美的。
桑多涅：两个坑，都很实际，面试能主动说出来很加分。第一个叫循环漂移。
仁菜：漂移？
桑多涅：它每一步都是根据当前历史重新决策的，没有全局计划约束方向。你让它查某家公司近三年的营收趋势，它第一步搜了去年的数据，第二步看到搜索结果里提到竞争对手，觉得这个也挺有意思，第三步就跑去搜竞争对手了 —— 越走越远，把原来的目标忘了。
仁菜：步骤越多越容易跑偏？
桑多涅：对，因为历史上下文越长，里面的「诱惑」越多，注意力越容易被从原始目标上拉走。第二个坑叫错误传播：每一步的决策都建立在前面所有结果之上，中间某一步拿到错误信息，后面所有推理都被带跑。
仁菜：那它不能回头检查吗？
桑多涅：没有这个机制。它默认前面的 Observation 都是对的，一路往前冲。一旦错误出现在早期步骤，整条推理链后面全部白费。
仁菜：这两个坑，根源是同一个吧？
桑多涅：……说说看。
仁菜：都是因为它只往前走 —— 没有全局规划管方向，也没有反思机制纠错。
桑多涅：纯粹的前向推理。对，就是这个根源。你今天进步挺快。
仁菜：那怎么解决？
桑多涅：既然问题出在「没有全局规划」，最直接的思路就是先让模型站在全局视角把整个任务想清楚，列出完整计划，再一步步执行。这就是 Plan-and-Execute。
仁菜：上一集提过，把规划和执行解耦。
桑多涅：具体分两个阶段。第一阶段是 Planner，把任务目标交给 LLM，让它先别急着动手，站在全局角度想清楚：这个任务分几步、每步做什么、步骤之间的依赖关系是什么，然后输出一份结构化的执行计划。这一步的关键是只做规划、不执行任何工具调用。
仁菜：第二阶段就是执行了。
桑多涅：Executor 拿着计划按顺序执行。这里有个细节很多人不知道：执行器处理单个子任务时，内部仍然可以跑 ReAct 循环。
仁菜：啊？那不是又回到漂移的问题了？
桑多涅：不会。因为执行器始终知道自己在整体计划里处于哪一步、下一步要做什么，它是在一个被框定的小范围里跑 ReAct，不会像纯 ReAct 那样漫无目的地漂。
仁菜：这个区别挺关键的。
桑多涅：还有一个工程上的好处，很多人答不出来。规划和执行既然是两个独立阶段，它们完全可以用不同的模型。
仁菜：不同的模型？
桑多涅：规划阶段对推理能力要求高，用能力强的大模型保证计划质量；执行阶段每一步的任务已经很具体了，用便宜的小模型就够。这种「强模型规划、弱模型执行」的搭配，实际项目里能把 LLM 调用成本降低百分之七十到九十，任务质量几乎不受影响。
仁菜：为什么能省这么多？
桑多涅：因为规划只调一次，花费有限；执行要调很多次，每次都用便宜模型，总成本自然下来了。这也是 Plan-and-Execute 相比 ReAct 的一个隐藏优势 —— ReAct 每一步都是同一个模型又推理又执行，没法做这种差异化分配。
仁菜：那这一集的雷是什么？
桑多涅：最大的一个你今天自己躲过去了 —— 以为模型在自己循环。剩下的：ReAct 的两个局限要能主动说出来，循环漂移和错误传播；然后要能说清 Plan-and-Execute 是怎么通过先规划再执行来解决漂移的；最后提一句大小模型混合使用，会显得你真跑过项目。
仁菜：今天好像没怎么被打脸。
桑多涅：那是因为你终于开始在我说之前想了。可丽饼我带走了。
仁菜：下一集我们把 ReAct、Plan-and-Execute、Reflection 三种范式放一起对比，讲怎么选型。我是仁菜，我们下集见。
