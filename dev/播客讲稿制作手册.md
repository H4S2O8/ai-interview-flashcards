# 播客讲稿制作手册

面向接手后续板块讲稿生成的 agent。Agent 板块（16 集 / 102 分钟）已按本手册完成，
可直接读 `dev/gen_podcast_renna.py` 里的 `ep(1..16, ...)` 和 `dev/讲稿/*.txt` 作为范本。

仓库分两区：`dev/`（本手册、生成脚本、讲稿对白、TTS 缓存）和 `ai-flashcards/`
（生产目录，手机 remoteResource 同步的唯一范围）。生成脚本的产物 —— `podcasts_renna.json`、
`audio/renna/*.mp3`、`*.lrc` —— 写进 `ai-flashcards/`，其余一切都留在 `dev/`。
以下命令均在仓库根目录运行。

---

## 0. 一句话目标

**听完播客就不用再读原文。** 这不是复习节目，是替代阅读的讲解节目。

闪卡负责「记住」，播客负责「第一次真正搞懂」。所以讲稿不能是知识点朗读，
必须把原文里每一个结论的**来龙去脉、代价、边界**都讲出来。

判据：把讲稿给一个没读过原文的人听，他能不能答上这道面试题。

## 1. 硬约束（违反会出线上问题）

### 1.1 必须 1 题 = 1 集

App 按 `deck + qno` 查播客：

```ts
// article.tsx:54
loadPodcasts()?.decks?.[deck]?.[String(qno)]
```

集号必须等于原文题号。不能把两题合成一集，也不能把一题拆成上下集。
各板块集数因此是定死的：

| deck | 集数 | 原文总字数 | 目标讲稿字数 | 目标时长 |
|---|---|---|---|---|
| `tools` | 16 | 66,480 | ~30,000 | ~87 分钟 |
| `rag` | 20 | 76,292 | ~34,700 | ~100 分钟 |
| `llm` | 22 | 122,453 | ~55,700 | ~161 分钟 |
| `langchain` | 12 | 58,730 | ~26,700 | ~77 分钟 |

### 1.2 台词里不能出现制作意图

`lint()` 会拦，但只拦已知模式，写的时候就要避免。禁止出现：

- 「你听完这一集就不用看原文了」——这是我们的产品定位，不是角色会说的话
- 「听众看不到代码」「这档节目的目标是」——点破媒介和制作意图
- 「你口述一下」——像导演指令

角色只知道自己在一间屋子里聊天，不知道自己在录节目。
唯一的例外是每集开头的集号和结尾的「我们下集见」，这是已确立的节目惯例。

### 1.3 文本格式

`ep()` 的 turn 文本里**不能有半角双引号 `"` 和反斜杠 `\`**（会破坏注入的 Python 字面量）。
引用一律用 `「」`，破折号用 `——`。

### 1.4 数字一律写成中文

TTS 读阿拉伯数字和英文缩写混排会出错。

- ✗ `128K token` → ✓ `十二万八千 token`
- ✗ `80% 提升到 91%` → ✓ `百分之八十提升到百分之九十一`
- ✗ `2023 年` → ✓ `二零二三年`
- ✗ `3~5 倍` → ✓ `三到五倍`

英文技术名词保留原样（`ReAct`、`Prompt Caching`、`LangGraph`），TTS 读得出来。

## 2. 人设

### 仁菜（host，voice `4ca68a299cb24ae599dbb828dc31a73c`）

Agent 方向在读研究生。**跨板块不变**，她是整个系列的主线人物。

- 机灵，爱打比方，能触类旁通——经常把这一集的东西和前面几集串起来
- 但会想当然，会当场被打脸。**典型错误模式：一看到更强的方案就想选它**
  （「那是不是应该都用第三种？」），这个毛病要反复出现，因为它是真实面试的高频扣分点
- 有可爱的插科打诨，但不能喧宾夺主——每集一到两处就够
- 她的提问是听众的提问。她卡住的地方，就是听众会卡住的地方

### 桑多涅（guest，voice `aa62e4bc5fa647ff9438935b9f5e7f7b`）

愚人众执行官第七席「木偶」。被仁菜用蛋糕和马卡龙请来答疑。

- **傲娇但专业，一针见血。**先否定，再给实质内容
- 说话短、不寒暄、不铺垫。「错了。」「不够。」「翻车了。」
- 从不主动夸人。要表达认可时用事实陈述代替：「这算数据。」「这是在陈述事实。」
- 会主动指出面试里的雷区，因为她见过太多人栽在同一个地方
- 口头禅式的判据：**能说出代价和边界的人，才像做过项目的人**

**她的两个签名动作**（只照着「一针见血」写，会写出一个冷冰冰的机器人 —— S3 起草时踩过）：

1. **把学生的原话摘回来追问。**不直接纠正，而是把仁菜说的词拎出来打问号，逼她自己发现漏洞。
   S2E1：仁菜说「它就拿这段 JSON 去调 API」→ 桑多涅「停。『它就拿这段 JSON 去调』—— 谁？」
   → 仁菜「它啊。」→ 桑多涅「它是谁。」→ 仁菜「模型啊……」
2. **带刺的反问。**S2E1：「模型拿什么调？网线长在它身上吗？」

**打脸必须是多轮拉扯，不是一句话纠正。**让仁菜越挖越深，喜剧感和人味全在这个过程里。
一句话纠正完固然高效，但那是文档，不是对话。

**小善意藏在动作里，不说出口。**「坐吧。」「……你这个比方还行。」—— 她永远不会承认自己在意。

## 2.5 人味的量化闸（S2 全季实测区间）

写完必须自检。低于下限说明写成了信息交换，不是对话：

| 指标 | S2 实测区间 | 说明 |
| --- | --- | --- |
| 含语气词的轮次占比 | **51% – 93%** | 语气词 = 啊诶哦呀嘛呢吧哎唉嗯、省略号、破折号、感叹号 |
| 感叹号总数 | **3 – 15** | 一个都没有 = 一定出问题了 |
| 问号总数 | **10 – 31** | 追问和拉扯的直接体现 |
| 非知识轮占比 | **21% – 85%** | 不含技术术语的闲笔轮。术语由 check_script.py 从该集原文自动抽取，不写死 —— 写死过一次（照 rag 板块写的表），到 llm 板块 Transformer/Attention 全不认，导致此值虚高、压缩比也虚高 |
| 短轮（≤20 字）占比 | **8% – 45%** | 短兵相接的密度 |

配套脚本：`.venv/bin/python dev/check_script.py <讲稿.txt> --deck rag --qno N`
一次跑完硬约束、压缩比、人味指标、知识点覆盖。

**跨板块沿用她。**她的设定原本是「资深 Agent 研究员」，写其他板块时改成
「资深大模型工程研究员」即可（`GUEST_ROLE` 常量），一行的事。

理由：换角色就要换音色，而目前只有这两个验证过的 Fish Audio `reference_id`。
新角色需要用户提供新的 voice id，不要自作主张换。

## 3. 每集的写作规则

### 3.1 结构

固定五段：

1. **开场**（2–4 轮）——集号 + 甜点交接 + 桑多涅一句定调
2. **第一次打脸**（4–8 轮）——先让仁菜按直觉答一遍，答错，桑多涅指出错在哪。
   这一段承担「破除误区」，是全集最重要的部分
3. **主体**（30–50 轮）——按「解决什么问题」而不是「是什么」的顺序展开
4. **代价与边界**（5–10 轮）——什么时候不该用、贵多少、有什么风险
5. **收尾**（3–6 轮）——剧情推进一步 + 仁菜预告下一集 + 「我是仁菜，我们下集见」

### 3.2 长度

**每集 1800–2600 字，对应 5–7.5 分钟。**

已知偏差参考：Agent 板块第 1 集写了 3970 字（11.5 分钟）是超标的，
第 9 集 1334 字（4 分钟）是因为原文本身只有 5 个知识点——
**不要为了凑时长注水**，原文薄就短，但不能漏知识点。

压缩比（原文字数 ÷ 讲稿字数）实测落在 **1.8x–3.2x**。
超过 3.5x 基本意味着漏了东西，低于 1.6x 意味着在照读原文。

### 3.3 讲解手法

- **每个抽象概念配一个具体类比。**已用过的：心算 vs 笔算（推理模式）、
  错题本（Reflexion）、会议纪要体系（层级式摘要）、盖房子买水龙头（框架 vs 手搓）、
  接力赛（Handoff）、工作台和抽屉（context 卸载）。类比要日常，不要再用 IT 比喻解释 IT
- **每个数字都要给出处和前提。**「延迟降低百分之四十到六十」后面必须跟
  「但这个数字有前提——任务依赖要稀疏，且工具 I/O 占主要耗时」，
  否则听起来像背结论
- **不要读代码。**遇到代码块，改讲它在做什么、为什么这么做
- **串联前面的集数。**「这跟第七集讲的 Replan 触发条件是一回事」——
  这是让听众形成知识网络的关键，也是仁菜「触类旁通」人设的体现

## 4. 剧情线

有剧情不是为了好玩，是为了让人听得下去 100 分钟。Agent 板块用了四条，
可以直接沿用到后续板块（时间线接着往后走）。

| 线索 | 做法 |
|---|---|
| **甜点账本** | 每集开头交接一种甜点，逐集升级。已用：马卡龙、可丽饼、杏仁豆腐、费南雪、芝士挞、可露丽、巴斯克蛋糕、提拉米苏。这是最轻的一条，负责节奏 |
| **阶段性目标** | Agent 板块用的是「下个月二十三号的模拟面试」，第 4 集立、逐集倒数、第 16 集揭晓（过了，但栽在最后一讲的题上，正好引出该集内容）。后续板块需要一个新目标，比如「投了某家的简历，一周后一面」 |
| **仁菜的成长** | 从「这是什么」问到「为什么不是另一种」。中段开始能预判桑多涅的反驳，后段能主动指出适用边界 |
| **桑多涅的软化** | 从「我只是为了马卡龙」到不请自来、说漏嘴夸人。全季只给三到四个软化点，密度高了就不傲娇了 |

Agent 板块结尾停在：模拟面试过了，仁菜请桑多涅吃饭，
桑多涅撂下「下一季甜点标准要涨」。**后续板块从这里接。**

## 5. 逐板块大纲与注意事项

### tools · LLM 工具调用（16 集 / ~87 分钟）

协议密集：Function Calling、MCP、A2A、WebSocket/SSE/WebRTC、网关。

- **最大风险是变成协议规格朗读。**每个协议先讲「它出现之前大家怎么做、
  痛在哪」，再讲它怎么解决——不要一上来就报组成部分
- 第 2、10、13 集只有 3 张卡，但原文有 3500–4200 字。
  **卡片清单在这几集会严重低估知识点，必须直接读 `articles.json` 原文**
- 第 11 集（Function Calling / Skill / MCP 三者区别）和第 6 集（MCP vs FC）
  内容会重叠，写的时候要分工：第 6 集讲两者，第 11 集讲三者的坐标系，
  后者要明确说「第六集讲过两个，今天补第三个维度」
- 第 14、15 集（WebSocket/SSE/WebRTC）偏网络基础，是最适合用类比的两集

### rag · RAG（20 集 / ~100 分钟）

最工程、最落地的一个板块，也是最好写的。

- 数字密集（chunk 大小、召回率、性能指标），全部按 §1.4 转中文
- 第 4、5 集（切割策略、语义被切断）是全板块的地基，值得写足
- 第 9、18、20 集是经验题（「你用的向量库数据量级多大」「怎么量化效果」
  「最难的地方在哪」），**这三集考的是有没有真做过**，
  桑多涅要用「你要是没真吃过亏，就诚实讲你在小项目里踩到的那层，别装」这类态度
- 第 14、15 集原文各近 6000 字，是本板块最长的两集，注意别超 2600 字

### llm · 大模型工程（22 集 / ~161 分钟）

**最难的一个板块。**原文 12 万字，且大量是数学和架构。

- Transformer、RoPE、MoE、量化这几集**没有公式可念、没有图可看**，
  完全靠类比撑。这是全项目最吃写作能力的地方，不要赶
- 第 3、4、19、20 集原文都在 6700–7600 字，压缩压力最大。
  宁可讲透一半知识点也不要蜻蜓点水地全提一遍——
  **但要在结尾诚实地说「还有几个点这集没展开」，不要假装讲完了**
- 第 7 集（Scaling Law、涌现）7158 字，是概念最玄的一集，
  适合让仁菜多犯几次错来带节奏
- 第 14 集（KV Cache / Prompt Caching）和 Agent 板块第 12 集有重叠，
  可以让桑多涅说「这个你在 Agent 那边听过一半，今天讲底层」
- 桑多涅在这个板块的身份要调成「资深大模型工程研究员」

### langchain · LangChain（12 集 / ~77 分钟）

框架和 API 密集，集数最少。

- **风险是变成 API 名称朗读。**遇到类名、方法名，讲它解决什么问题，
  不要逐个念出来
- 第 9、10 集（LangChain vs LangGraph、LangGraph 优势）合计 23 张卡、
  15747 字，是本板块的重头，两集要分工清楚
- 第 8 集（LangChain4j / Java 生态）对听众可能是冷知识，
  让仁菜先问「这个有必要了解吗」，桑多涅回答为什么面试会问
- 第 11 集（大版本升级）是时效性内容，写之前**核对一遍当前版本状态**，
  不要照抄原文里可能已过期的版本号
- 这个板块和 Agent 板块知识重叠最多，串联前作的机会最多，用足

## 6. 操作流程

### 6.1 写稿

先在 `/tmp/` 起草，格式：

```python
EPS = {}
EPS[1] = ("集标题", [
    ("host",  "仁菜的话"),
    ("guest", "桑多涅的话"),
])
```

### 6.2 验覆盖（每集都要做，不要跳）

先从 `cards.json` 拉这一集的知识点清单作为**下限**，
再直接读 `articles.json` 的原文补充卡片没覆盖到的（卡片会漏，Agent 板块验证过）。
然后跑探针：

```python
import json
arts = json.load(open("articles.json", encoding="utf-8"))["decks"][DECK]
KEY = {1: ["关键词A", "关键词B", ...]}     # 手工列，一集 20–35 个
for n in sorted(EPS):
    txt = " ".join(t for _, t in EPS[n][1]); c = len(txt)
    src = sum(len(b["v"]) for b in arts[str(n)]["blocks"] if b["k"] in ("p", "li"))
    miss = [k for k in KEY[n] if k.lower() not in txt.lower()]
    print(f"{n:>3} {len(EPS[n][1]):>3}轮 {c:>5}字 {src/c:>4.1f}x  "
          f"{len(KEY[n])-len(miss)}/{len(KEY[n])}" + (f"  缺: {miss}" if miss else "  ✓"))
```

**探针会有假阴性**（写成中文数字、换了措辞），逐条人工确认，
不要看到 ✓ 就放心，也不要看到「缺」就乱改。

### 6.3 注入生成脚本

把 `EPS` 转成 `ep(n, title, [T("host", "..."), ...])` 追加到
`gen_podcast_renna.py` 的讲稿区。注入前断言文本里没有 `"` 和 `\`。

### 6.4 生成

```bash
.venv/bin/python dev/gen_podcast_renna.py --dry-run
```

体检 + 规模预估，不调 API。确认无越界台词、各集字数在 1800–2600 后：

```bash
.venv/bin/python dev/gen_podcast_renna.py
```

默认 5 并发，每轮一次 TTS 请求，结果按序号回收再拼接。
`--only 5,7` 指定集数，`--force` 覆盖已存在的 mp3，`--concurrency N` 调并发。

`dev/.tts-cache/` 按 `sha256(model|voice|rate|text)` 缓存分句 wav，
**改一个字只重新合成那一轮**，重跑不重复计费。

### 6.5 导出讲稿

```python
import json, pathlib
d = json.load(open("ai-flashcards/podcasts_renna.json", encoding="utf-8"))["decks"][DECK]
out = pathlib.Path("dev/讲稿"); out.mkdir(parents=True, exist_ok=True)
NAME = {"host": "仁菜", "guest": "桑多涅"}
for n in sorted(d, key=int):
    e = d[n]
    L = [f"第 {int(n)} 集　{e['title']}", "=" * 60, ""]
    L += [f"{NAME[t['s']]}：{t['t']}" for t in e["turns"]]
    (out / f"{DECK}第{int(n):02d}集.txt").write_text("\n".join(L) + "\n", encoding="utf-8")
```

### 6.6 时间轴与 LRC

逐轮合成天然带来精确时间轴：拼接是采样级的，静音长度是
`int(SAMPLE_RATE * gap)` 帧，所以每轮起点可以精确算出来，不需要做强制对齐。

```bash
.venv/bin/python dev/gen_podcast_renna.py --sync-only
```

用 `dev/.tts-cache` 里的分句 wav 算时间轴，**不调 API**，把 `ms` 写进 json 的每一轮
（以及集级 `ms` 总时长），同时导出 `audio/renna/NN.lrc`。
已生成过的集数可以随时补，改了讲稿重新生成后也会自动更新。

**坑：Fish Audio 返回的是流式 wav，头里 `nframes` 是占位符 `0x7FFFFF80`，
`wave.getnframes()` 拿到的是假值。**必须按实际读到的字节数算帧数。
`concat_wavs` 不受影响（`readframes` 读到 EOF 就停），所以音频本身是对的——
只有时间轴会算错，而且错得很隐蔽：不同集只要轮数相同，算出来的总长就一样。

实测精度：算出的总时长与 mp3 实测偏差 ≤51ms，且不随集长增长
（LAME 编码器固定延迟，不是累积漂移）。

App 端优先解析 `audio/renna/NN.lrc` 做同步滚动歌词；LRC 缺失时回退到 json 里每轮的 `ms`。
LRC 也可给外部播放器使用。

### 6.7 核对产出

```bash
python3 -c "
import json,subprocess,os
d=json.load(open('podcasts_renna.json',encoding='utf-8'))['decks']['$DECK']
for k in sorted(d,key=int):
    f=d[k]['audio']
    o=subprocess.run(['afinfo',f],capture_output=True,text=True).stdout
    sec=float([l for l in o.splitlines() if 'estimated duration' in l][0].split()[2])
    ch=sum(len(t['t']) for t in d[k]['turns'])
    print(f'{int(k):>3} {sec/60:>5.1f}m  偏差 {(sec-ch/346*60)/(ch/346*60)*100:>4.0f}%')
"
```

实测时长与「字数 ÷ 346」的偏差应在 ±10% 内。
偏差大说明某集丢轮或截断，回去查日志。

## 8. 发布到生产（master / 手机）

生成完成后，产物分三路走：

1. **mp3 → Cloudflare R2**（不进 git！仓库体积直接决定手机 remoteResource 拉取成败）：

   ```bash
   # 坑：wrangler 的 r2 object 命令默认 --local（本地模拟器，产物写进 CWD 的 .wrangler/），
   # 必须 --remote 才真的上传；或绕开 wrangler 直接用 REST API（Bearer 用 wrangler 的 OAuth token）：
   curl -X PUT "https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/r2/buckets/ai-flashcards-audio/objects/audio/renna/01.mp3" \
     -H "Authorization: Bearer $TOKEN" -H "Content-Type: audio/mpeg" \
     --data-binary @ai-flashcards/audio/renna/01.mp3
   ```
   对象键与仓库内路径一致（`audio/renna/NN.mp3`）。App 从 `audio.asylum.icu` 按需下载（article.tsx 的 `AUDIO_BASE`，Worker flashcards-audio 供流，带 Range）。

2. **podcasts_renna.json + audio/renna/*.lrc → master**（小文件，进仓库）：生成后到 master 工作区提交这两个路径，`script.json` 的 version 加一。

3. 推送 master 后手机 24h 内自动更新。

## 10. S4（llm 板块）实录补充

**桑多涅身份按 deck 切换**：`GUEST_ROLE_BY_DECK = {"llm": "……资深大模型工程研究员……"}`，
跑 `--deck llm` 时生效，不用手改常量。

**质量闸的四次修正**（都是闸自己的 bug，不是稿子的问题，记下来别再踩）：

1. **术语表不能写死。**原来照 rag 板块写了一张 KNOW 表，到 llm 板块 Transformer /
   Attention / softmax 一个都不认，导致「非知识轮」和「压缩比」双双虚高 ——
   E2 一度报 4.98x。改成从该集原文自动抽取（拉丁词 + 中文技术词），换 deck 不用改代码。
2. **非知识轮下限是假阈值。**原来的 50% 是拿旧关键词表算出来的。用新方法重算
   S1+S2，实际区间是 21%–85%，据此改成 25%。旧阈值会误杀正常集子。
3. **数字判定要放行技术专名。**取数字所在的最大 `[A-Za-z0-9.-]` 记号，含拉丁字母就放行 ——
   A2A / R1 / BM25 / GPT-4 / INT8 / V3 都过，「40」「2023」这种量词被拦。
   A2A、R1 在 S1/S2 生产讲稿里是既成写法。
4. **结尾惯例句窗口。**软化点常挂在签名之后：S2E16 隔四轮，S4E22 隔五轮。
   窗口放到六轮 —— 规则意图是「签名不能被埋掉」，差一格不构成被埋。

**压缩比上限警告值得当真。**S4 里触发了四次，其中两次是真漏（E12 漏了
「Beam Search 和 KV Cache 不兼容」整段、E18 漏了「参数化知识 vs 检索式知识」
和 RLHF 加剧幻觉的完整机制），两次是剧情重导致的度量假象（E13、E19）。

**语气词是最容易栽的指标。**我连续六集低于下限。量了 S2 才发现它的语感密度
主要靠**破折号**撑着（三十九到六十三轮的集子里有十到二十一处），那是这个节目的

**辅助工具**（`dev/rhythm.py`）：把平句里「短引子。展开说明」的第一个句号改成破折号，
是手工动作的固化。只动没有任何语气标记的轮次，引子长度限制在三到十四字。

**它可信到什么程度**：S4 全季 22 集共机械改了约三百六十处，事后做过一次系统扫描 ——
