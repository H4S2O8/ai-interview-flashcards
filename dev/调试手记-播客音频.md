## 当前精确症状（v2.5.4 实测，最重要的线索）

- `onReadyToPlay` 触发（就绪=是）、`play()` 返回 true（播放中=是）、`timeControlStatus = 2`（playing）
- 但 `currentTime` 恒为 0、无声 → **AVPlayer 在“播放”一个解码不出样本的东西**
- 缓存文件 `statSync().size` 与源 mp3 完全一致（大小对，内容存疑）

## 首要假设与下一步

**假设：真机上 `FileManager.writeAsBytes(path, Uint8Array)` 把字节写坏**（大小不变、内容不可解码）。v2.5.5 已改走 `Data.fromArrayBuffer(buf)` + `writeAsDataSync`，并在下载后校验文件头（合法 mp3 = `ID3` 或 `0xFF` 帧同步），`cachedFileOk` 也加了文件头校验 → 升级后打开会自动重下坏缓存。

**接手第一步**：让用户更新到 v2.5.5（autoUpdateInterval 现为 600s，10 分钟内自动拉），进原文页（会自动重下），看诊断行「头」字段：
- `49 44 33 ✓`（ID3）→ 文件是好的 → 假设转向 AVPlayer/音频会话层（可试 BackgroundURLSession 原生下载对比，或换一个已知能播的 mp3 放 R2 做 A/B）
- 其他值 + `✗非mp3` → 写盘通道仍坏 → 改用 `BackgroundURLSession.startDownload` 原生落盘（URL 无需 JS 字节层）

## 基础设施

- R2 桶 `ai-flashcards-audio`，对象键 `audio/renna/NN.mp3`（与仓库内路径一致）
- 自定义域名 `audio.asylum.icu` ← Worker `flashcards-audio`（源码本仓库 `dev/r2-worker/`，支持 Range；r2.dev 公开链接 R2_PUBLIC_HOST_REDACTED 也开着可当备用源）
- 上传：REST API `PUT /accounts/<ACCT>/r2/buckets/<BUCKET>/objects/<key>`（README 播客节有完整命令）或 wrangler `--remote`
- **坑**：wrangler 的 `r2 object put/get` 默认 `--local`（本地 miniflare 模拟器，产物写进 CWD 的 `.wrangler/`），必须显式 `--remote`
- wrangler 在 `/tmp/wrtools`（重启即丢，重装：`npm install --prefix /tmp/wrtools wrangler`）；OAuth token 在 `/tmp/xdg-config/.wrangler/config/default.toml`（重启丢，需重新 `wrangler login`，运行时带 `XDG_CONFIG_HOME=/tmp/xdg-config`）
- Cloudflare 账号 ID：`CF_ACCOUNT_ID_REDACTED`
- 手机同步机制：remoteResource 的 url 是「zip 或 Git 仓库」= 整仓传输，`/tree/master/ai-flashcards` 只是指定脚本根；所以 master 必须保持苗条（.gitignore 已防 mp3/.wrangler/dev/）
