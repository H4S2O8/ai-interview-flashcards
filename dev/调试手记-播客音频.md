## 当前精确症状（v2.5.4 实测，最重要的线索）

- `onReadyToPlay` 触发（就绪=是）、`play()` 返回 true（播放中=是）、`timeControlStatus = 2`（playing）
- 但 `currentTime` 恒为 0、无声 → **AVPlayer 在“播放”一个解码不出样本的东西**
- 缓存文件 `statSync().size` 与源 mp3 完全一致（大小对，内容存疑）

## v2.5.5 的假阴性（已定位并修掉）

报错括号里**是空的**：`文件头异常（，不是 mp3）`。`bytesToHex` 只有在
`Math.min(3, bytes.length)` 为 0 或 `NaN` 时才返回空串 —— 即真机上
`FileManager.readAsBytesSync(p).slice(0, 3)` 的返回值在 JS 侧**取不到下标和 length**。

所以 v2.5.5 报的是「读不出文件头」，不是「文件头不对」。它把一次 `written ===
buf.byteLength` 已经核对通过的下载判死了；`cachedFileOk` 用同一条读通道，于是缓存
永远判坏 → 重下 → 再判死，正好是「不管重试几次都一样」。

**结论：`readAsBytes*` 这条读通道在真机上不可用。**（写通道 `writeAsData` 大小对得上，
未见异常。）v2.5.6 起：读头一律走 `Data.fromFile(p).slice(0,4).toHexString()`，
且 `headIsMp3()` 返回三态 —— `null`（读不出）绝不当成坏文件。

**教训**：诊断代码本身也会骗人。任何「校验失败就阻断」的分支，都要先确认校验器读得到东西。

## v2.5.6 的主改动：绕开整条文件通道

`AVPlayer.setSource(filePathOrURL)` **文档第一个例子就是直接喂 `https://.../audio.mp3`**，
远程 URL 一直是支持的，前面五个版本没试过。R2 Worker 的 Range 已实测可用
（`206` + `content-range`），所以 v2.5.6 把音源默认切成在线流式，
`fetch → arrayBuffer → Data → writeAsData → 读回` 这条连挂 5 版的通道整条绕开。

本地缓存保留为第二音源，播放器卡片和出错卡片上都有一键切换，可直接做 A/B。

## 源文件已确认无罪

```
$ curl -sI https://audio.asylum.icu/audio/renna/01.mp3
content-type: audio/mpeg   content-length: 5505775   accept-ranges: bytes
$ curl -s -H "Range: bytes=0-1023" ... | xxd
00000000: fffb 50c4 ...  0049 6e66 6f       ← 裸帧同步 + LAME 的 Info 头
```
无 ID3，头是 `ff fb`。`headIsMp3` 认 `ff` 开头，没问题。R2 侧完全正常。

## 首要假设与下一步

让用户更新到 v2.5.6（autoUpdateInterval 600s），进原文页 —— 默认就是**在线**音源，
直接点播放。三种结果对应三条路：

1. **能正常出声** → 文件通道确实是唯一病灶。收尾：撤诊断行、`autoUpdateInterval`
   恢复 86400，本地缓存那条路要么修好要么删掉（在线已够用，代价是没有离线）。
2. **在线也是「就绪=是 / 播放中=是 / 状态=2 / 时间恒 0 / 无声」** → 跟 v2.5.4 一模一样
   → 与文件**无关**，病灶在 AVPlayer / 音频会话 / 输出路由层。下一步查：静音拨片、
   `SharedAudioSession` 到底激活成哪个 category（把成功的那一档也打到诊断行）、
   换一个已知能播的公网 mp3 做对照。
3. **在线报错**（setSource false / 25s watchdog / onError）→ 记下诊断行原文，
   同时切「音源：本地」跑一遍，看「头」字段现在读出的十六进制是什么。

诊断行读法（v2.5.6）：`音源 · 缓存 · 头 · 就绪 · 播放中 · 状态 · 时长`。
「头」在在线模式显示「在线不适用」；本地模式下 `fffb...✓` = 文件好，
`读不出` = Data 通道也读不到（那就别再纠结校验，直接用在线），
`✗非mp3` = 写盘确实坏了 → 此时才轮到 `BackgroundURLSession.startDownload`。

## 基础设施

- R2 桶 `ai-flashcards-audio`，对象键 `audio/renna/NN.mp3`（与仓库内路径一致）
- 自定义域名 `audio.asylum.icu` ← Worker `flashcards-audio`（源码本仓库 `dev/r2-worker/`，支持 Range；r2.dev 公开链接 R2_PUBLIC_HOST_REDACTED 也开着可当备用源）
- 上传：REST API `PUT /accounts/<ACCT>/r2/buckets/<BUCKET>/objects/<key>`（README 播客节有完整命令）或 wrangler `--remote`
- **坑**：wrangler 的 `r2 object put/get` 默认 `--local`（本地 miniflare 模拟器，产物写进 CWD 的 `.wrangler/`），必须显式 `--remote`
- wrangler 在 `/tmp/wrtools`（重启即丢，重装：`npm install --prefix /tmp/wrtools wrangler`）；OAuth token 在 `/tmp/xdg-config/.wrangler/config/default.toml`（重启丢，需重新 `wrangler login`，运行时带 `XDG_CONFIG_HOME=/tmp/xdg-config`）
- Cloudflare 账号 ID：`CF_ACCOUNT_ID_REDACTED`
- 手机同步机制：remoteResource 的 url 是「zip 或 Git 仓库」= 整仓传输，`/tree/master/ai-flashcards` 只是指定脚本根；所以 master 必须保持苗条（.gitignore 已防 mp3/.wrangler/dev/）
