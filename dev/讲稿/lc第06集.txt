langchain第06集　LangChain 中的短期记忆和长期记忆分别怎么实现？
============================================================

仁菜：欢迎回来，我是仁菜。今天……我没买。
桑多涅：我知道。糖不甩，楼下那家，趁热。
仁菜：你带的啊？
桑多涅：你昨天说你没时间。我不想看你空着手来，还要解释十分钟。
仁菜：……那我下次也不解释了。进度：还剩四周，昨天那一百三十行删完了。
桑多涅：那今天讲记忆。短期和长期，分别怎么实现。
仁菜：短期记忆就是把最近几轮对话放进 Prompt，长期记忆就是把全部聊天记录存进向量数据库。
桑多涅：……全部聊天记录都值得长期保存吗？当前线程的状态由谁管理？用户换一个会话之后，以前的偏好从哪里读回来？
仁菜：那……用 ConversationBufferMemory 和 ConversationSummaryMemory？
桑多涅：……你这个答案是从哪一年的教程上抄的。
仁菜：……网上搜的第一条。这个真不是我装的，我以为它还是主流。
桑多涅：那是 Chain 时代的抽象，现在主要在 langchain-classic 里。维护存量项目用它没问题，但新项目它不是主路径。主路径是三句话：AgentState 加 Checkpointer 管线程内状态，Store 加 namespace 管跨线程长期记忆，Middleware 或者图节点管裁剪、摘要和写入策略。
仁菜：……等一下。记忆这块，上一季 RAG 不是已经讲过了吗？向量库、召回、切块，我做了三个月。
桑多涅：那你说说，上一季讲的是什么。
仁菜：……怎么把一堆文档找回来。
桑多涅：对。上一季讲的是检索本身 —— 怎么切、怎么存、怎么召回、怎么评。今天讲的是框架把记忆抽象成了什么。
仁菜：……抽象成什么？
桑多涅：抽象成作用域。检索是手段，作用域是设计。你上一季学会了怎么找回来，这一季得先回答：这条信息该活在哪个范围里。
仁菜：所以第一步不是选数据库啊。
桑多涅：第一步永远不是选数据库。举个例子 —— 用户在规划一趟旅行，他说了日期、预算、下一步打算去哪。一周后他新开一个会话，Agent 还知道他不吃辣、喜欢住地铁附近。
仁菜：前面那些是短期的，只服务这一次；后面那些是长期的，跨会话还有效。换成我们的产品 —— 本次工单号、当前排查到哪一步，短期；用户的机型、历史投诉记录，长期。
桑多涅：对了。那短期怎么落地。
仁菜：……State？
桑多涅：create_agent 底层跑在 LangGraph 上，Agent State 默认带 messages，也可以扩展 —— 订单号、当前步骤、工具调用次数，都能塞进去当业务字段。
仁菜：那 State 就够了吧？
桑多涅：请求可能落在不同的服务实例上，进程也会重启。
仁菜：……那 State 就没了。
桑多涅：所以要 Checkpointer。调用的时候传一个稳定的 thread_id，同一个编号就能恢复同一条线程。示例里那个 InMemorySaver 只适合本地演示 —— 进程一退状态就丢，线上必须换成持久化实现。
仁菜：那 Checkpoint 里存的就是聊天记录咯。
桑多涅：……你再说一遍。
仁菜：……不是？
桑多涅：存的不是聊天字符串，是图执行过程中的 State 快照。聊天记录只能告诉你说过什么；快照能告诉你走到了哪一步、哪个工具调过了、中间结果是什么。
仁菜：……所以它能从中间接着跑。那暂停恢复、人工审批、故障恢复，全靠这个。
桑多涅：对。这就是它和一份聊天记录的全部差别。
仁菜：人工审批！前天你讲七步的时候说要留人工审批的口子，我回去自己写了个状态表 —— 存到哪一步、等谁批。八十来行。
桑多涅：……Checkpointer 本来就在做这件事。
仁菜：……又是。
桑多涅：记着这个感觉，这一季你还会碰到几次。下一个问题 —— Checkpointer 能保存全部历史，是不是每次都该把全部历史交给模型。
仁菜：……应该不是。消息越多，Token 越贵，延迟也会涨。
桑多涅：第三个最容易被忘。
仁菜：……干扰？
桑多涅：无关的旧消息会把模型带偏。所以要治理，常用三种手段。
仁菜：裁剪、摘要，还有……删除？
桑多涅：三个的区别说准了，这题就答对一半。裁剪只减少本次给模型的输入，持久状态一点没动；删除是真的从持久状态里移走；摘要是用更短的文本保留主要语义。
仁菜：那能不能就定一条规则，永远只保留最近十条？听起来很省事。
桑多涅：客服 Agent 里，用户的工单号和你答应过的承诺，在第十一条。代码 Agent 里，最新的报错和刚改过的文件，也可能在窗口外面。
仁菜：……那就全丢了！所以不能只按条数。
桑多涅：要结合 Token 预算、消息角色和业务重要性一起定。这句是加分句。
仁菜：记下了。那长期记忆呢？
桑多涅：先问你 —— 新开一个 thread_id，默认继承旧线程的 State 吗。
仁菜：不继承吧。……我一开始真以为这是个 Bug，还去翻了半天文档。
桑多涅：这是正确的线程隔离，不是 Bug。要跨线程用的信息，得提炼出来写进 Store。Store 用 namespace 加 key 加 value 定位，namespace 通常包含租户、用户和记忆类型。
仁菜：为什么一定要带租户呢？
桑多涅：两个客户公司的用户重名了，你猜会发生什么。
仁菜：……串。
桑多涅：读的时候，已知 key 就精确读取；要按语义从多条记忆里找，才配向量索引再搜。
仁菜：那不就是上一季那套吗？
桑多涅：手段是那套。但记住一句 —— 向量检索只是召回方式，不代表所有聊天记录都该成为长期记忆。
仁菜：……我今天开头就是这么答的。
桑多涅：所以让你吃糖不甩。你猜为什么叫不甩。
仁菜：……糖裹在丸子上，甩不掉。
桑多涅：你那个全存进向量库，就是这个。存的时候一时爽，之后甩不掉 —— 噪声、冲突、隐私风险，一样都少不了。
仁菜：……这个比喻你是特意等到今天才用的吧。
桑多涅：……买的时候没想那么多。那什么该写进去。
仁菜：用户明确说请记住的？
桑多涅：那种可以在主链路里实时写入，让它立刻生效。从对话里推断出来的偏好，则交给会话结束之后的后台任务，提炼、去重、脱敏，再写。
仁菜：为什么不当场写呢？
桑多涅：当场写你来不及判断它对不对，也来不及查它和旧记忆冲不冲突。写进去的时候还要带来源、时间、置信度，而且必须支持更新、纠错和删除。
仁菜：那用户的账户余额，我是不是也可以记下来省一次查询——
桑多涅：不行。订单金额、账户余额、库存，这些是实时事实，永远查权威业务系统。长期记忆不能代替真实数据库。
仁菜：……记错一次就是事故。那工具怎么拿到这些东西？ToolRuntime 吧，昨天讲过。
桑多涅：昨天你只用了一个入口，今天把三个说全。
仁菜：runtime.state 是当前线程的短期状态，runtime.context 是可信身份和权限，runtime.store 是跨线程的长期数据。
桑多涅：能不能混成一个数据袋，用的时候随便取。
仁菜：……不能。作用域不一样。而且 user_id 得从 context 注入，不能让模型填。
桑多涅：两个不同的 thread_id，只要可信 user_id 相同呢。
仁菜：访问同一个长期记忆 namespace，换会话也认得他。另一位用户则被 namespace 和服务端权限隔离在外面。
桑多涅：这段答完，面试官会问你上过线没有。生产上有四关，你说得出几关。
仁菜：第一关……数据能不能可靠存下来？
桑多涅：对。数据库型的 Checkpointer 和 Store，表结构和迁移要一起进部署流程。第二关。
仁菜：……这是谁的记忆。thread_id、tenant_id、user_id 都要来自可信身份体系，不能信模型生成的身份，也不能让客户端随便指定别人的 namespace。
桑多涅：这一关破了会怎样。
仁菜：……记得越多，泄得越多。
桑多涅：第三关。
仁菜：嗯……记忆会过时、会冲突、会被用户纠正，所以要能去重、更新、过期淘汰。还有 —— 用户得能查看、更正、导出和删除自己的记忆。敏感信息默认不记，确实要存的加密并限制访问。
桑多涅：还有一个口子，九成的人漏掉。
仁菜：……日志？
桑多涅：日志和 Trace 也是隐私泄漏口。你在业务里把它脱敏了，链路追踪里原样躺着。
仁菜：……我们的 Trace 全量打印入参。
桑多涅：回去看。第四关。
仁菜：评测？看写进去多少条。
桑多涅：……写入条数是什么指标。
仁菜：……是产量。
桑多涅：评测要沿着整条链路走：这条信息值不值得写入，相关问题能不能召回，无关问题会不会误召回，注进模型之后答案有没有真的变好。四步都有效，记忆才不是一个不断膨胀的数据库。
仁菜：那这题该怎么起头呢？
桑多涅：两条主线先说清。短期是线程级 State，Checkpointer 按 thread_id 存；长期是跨线程数据，Store 按 namespace 和 key 管。
仁菜：然后是 ToolRuntime 的边界 —— 模型只生成任务参数，可信身份从 Context 注入，工具再去访问 State 和 Store。最后补长上下文治理和生产要求。
桑多涅：再加一句旧式 Conversation 那一套的定位，对方就知道你分得清版本。
仁菜：……学费。我们那个产品，会话是我自己写的一张 session 表，三万七千条会话记录。
桑多涅：有多少条被读回来用过。
仁菜：……我今天下午才第一次统计。百分之四点二。剩下那九成五全是全量原始对话，存了，没人读，一直在涨。
桑多涅：……还有呢。你脸色不对。
仁菜：……我那张表的 thread_id，是前端传上来的字符串。
桑多涅：和登录态绑了吗。
仁菜：……没有。
桑多涅：那今天这四关，你破在第二关。
仁菜：……我知道。我明天第一件事就是把它绑上。
桑多涅：这算数据。带上那百分之四点二一起报，那个数字比表更能说明问题 —— 因为它说明你分不清作用域的时候，系统不会报错，它只会默默变胖。
仁菜：……糖不甩。
桑多涅：……嗯。明天讲 LangChain 和 LlamaIndex 的区别。炸鲜奶。
仁菜：那两个不是竞品吗？
桑多涅：你要是这么答，我明天不带甜点。
仁菜：诶？！那你今天承认是特意带的了。
桑多涅：……下一句。
仁菜：……我是仁菜，我们下集见！
