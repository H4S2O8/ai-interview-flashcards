llm第03集　多头注意力（MHA）有哪些局限？MQA、GQA、Flash Attention 怎么解决？
============================================================

仁菜：欢迎回来，我是仁菜。姜撞奶——趁热，你先喝。
桑多涅：……你今天怎么这么殷勤。
仁菜：因为今天我要报第一笔支出了，心虚。
桑多涅：说吧。
仁菜：导师让我先跑个小规模验证，我申请了机时。钱倒是不多，但我发现一个事——同样的卡，序列一长，速度就崩。
桑多涅：那正好，今天的题就是它。MHA 有哪些局限。
仁菜：这个我背过！计算复杂度是 O(N²)，长序列特别慢。Flash Attention 用了一些数学技巧让它变快。
桑多涅：「数学技巧」——什么技巧。
仁菜：呃……
桑多涅：再问你，O(N²) 是计算复杂度，还是显存复杂度。
仁菜：……这俩不是一回事吗？
桑多涅：不是。而且更关键的：MHA 的真正瓶颈在训练还是推理。
仁菜：呃，都慢吧？
桑多涅：训练慢和推理慢，是一个原因吗。
仁菜：……我不知道。
桑多涅：这就是这道题最大的坑。很多人笼统说一句「N 平方慢」，一追问就答不下去，根源就是把训练和推理混在一起讲。今天分开说。先训练。
仁菜：训练的时候，每一层 Attention 都要算一个 N 乘 N 的注意力分数矩阵。
桑多涅：这个矩阵在显存上要存下来，干什么用。
仁菜：给反向传播用？
桑多涅：算笔账。序列长度四千的时候，这个矩阵是多少个数。
仁菜：四千乘四千……一千六百万个数。
桑多涅：三万二呢。
仁菜：……十亿个数。
桑多涅：FP16 大约两 GB。计算上也是 N 平方，序列翻倍，计算量翻四倍。
仁菜：那这也太吓人了！
桑多涅：但有个好消息——训练时这个矩阵是一次性算完的，不需要在多个时间步之间持续保留。
仁菜：那推理呢？
桑多涅：推理是另一个故事。LLM 是自回归生成，每次生成一个新 token，都要重新对前面所有 token 算注意力。
仁菜：每次都从头算？那成本不是滚雪球——
桑多涅：会累加成 N 的三次方，根本不可接受。所以有了标配的做法。
仁菜：KV Cache！把前面所有 token 的 K 和 V 存下来，新 token 只算自己的 Q，再和缓存的 K、V 做注意力。
桑多涅：对。但这个救星本身，就是个显存大户。
仁菜：有多大？
桑多涅：算给你看。一个七十亿参数的模型，三十二层、三十二个头、每个头一百二十八维，跑三万二的上下文。
仁菜：嗯……
桑多涅：光 KV Cache 十七 GB。加上模型权重十四 GB。
仁菜：三十一 GB……我们那张卡才二十四 GB！
桑多涅：一张 RTX4090 根本放不下。这就是长上下文场景的头号问题，也是面试里追问「KV Cache 怎么省」的根源。
仁菜：所以瓶颈就是显存不够？
桑多涅：显存挤爆只是一面。更隐蔽的是——速度也快不起来。
仁菜：显存和速度有什么关系？
桑多涅：GPU 的计算单元算力很猛，但显存带宽跟不上。Attention 计算里大量时间花在「等数据从显存搬到计算单元」。
仁菜：所以计算单元在……等米下锅？
桑多涅：这个词你留着用。这叫 memory-bound，访存受限。
仁菜：那是不是换张算力更强的卡就好了？
桑多涅：……你猜。
仁菜：……不好？
桑多涅：算力翻一倍，跑 Attention 可能只快百分之二十。因为瓶颈根本不在算力。
仁菜：啊……那我刚才那笔机时申请，是不是买贵了。
桑多涅：下次先问清楚瓶颈在哪再花钱。现在三个痛点连成一条线了——你说。
仁菜：N 平方复杂度，序列稍长计算量就按平方膨胀；KV Cache 让长上下文显存爆掉；访存带宽让算力发挥不出来。
桑多涅：而且三个互相加剧。后面所有优化方案，都是在攻击这三个里的一个或多个。第一个方案，MQA。
仁菜：多查询注意力吧？
桑多涅：思路非常暴力：所有 head 共享同一份 K 和 V，只有 Q 是每个 head 独立的。
仁菜：等等——原本三十二个头，每个头都有自己的 K 和 V。现在 K、V 只留一套？
桑多涅：三十二套 Q 保留，K 和 V 全部共享一套。KV Cache 立刻变成几分之几。
仁菜：三十二分之一！那刚才那个十七 GB——
桑多涅：剩零点五 GB 多一点。
仁菜：这么狠？！那还要 MHA 干嘛，全换 MQA 不就行了——
桑多涅：……停。第三集第二次了。
仁菜：……代价是什么。
桑多涅：表达能力下降。你自己想：原本三十二个头，各有各的 K 和 V，等于三十二套不同的视角。
仁菜：K 是「我有什么标签」，V 是「我的内容」——昨天那个职责牌的比方。
桑多涅：共享之后呢。
仁菜：三十二个视角变成……大家都看同样的标签、同样的内容，只是用不同的 Query 去问。
桑多涅：多视角被压成单视角。实测在大模型上效果下降百分之二到五。
仁菜：五个百分点听着还好啊？
桑多涅：对简单任务差不多。但对推理类任务——数学、代码——损失很明显。所以 MQA 在工业界不如它的折中版本受欢迎。
仁菜：折中版本？
桑多涅：GQA，分组查询注意力。把 H 个头分成 G 组，每组内部共享一份 K、V，组之间各自独立。
仁菜：哦——！那 MHA、MQA、GQA 是不是一条光谱？
桑多涅：说下去。
仁菜：G 等于 H 就退化成 MHA，每个头一套；G 等于一就退化成 MQA，全部共享一套；中间任意取值都行！
桑多涅：这个理解对了，面试就赢一半。显存上，KV Cache 从 H 套压到 G 套。
仁菜：三十二个头分八组的话，显存压到四分之一——比 MQA 的三十二分之一大，但也很省了。
桑多涅：表达力上呢。
仁菜：每组内部共享、组间独立，等于每组都有自己的视角。组数越多视角越丰富。
桑多涅：Meta 的论文里，八组配置下，效果几乎和 MHA 持平——差距不到百分之零点五，但 KV Cache 压到四分之一。
仁菜：显存降四倍，效果几乎不损失……这也太甜了。
桑多涅：所以它成了现代大模型的标配。第二代 Llama 的七百亿模型开始用，六十四个头分八组；第三代 Llama 全系都用；Qwen 的二代三代主力模型也用。
仁菜：那 DeepSeek 呢？我看他们好像不太一样。
桑多涅：DeepSeek 的 V2、V3 走了另一条更激进的路，叫 MLA，多头潜在注意力。
仁菜：是 GQA 的升级版吗？
桑多涅：别这么说。目标相似——都是省 KV Cache，但机制完全不同。
仁菜：那它怎么省的？
桑多涅：不共享，而是把每个 token 的 K、V 通过降维投影压缩到一个低维的潜在向量里存起来，需要时再配合额外投影参与计算。
仁菜：所以存的不是「几套高维 K、V」，是「压缩后的低维表示」。
桑多涅：显存比传统 MHA 和 GQA 更省。但面试里别把它说成 GQA 的变体，那是两条路。
仁菜：记下了。那 Flash Attention 呢？它是第三条路？
桑多涅：完全另一条赛道。MQA 和 GQA 都在改 Attention 的结构——从「要存几套 K、V」下手。Flash Attention 不改数学公式，改的是底层实现。
仁菜：不改公式还能变快？
桑多涅：回到访存瓶颈。GPU 的存储分两层，你知道吗。
仁菜：……不知道。
桑多涅：第一层 HBM，高带宽显存，容量大——A100 是四十或者八十 GB，但带宽相对慢，一点五 TB 每秒。这就是平时说的显存。
仁菜：第二层呢？
桑多涅：SRAM，片上缓存。容量小得可怜，A100 每个 SM 只有一百九十二 KB。
仁菜：才这么点？
桑多涅：但带宽十九 TB 每秒——是 HBM 的十三倍。
仁菜：十三倍……那标准 Attention 是在哪一层算的？
桑多涅：在 HBM 上反复读写 N 乘 N 那种大矩阵。访存时间远超实际计算时间。
仁菜：所以序列从两千涨到四千，理论上慢四倍，实际更糟？
桑多涅：瓶颈全在 HBM 来回搬运。那 Flash Attention 怎么办。
仁菜：既然 SRAM 快……是不是把计算搬到 SRAM 里？可它才一百九十二 KB，装不下啊。
桑多涅：所以要切块。把 Q、K、V 切成小块，比如一百二十八乘一百二十八，每次只在 SRAM 里算一小块，算完直接和最终输出累加。
仁菜：不把中间那个大矩阵写回 HBM！
桑多涅：但这里有个数学难题。softmax 要看整行才能算，不能局部独立计算。
仁菜：……那不就切不了了吗？
桑多涅：所以有了在线 softmax。分块计算的同时，维护一个「当前最大值加累积和」的状态，每来一块做一次增量更新。
仁菜：最终结果和一次性算 softmax 一样吗？
桑多涅：完全一样。这是重点——它不是近似。
仁菜：那效果呢？
桑多涅：显存从 N 平方降到 N 的一次方，不再需要存中间大矩阵；速度快两到四倍，因为 HBM 读写次数大幅下降。
仁菜：等等，你说「完全一样」，但浮点数不是有精度问题吗？
桑多涅：问得好。分块顺序和数值精度不同，最后几位可能有微小差异。但不会像稀疏近似、低秩近似那样引入模型精度损失。
仁菜：这个区别在面试里很重要吧？
桑多涅：说「等价实现」和说「近似加速」，是两个水平。Flash Attention 现在已经迭代到 v3，针对 H100 这类新卡做了优化，基本是 vLLM、SGLang、TGI 的默认实现。
仁菜：那最后一个问题——MQA、GQA 和 Flash Attention，我该选哪个？
桑多涅：……又来了。谁告诉你要选。
仁菜：诶？
桑多涅：这是这道题最关键的认知：MQA 和 GQA 是结构层的优化，Flash Attention 是实现层的优化。
仁菜：所以它们……不冲突？
桑多涅：叠加，不是替代。现在的主流模型基本都是 GQA 加 Flash Attention 一起用。
仁菜：哦——！一个省 KV Cache，一个省访存，各管一层。
桑多涅：这句话说出来，面试官就知道你捋顺了。今天这道题从头到尾就一条主线：瓶颈到底卡在显存还是带宽，每种方案在哪一层动刀，它们是替代还是叠加。
仁菜：记下了。学费——今天那笔机时我查了明细：同样的卡，序列从四千跑到三万二，吞吐掉了七成八，但 GPU 利用率一直没上过百分之四十。
桑多涅：……这算数据。掉七成八、利用率不到四成——那就是典型的访存受限，不是算力不够。带上卡型和序列长度一起报。
仁菜：所以我那笔钱……
桑多涅：没白花。你买到了一个结论：你们的瓶颈在带宽。下次申请之前，先把这个结论用上。
仁菜：明白了！那明天呢？
桑多涅：位置编码。今天我们说 Attention 的计算是对称的，不看词序——明天讲怎么把顺序补回去。豆沙锅饼。
仁菜：又是一座大山？
桑多涅：没有图可看的那种。带脑子来。
仁菜：……我今晚早点睡。我是仁菜，我们下集见。
