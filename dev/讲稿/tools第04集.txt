tools第04集　什么是 MCP（模型上下文协议）？讲讲它的核心内容？
============================================================

仁菜：欢迎回来。我是仁菜。今天的甜点 —— 达克瓦兹，原味的，用你出的钱买的，蓝月亮那家是真不错。
桑多涅：嗯，这家粉没问题。七天了。
仁菜：七天上 MCP。这个我熟，上季第一集你就讲过！
桑多涅：那你背背看。
仁菜：MCP 三层：Host 是跟用户交互的应用，Client 管建连接、管通信，Server 真正暴露工具能力。还有你说的 M 乘 N 适配爆炸，还有那个比喻 —— 给 Agent 的工具世界立了个 USB-C 标准！
桑多涅：背得挺熟。背得出，不代表懂。今天把这些名词拆开，看里面的零件。先答：MCP 到底是个什么东西？
仁菜：MCP 就是个工具调用框架嘛，跟 Function Calling 干的事差不多，都是让模型调外部工具 ——
桑多涅：错。协议，不是框架。这两个词差着一整个层面。
仁菜：……协议和框架，不都是一个东西管调用吗？
桑多涅：不是一个层面。Function Calling 解决的是「模型怎么把调用请求说清楚」—— 模型内侧的事。MCP 解决的是「工具怎么标准化接入」—— 工具外侧的事。一个管嘴，一个管门。
仁菜：哦……那我再猜，MCP 是 Anthropic 给 Claude 定的 API 标准，让 Claude 能接更多工具？
桑多涅：又错。它是开放协议，谁都能实现。Claude Desktop、Cursor、Windsurf，各家的 AI 应用都能接。你把它想成 Claude 专属，面试官立刻知道你没搞懂。
仁菜：连错两个……那它到底解决什么问题？你别报名词，给我讲事。
桑多涅：讲事就讲事。你给 Claude 接一个 GitHub 工具，MCP 还没出现的年代，你得自己写：GitHub 接口怎么调、认证的 token 怎么传、返回的格式怎么转成模型看得懂的。好不容易跑通了，两个月后 Claude 升级，接口变了，你的对接代码跟着改。
仁菜：这还能忍，反正就改一次。
桑多涅：你手里这样的工具有十个呢。十套对接代码，十种认证方式，十种错误处理。然后产品经理走过来说：这套工具也给 Cursor 用一遍。
仁菜：……重写。Cursor 和 Claude Desktop 接法完全不一样。
桑多涅：对。这就是那个 M 乘 N：M 个应用乘 N 个工具，全都要两两写适配。每个工具、每个模型都是一座孤岛，接一个新工具就得重新搭一座桥。
仁菜：所以 MCP 就是把桥标准化了。上季那个 USB 的比方，我后来还真想过：USB 出来之前，鼠标一个口、键盘一个口、打印机又一个口，换台电脑全得愁。USB 一统一，鼠标厂只做一次适配，全球所有电脑都能插。
桑多涅：对，今天把那个比方的下半截补全。在 MCP 的世界里，GitHub 官方按协议实现一个 MCP Server，把列 PR、建 Issue、搜仓库、看 Diff 这些操作封装进去；你那个 AI 应用，只要支持 MCP，就能直接连上，自动发现里面的工具，一行对接代码不用写。
仁菜：一次实现，到处复用。那架构还是上季那三层？
桑多涅：Client-Server。Server 是工具实现方，GitHub 的能力都封装在 GitHub 的 Server 里；Client 在 AI 应用那一侧，负责连接和通信。关键在下一句 —— 一个 Client 可以同时连多个 Server。
仁菜：什么意思？
桑多涅：你把文件系统的 Server、GitHub 的 Server、PostgreSQL 的 Server 全接上，你的 AI 应用一下子就有三套能力：操作本地文件、读写代码仓库、查询数据库。而你要做的，是在配置文件里加几行 JSON，重启，它自动发现。
仁菜：等一下，从写对接代码，到改几行配置 —— 这中间省掉的就是那个 M 乘 N。
桑多涅：省的是整个维度。接下来拆 Server 里的三类能力，这是面试重点，混一个扣一分。第一类，Tools，工具，对应你上集 Function Calling 里那个函数。它的本质是「有副作用的操作」—— 执行完，外部世界的状态变了：建文件、提交代码、发消息。
仁菜：所以它最危险。
桑多涅：所以它通常要用户授权确认才执行，不能让模型想调就调 —— 上集说的手脚上锁，锁就在这一环。第二类，Resources，资源，跟 Tools 的区别就一个字：读。它不改任何东西，只把数据给模型看：读日志、查记录、拿文档。只读，无副作用，暴露起来就宽松，不用像 Tools 那样层层确认。
仁菜：一个动刀的，一个递资料的。那第三类呢？
桑多涅：Prompts，提示词模板，最容易被忽略的一类。预定义的模板，带参数占位符。你团队有一套固定的代码审查 prompt，要传编程语言和代码内容两个参数，谁用谁传值，自动展开成完整提示词 —— 不用每次从头写。公司积累的好 prompt 封装进去，全组复用，标准还统一。
仁菜：等等，这个有意思，协议里连 prompt 都管……那底层是怎么通信的？总不能是玄学吧？
桑多涅：JSON-RPC 二点零。一套很轻的远程调用协议：客户端发一个 JSON，写清楚调哪个方法、参数是什么、这单请求的编号是多少；服务端回一个 JSON，带结果或者错误。用 JSON 不用二进制，图它易读、好调试、什么语言都能实现。
仁菜：又是 JSON！上季说它格式定死好解析，上集说它是模型的「话」，这集它成了协议的骨架 —— 这一家子的。
桑多涅：一脉相承的，面试里把这条线串出来很加分。传输层有两种：stdio，本地 —— Server 作为子进程跑在你机器上，走标准输入输出管道，启动快、延迟低，本机工具用它；Streamable HTTP，远程 —— Server 部署在服务器上，走 HTTP，团队共享一个数据库 Server 就用它。
仁菜：就两种？听起来不多啊。
桑多涅：名字今天记住就行，里面的门道 —— 长连接怎么维持、消息怎么推送 —— 第十三集专门拆，那里有它的一段演进史，够讲一整集。今天只补一句：这套规范二零二四年十一月底由 Anthropic 发布，开放协议，然后生态起得飞快。
仁菜：快到什么程度？
桑多涅：两个原因。一，门槛低到离谱：规范和 SDK 全开源，写一个最简单的 Server 不到三十行代码。二，头部工具第一时间跟进：GitHub、Slack、PostgreSQL、浏览器自动化、地图，官方或社区的 Server 现成的，开发者接一个新工具就是改几行配置。用的人越多，写 Server 的人越多，写 Server 的人越多，用的人越多 —— 正向循环。
仁菜：所以它赢在不是设计多深，是门槛够低加生态滚起来了。那这套东西有没有什么要注意的坑？
桑多涅：有，还是那把锁。Tools 有副作用，所以授权这层永远不能省 —— 模型说它要删库，Client 得先问你。Resources 是只读，才能放宽。这条边界线拎得清，你讲 MCP 才像个跑过项目的。
仁菜：我过一遍：MCP 是开放协议不是框架，管工具怎么标准化接入，Function Calling 管模型怎么说调用请求，一个管嘴一个管门；它终结 M 乘 N 的孤岛，Server 实现一次到处接；三类能力 —— Tools 动刀的要授权、Resources 只读的随便看、Prompts 模板全组复用；底层 JSON-RPC 二点零，传输本地 stdio 远程 Streamable HTTP；门槛低加头部跟进，生态才滚起来。完了。
桑多涅：……大差不差。就一个错：你说三类能力那块，把 Resources 的定位再说一遍？
仁菜：Resources 是有副作用的，需要授权 ——
桑多涅：停。Resources 只读。动刀的是 Tools。
仁菜：对对，说顺嘴了！动刀 Tools，递资料 Resources。
桑多涅：这个错面试里就是安全事故，记住。
仁菜：记住了！下集预告：今天认识的是 MCP 的三大件，可下集说要拆到零件级 —— 一个协议里面居然还有那么多小零件。甜点，圣马可，咖啡可可那种千层。我是仁菜，我们下集见。
桑多涅：圣马可。别拿歌剧院糊弄我，它们长得像，不是一个东西。
