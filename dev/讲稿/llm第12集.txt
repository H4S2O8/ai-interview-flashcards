llm第12集　大模型生成文本时的解码策略有哪些？贪心、Beam Search、采样分别什么时候用？
============================================================

仁菜：欢迎回来，我是仁菜。鸡蛋仔——趁热，凉了就不脆了。
桑多涅：预算。
仁菜：还是百分之六——这周在等标注方案，钱没动。
桑多涅：那正好把推理这一侧补上。今天换个方向——模型是怎么把字一个一个吐出来的。
仁菜：解码策略！这个我列得出来：贪心，每次选概率最高的；Beam Search，保留几个候选；还有采样的，Temperature、Top-K、Top-P。
桑多涅：……你只列了名字，没说本质。
仁菜：诶？
桑多涅：贪心和采样的区别是「确定还是随机」。那 Beam Search 是确定还是随机。
仁菜：应该是确定的？它能更准。
桑多涅：那为什么 LLM 现在很少用 Beam Search 了。
仁菜：因为……更慢吧？
桑多涅：「更慢」是表面原因——翻译模型时代为什么大家都用它。
仁菜：……我没想这么深。
桑多涅：再问一个——贪心解码和「温度等于零的采样」，是同一回事吗。
仁菜：呃……听起来好像是？
桑多涅：这道题表面是「下一个 token 怎么挑」，本质是「不同生成任务想要什么样的结果」。
仁菜：那从最底层讲起吧。
桑多涅：LLM 是自回归生成，每生成一个新 token，模型输出什么。
仁菜：一个概率分布？
桑多涅：多大的。
仁菜：呃……和词汇表一样大？
桑多涅：典型五万到十五万——它告诉你「下一个 token 是『苹』的概率百分之三十、是『香』的百分之二十五、是『桃』的百分之二十」。
仁菜：所以解码策略就是——怎么从这个分布里选一个出来。
桑多涅：不同策略是不同的选择规则——但差异不只是「选哪个」，更深层是什么。
仁菜：更深层？
桑多涅：是对生成任务本质的不同假设——贪心和 Beam Search 假设什么。
仁菜：假设……存在一个唯一最优答案？目标是找到它。
桑多涅：采样类呢。
仁菜：假设答案有多种合理可能，目标是从这个可能空间里采样！
桑多涅：记住这个分歧，今天所有取舍都从这儿来。先说贪心。
仁菜：每一步无脑选概率最高的那个，拼到序列后面，进入下一步。
桑多涅：优点三条。
仁菜：极简，每步只挑最大值；完全确定，相同输入永远同样输出；不引入随机性，API 结果稳定。
桑多涅：确定性对什么友好。
仁菜：调试和复现！还有单元测试、批处理。
桑多涅：但它有一个臭名昭著的毛病。
仁菜：什么毛病？
桑多涅：复读机——让模型用贪心续写「我喜欢我的狗，因为」，它可能写出「它很可爱。它很可爱。它很可爱」。
仁菜：一直重复？为什么会这样？
桑多涅：你自己推——模型某一步生成了「它很可爱」，下一步在概率分布里会看到什么。
仁菜：会看到……这个模式刚刚出现过？
桑多涅：上下文里这个模式的概率很高。
仁菜：所以又选了它！再下一步又选一遍——
桑多涅：走进自我加强的循环，就出不来了。这是贪心最经典的失效模式。
仁菜：那除了复读，还有别的问题吗？
桑多涅：更隐蔽的——生成的文本乏味、保守、缺乏惊喜。
仁菜：为什么？
桑多涅：每步都选最稳的那条路，最终生成的就是「最大众化的表达」。
仁菜：读起来很无聊……那贪心是不是就没用了？
桑多涅：……它有它的最佳战场。你猜是什么任务。
仁菜：呃……需要确定性的？
桑多涅：精确任务——代码生成、SQL 生成、JSON 抽取这种「输出有标准答案」的。
仁菜：哦——！这种任务本来就不需要创意，确定、不乱写才是优点。
桑多涅：所以别把贪心当成「落后方案」，它只是有明确的适用面。第二种，Beam Search。
仁菜：它是贪心的扩展版？
桑多涅：每一步不只保留一条路径，而是保留若干条最高概率的路径同时推进。
仁菜：若干条是多少？
桑多涅：这个数叫束宽，典型是四或者八——举个例子，假设保留三条。
仁菜：第一步保留概率最高的三个 token？
桑多涅：比如「我」「你」「他」。第二步呢。
仁菜：把这三个各自当前缀继续预测……那候选就变成三乘以词汇表那么多了？
桑多涅：从里面挑总概率最高的三条路径——可能是「我喜」「我爱」「你爱」。
仁菜：然后一直重复到遇到结束符，最后从三条里选整体概率乘积最高的那条。
桑多涅：它的优点是什么。
仁菜：全局视野更好？某一步贪心选错了，它还有其他备份路径可以走。
桑多涅：总体概率上比贪心高得多，输出更「合理」。所以它在哪个时代是绝对主流。
仁菜：翻译？
桑多涅：二零一四到二零一八年的机器翻译时代，几乎所有翻译模型都用它。
仁菜：为什么翻译特别适合？
桑多涅：翻译任务有一个独特属性——给定源语言句子，存在一个或几个「最优译文」。
仁菜：所以「找概率最高序列」这个目标，和翻译任务高度匹配！
桑多涅：那到了 LLM 时代呢。
仁菜：你刚才说几乎被弃用了……可我还是觉得「更准」应该是好事啊。
桑多涅：那你说说，写故事、对话、回答开放问题，存在「最优答案」吗。
仁菜：……不存在。开放式的生成任务，存在的只是一个广阔的合理回答空间。
桑多涅：所以 Beam Search 的优化目标，和生成式任务的本质不匹配。这是深层原因，「慢」只是表面。
仁菜：可它至少不会写错吧？
桑多涅：它在长序列上有一个反直觉的失效模式——会输出最无聊、最重复的内容。
仁菜：啊？比贪心还糟？
桑多涅：你想想，「整体概率最高」往往等价于什么。
仁菜：每一步都选最稳的词？
桑多涅：最稳的词通常是什么。
仁菜：……重复前面已经出现过的内容！因为重复模式在概率分布上特别尖锐。
桑多涅：模型对重复模式特别熟悉——所以 Beam Search 生成长文本时会陷入复读，甚至比贪心还严重。
仁菜：这个太反直觉了……它明明是「更聪明」的算法。
桑多涅：更聪明地做错的事。而且还有个更难受的——束宽越大，输出越保守乏味。
仁菜：越大越差？！那不是加了钱还变糟？
桑多涅：八比四还差。这有个名字，叫 Beam Search 困境。
仁菜：……那还有别的问题吗。
桑多涅：有个工程上的硬伤——它和现代 LLM 推理优化不兼容。
仁菜：不兼容？哪一块？
桑多涅：你想想 KV Cache 的前提是什么。
仁菜：第三集讲过……把前面所有 token 的 K 和 V 存下来。前提应该是，序列是单一前缀往下生成？
桑多涅：而 Beam Search 要同时维护好几条不同前缀。
仁菜：那 KV Cache 就得复制好几份！显存直接爆炸。
桑多涅：Flash Attention、PagedAttention 这些也都是为单序列设计的，改起来很麻烦。
仁菜：所以现在的推理框架干脆不支持它？
桑多涅：……这话说过头了。vLLM、SGLang、TGI 大多支持，只是默认通常不开。
仁菜：那我该怎么说才准？
桑多涅：Beam Search 不是彻底没用，是从「默认主角」退回了「特定任务工具」。
仁菜：哪些任务还用它？
桑多涅：某些翻译、受约束生成、候选重排。说「被淘汰了」和说「退回特定场景」，差着一个段位。
仁菜：那第三类，随机性策略。
桑多涅：核心思路从「找最优」变成「按概率分布掷骰子」。最基础的叫普通采样——直接按模型输出的分布随机抽。
仁菜：那多样性肯定有了。
桑多涅：但有个新问题：长尾噪声。所以要在它上面加控制。第一个是 Temperature 采样，通过缩放概率分布的「锐度」控制随机性强度。
仁菜：锐度？
桑多涅：温度越低，分布越尖，越确定；温度越高，分布越平，越发散。第十三集专讲参数怎么调。
仁菜：那 Top-K 呢？
桑多涅：每步只从概率最高的 K 个 token 里采样，把长尾截断。
仁菜：长尾就是那些概率特别低的词？
桑多涅：它们加起来也有一定概率，不截断的话，偶尔会蹦出一个完全不相干的词。
仁菜：Top-P 呢？
桑多涅：每步累加概率到 P 为止，从这个「核」里采样。
仁菜：这两个的区别是——Top-K 是固定取几个，Top-P 是……
桑多涅：自适应截断——分布尖的时候可能只取两三个，分布平的时候可能取几十个。
仁菜：哦！所以它更贴合当下这一步的确定程度。
桑多涅：两大类的核心区别，你总结一下。
仁菜：确定性策略保证质量但牺牲多样性；随机性策略保证多样性但每次输出不同。
桑多涅：那回到我一开始那个问题——贪心解码和温度等于零的采样，是同一回事吗。
仁菜：……我现在觉得是了？温度等于零，分布无限尖，那就只会选最高的那个。
桑多涅：工程上可以这么理解——但你要说「完全是同一回事」，得看具体实现里对边界情况怎么处理。
仁菜：又是一个不能说死的地方。
桑多涅：这个板块到处都是——最后说工程实践怎么选。
仁菜：精确任务用贪心或者低温——代码、数学、信息抽取，要可复现。
桑多涅：对话和创意任务呢。
仁菜：较高温度配 Top-P，平衡多样性和质量。
桑多涅：还有一句得说准——各家 API 的默认值不完全一样，有的默认更稳定，有的默认更开放。
仁菜：所以不能说「LLM 默认都用温度采样」。
桑多涅：你要说的是「通常都会提供温度和 Top-P 这类参数」。差一个字，专业度差一截。
仁菜：那明天组会我怎么讲？
桑多涅：先讲本质——每步从一个词汇表大小的概率分布里选 token。再讲两大类背后的假设分歧。
仁菜：然后是 Beam Search 为什么在 LLM 时代失宠：不是慢，是它假设「存在唯一最优答案」，而生成式任务没有。
桑多涅：最后落到「什么任务用什么」——别说哪个最好。
仁菜：学费——我把我们客服场景的两种配置都跑了：贪心生成的回答，三十条里有七条出现整句重复；温度零点七配 Top-P，一条都没有，但有两条跑题。
桑多涅：……这算数据。七比零和零比二，这是个真取舍。带上样本量和参数值一起报。
仁菜：那我们该选哪个？
桑多涅：客服要的是稳，还是要的是活。
仁菜：……稳。所以低温加 Top-P，中间找个点。
桑多涅：明天就讲这个点怎么找。钵仔糕。
仁菜：这个我没吃过！我是仁菜，我们下集见。
