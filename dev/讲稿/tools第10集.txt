tools第10集　MCP 和 Agent Skill 的区别是什么？
============================================================

仁菜：欢迎回来。我是仁菜。你定的甜点 —— 生巧。……喂，这算哪门子蛋糕，连面粉都没有！
桑多涅：账本上写的是甜点，没写必须是蛋糕。合同精神，收下。
仁菜：……行，你狠。四天，今天的第二集，加练。
桑多涅：加练加的是对比题：MCP 和 Agent Skill，什么区别？这道题上集刚铺垫完，正好考你。
仁菜：这我熟！它俩都是给 Agent 加能力的嘛 —— MCP 用工具列表描述 Agent 能做什么，Skill 也是描述 Agent 能做什么，本质上差不多，就是格式不同 ——
桑多涅：「本质上差不多」？那为什么要搞两套东西，一套不就够了？如果真差不多，为什么它的结构、加载方式、使用场景完全不一样？
仁菜：呃……那我换个说法：Skill 是一种更高级的 prompt 模板？把常用指令存下来，比 MCP 多了点描述信息？
桑多涅：又把 Skill 降格成 prompt 模板了。上集你才背过的：它是一个完整文件夹 —— 指令、脚本、模板、参考文档，Agent 自动发现、按需加载。你背得出来，一放到对比里就糊，这就是这题的坑：站在「对比」的视角，人自动把新概念往旧概念上套。
仁菜：……上集刚学的，一对比果然又糊了。那你给我一个糊不了的锚点。
桑多涅：锚点就一句：MCP 解决「Agent 怎么获得外部能力」，Skill 解决「有了能力之后该怎么用」。没有 MCP，Agent 就是个只会说话的模型 —— 查数据库查不了，读文件读不了，调接口调不了；MCP 把这些封装成标准服务，Agent 从无到有，能操作外部世界了。可能用得了之后呢？面对「帮我做代码审查」，先做什么、后做什么、什么标准、什么格式 —— 这份知识和流程，是 Skill 给的。
仁菜：配电脑开权限，和发操作手册 —— 上集那个比方，原来是这道题的答案。
桑多涅：现在往深里拆，先拆 MCP 这一侧。为什么我说它是 Agent 的手？因为它的粒度，是原子操作。
仁菜：原子操作？
桑多涅：读一个文件 —— read_file，是一件工具；查一次数据库 —— query_database，是一件工具。每次调用只做一件明确完整的事，做完立刻返回结果。而且每个工具的 schema —— 叫什么、收什么参数、回什么格式 —— 全部摊开给模型看。模型正是靠这份完整可见的说明书，才能判断眼前这个问题该调哪一件。
仁菜：一件一件事地干，说明书全摊开……那 Skill 的粒度呢？
桑多涅：粗得多。Skill 的粒度是完整的工作流程 —— 「代码审查」是一个 Skill，「数据分析报告」是一个 Skill，里面横跨好几个步骤、动用好几个工具。至于它的两个看家本领 —— 自动发现和渐进式加载 —— 上集拆透了，不重复。今天看它俩碰头之后怎么干活。
仁菜：来了来了，实战演示。
桑多涅：场景：你对 Agent 说，帮我审查一下这次提交的代码。第一步，Agent 扫描自己可用的 Skill 列表，发现一个叫 code-review 的，跟任务匹配度最高，加载它的 SKILL.md 正文 —— 注意，这时候它读到的只是一份流程：先读代码，再做安全检查，最后出报告。
仁菜：第二步执行流程 —— 伸手要工具了。
桑多涅：对。执行「读代码」这一步，Agent 去调文件系统 MCP Server 的工具；执行「安全检查」，它加载的不再是 MCP，而是 Skill 自带的安全检查脚本 —— 这是 Skill 比纯文字指令强的地方，手册里能夹可执行的附件；第三步「出报告」，加载 Skill 附带的报告模板，按定义好的格式把结果整理成结构化报告交回来。
仁菜：所以整场下来：Skill 站在后面拿着流程图喊口令 —— 做什么、按什么顺序、什么标准；MCP 的每个专业工人趴在前面干活 —— 一人一件小事。一个是编排的，一个是执行的。
桑多涅：口诀记下：Skill 是编排者，MCP 是执行者。缺了 Skill，Agent 一堆工具在手不知道什么时候用；缺了 MCP，流程写得再漂亮也是纸上谈兵。
仁菜：那要是流程里碰上岔路呢？比如 —— 如果改动涉及数据库表结构，就额外做权限合规检查，这种条件分支，谁管？
桑多涅：还是配合着管，而且是判断套判断。Agent 执行到这条指令，先调一个 MCP 工具，扫描这次提交有没有动数据库的表结构，拿回一个是或否；是，就走分支，再调一个查合规规则的工具；查完，决定报告里要不要加一条严重级警告。你看 —— 每一步动手的都是 MCP 工具，但什么时候动手、动手之后走哪条路，全是 Skill 的流程在指挥。
仁菜：项目经理拿着流程图和验收标准，工人各管各的手艺。那这套配合有没有边？
桑多涅：有，而且是人的责任：Skill 的流程是人定义的，定义得再细，也覆盖不了所有情况 —— 流程没写到的地方，Agent 只能靠模型自己判断，质量就回到模型头上和你的流程质量上。所以别迷信「加了 Skill 就稳了」，流程本身是要跟着业务养、跟着事故改的。
仁菜：流程是养出来的，不是画完就完……记下了。我过一遍：定位 —— MCP 管从无到有获得能力，Skill 管有了能力怎么用；粒度 —— MCP 是原子操作，说明书全摊开，Skill 是完整工作流程；配合 —— 扫列表、加载 SKILL.md，动手调 MCP 工具，中间还能跑 Skill 自带脚本、套自带模板，编排者加执行者；条件分支 —— 工具查结果，流程定走向；边界 —— 流程没覆盖的，模型自己兜，流程质量是人的责任。
桑多涅：……上次全对，这次差点意思 —— 你把编排者和执行者开头说反了一次，后半句自己圆回来了。
仁菜：圆回来也算数！那下集就是终极合体了：Function Calling、Skill、MCP，三个到底怎么摆 —— 上集……不对，第六集讲过两个，今天补第三个维度。甜点，泡芙，要冰的。我是仁菜，我们下集见。
桑多涅：冰泡芙。咬之前想清楚，里面是奶油，别溅我。
