langchain第07集　LangChain 和 LlamaIndex 有什么区别？
============================================================

仁菜：欢迎回来，我是仁菜。炸鲜奶，还烫着呢。
桑多涅：这次是你买的。
仁菜：……我五点半就下班了一次，专门去买的，然后又回公司了。
桑多涅：进度。
仁菜：还剩三周零六天啊。
桑多涅：……你改口径了。
仁菜：从今天起我按天数了——周为单位的时候，我总觉得还早。
桑多涅：那今天这题正好——LangChain 和 LlamaIndex，有什么区别。
仁菜：这个我知道啊！LangChain 用来写 Chain，LlamaIndex 用来做 RAG。
桑多涅：……
仁菜：……怎么了。
桑多涅：你这句话，是哪一年的。
仁菜：诶？
桑多涅：现在两边都能做 Agent、都能调 Tools、都能做 RAG、都有 Workflow。
仁菜：……都能？
桑多涅：都能。
仁菜：那既然功能差不多，选热度高的那个不就行了吗？
桑多涅：……
仁菜：……又说错了。
桑多涅：功能有交集，不代表设计重心相同。
仁菜：设计重心……
桑多涅：记住这四个字，这题一半分在这儿。
仁菜：那……我要是选了 LangChain，是不是就不能再用 LlamaIndex 了？技术栈会冲突吧。
桑多涅：谁告诉你框架只能二选一。
仁菜：……没人告诉我。我自己以为的。
桑多涅：所以今天先把一句话给你 —— 这两个不是竞品。
仁菜：不是竞品？
桑多涅：答成竞品，说明你两个都没真用过。
仁菜：……这句好狠。
桑多涅：面试官就是这么想的——他不在乎你会不会用，他在乎你有没有在真项目里为它们分过工。
仁菜：那正确的比法是什么呢。
桑多涅：先说 LangChain 的重心。你自己讲，你用了四天了。
仁菜：它在统一接口吧？Model、Message、Tool、结构化输出，还有中间件。
桑多涅：统一了有什么用。
仁菜：……换模型供应商的时候不用重写？
桑多涅：还有呢。
仁菜：接搜索、接数据库、接浏览器、接 MCP Server、接公司内部 API —— 接口都不一样，它把差异屏蔽掉了。
桑多涅：所以 LangChain 最贵的那块工程成本，是替你省掉的哪一块。
仁菜：……适配。不同接口之间的适配。
桑多涅：对了。那它的主要难点在哪。
仁菜：让模型选对工具、填对参数吧。
桑多涅：再加一句 —— 把权限、重试和审批统一接进调用过程。这就是 Middleware 在干的事。
仁菜：那流程再复杂呢？比如要分支、要并行、要能停下来等人批。
桑多涅：下沉到 LangGraph。
仁菜：那我之前定的模型和工具要推翻重写吗？
桑多涅：不用。LangGraph 本来就是 create_agent 的底层运行时。
仁菜：……所以是一条路走到底，不是换一条路。
桑多涅：简单的模型加工具循环，create_agent 就够。出现复杂分支、并行、暂停恢复和人工审批，再显式写状态图。
仁菜：记下了。那 LlamaIndex 呢。
桑多涅：这个我不讲，你讲。
仁菜：诶？为什么。
桑多涅：你上一季做了三个月企业知识库——它的重心是什么，你比我有资格说。
仁菜：……数据。
桑多涅：展开。
仁菜：真做 RAG 的时候啊，最难的根本不是把文档塞进向量库。
桑多涅：那是什么。
仁菜：数据刚进来那一刻就开始难了——PDF 里的表格、跨页断掉的段落、怎么切、元数据带什么。
桑多涅：继续。
仁菜：还有版本——同一份制度，去年一版、今年一版、还有个草稿版，得判断哪一份还有效。
桑多涅：查询阶段呢。
仁菜：要决定走向量检索、走关键词，还是直接查结构化数据库呢。多路结果回来了还得过滤、重排、处理冲突。
桑多涅：所以难点是长在哪儿的。
仁菜：……是一路传下来的。数据进入、建立索引、发起检索、组织上下文，每一段都在漏。
桑多涅：所以不是换一个更好的向量库就能解决。
仁菜：……我上一季换过两次，问题一次都没变。
桑多涅：……这段你说得比我顺。
仁菜：诶？
桑多涅：陈述事实——LlamaIndex 就是把你刚才那条痛苦的链路，拆成了正式的抽象。
仁菜：拆成什么样呢。
桑多涅：数据接入、解析与切分、索引、检索与重排、Query Engine，最后才到 Agent。
仁菜：……和我踩坑的顺序一模一样！
桑多涅：所以它的价值不在于你背下每个组件名字。
仁菜：嗯……在于它把「怎么得到高质量上下文」当成核心工程问题。
桑多涅：这句直接进答案——那它能不能做 Agent。
仁菜：……不能吧？它是做 RAG 的。
桑多涅：又来。
仁菜：……能。
桑多涅：它有 Agent，也有事件驱动的 Workflow。所以准确说法是它以数据为优势重心，不是它只能做 RAG。
仁菜：那这张对比表，比的到底是什么呢。
桑多涅：比的是优势重心，不是能力边界——LangChain 也有完整的 RAG 组件啊。
桑多涅：LlamaIndex 也能创建 Agent。
仁菜：区别在于哪套抽象更贴近我的主要问题吧。
桑多涅：所以选型的时候，你只要问一句话。
仁菜：哪一句呀。
桑多涅：这个项目最怕哪件事做不好。
仁菜：……就这一句？
桑多涅：就这一句。你答一遍 —— 主要难点是模型和工具集成。
仁菜：……优先评估 LangChain。
桑多涅：主要难点是私有数据处理和检索质量。
仁菜：优先评估 LlamaIndex。
桑多涅：两边都复杂。
仁菜：……那就都上？
桑多涅：说清楚怎么上。
仁菜：嗯……LlamaIndex 负责数据层，把检索能力封装成 Tool，再交给 LangChain Agent 或者 LangGraph 调度。
桑多涅：边界在哪个词上。
仁菜：……Tool。
桑多涅：对。最常见的组合边界就是 Tool。
仁菜：具体怎么接呢。
桑多涅：LlamaIndex 那边加载数据、建索引、实现 Query Engine，然后对外暴露一个查询企业知识库的函数。
仁菜：然后包装成 LangChain Tool 吧。
桑多涅：LangChain Agent 只负责判断什么时候该调它。外层要审批、要重试、要恢复，交给 LangGraph。
仁菜：……那这段代码的重点其实不是代码。
桑多涅：是职责边界——LlamaIndex 管数据与检索，LangChain 管模型和工具选择。
仁菜：上线还要补什么吗？
桑多涅：租户权限、引用来源、超时、可观测性。这四样一个都不能少。
仁菜：引用来源为什么在这儿呢。
桑多涅：答案跨了两个框架，出问题的时候你得说得出这句话是从哪份文档来的。
仁菜：……不然只能猜。
桑多涅：那现在反过来问你——既然组合这么香，是不是所有项目都该两个一起上。
仁菜：……应该不是。
桑多涅：为什么。
仁菜：多一套依赖啊。多一条追踪链路，调试成本会涨。
桑多涅：什么时候才值得。
仁菜：……只有当数据层和 Agent 编排层确实各有独立难题的时候。
桑多涅：如果只是一个简单知识库，或者一个单工具 Agent 呢。
仁菜：那没必要为了架构完整同时引两套吧。
桑多涅：这句话是这题的成熟度分——会加法的人多，会说不加的人少。
仁菜：那还有什么误区吗？
桑多涅：被名字骗——LangChain 这个名字里有 Chain。
仁菜：……所以大家以为它只会把 Prompt 串起来。
桑多涅：现在主线已经转向 Agent 了，固定流程那部分继续由 Runnable 和 LCEL 承担。
仁菜：LlamaIndex 那边呢。
桑多涅：它不是向量数据库——它能连向量库，但它自己不是。
仁菜：……我一直以为它是。
桑多涅：第二个误区——有辨识度的是它对数据处理、索引、检索和上下文组织的抽象，不是它存不存向量。
仁菜：那这题我最后怎么收呢。
桑多涅：先把那个过时标签扔掉，明说两者都能做 Agent、工具调用和 RAG，真正的区别是设计重心。
仁菜：然后各说一句重心吧。
桑多涅：LangChain 偏通用 Agent 组装和广泛工具集成，复杂执行流程下沉 LangGraph。
仁菜：那另一句呢。
桑多涅：LlamaIndex 偏数据接入、解析、索引、检索和上下文增强。
仁菜：……最后落到业务上。
桑多涅：落到那三种情况——这样答完，对方知道你选过型，而不是看过对比图。
仁菜：……学费。今天这条我算了一下午。
桑多涅：说。
仁菜：我上一季那条数据管线啊 —— 解析加切分加多版本判断，一共一千二百行。
桑多涅：其中多少行是检索本身。
仁菜：……两百四十行。
桑多涅：剩下那八成是什么。
仁菜：……是让数据变得能用。
桑多涅：……
仁菜：怎么了。
桑多涅：你自己没听见你刚才说了什么吗。
仁菜：……我说八成的力气花在数据上。
桑多涅：那你现在明白 LlamaIndex 为什么把重心放在那儿了。
仁菜：……它不是在做一个 RAG 库，它是在给那八成建抽象。
桑多涅：这算数据——八比二这个比例，比任何一张对比表都有说服力。
仁菜：那我们这次的产品要引它吗？
桑多涅：你自己判断——你的主要难点是什么。
仁菜：……工具集成。知识库那块我上一季已经做完了。
桑多涅：那就别引。
仁菜：……第一次听你说别引一个东西。
桑多涅：剩三周零六天的人，没有资格多养一套依赖。
仁菜：……记下了。
桑多涅：明天讲 LangChain4j 和 Java 生态。西米露。
仁菜：……Java？
桑多涅：怎么。
仁菜：我们全栈 Python 啊！这个有必要了解吗？
桑多涅：明天你会知道面试官为什么问。下一句。
仁菜：……我是仁菜，我们下集见！
