llm第05集　什么是大模型项目的分词器？原理是什么？
============================================================

仁菜：欢迎回来，我是仁菜。驴打滚——黄豆面撒多了，你别抖。
桑多涅：……我不抖。今天你自己开个头吧。
仁菜：诶？
桑多涅：昨天你说这集听起来简单。那你先讲，讲到我打断为止。
仁菜：那我讲了啊——分词器就是把文本切成一个个词，让模型能处理。
桑多涅：……打断。
仁菜：这么快？！
桑多涅：「切成词」是表面理解。模型为什么需要分词呢，直接用文本不行吗。
仁菜：因为模型只认数字吧？分词器把文字转成数字 ID 序列。
桑多涅：方向对了。那「词」是什么——一个字、一个词，还是别的。
仁菜：呃……
桑多涅：粒度怎么选呢。按字符切行不行——每个字一个 token。
仁菜：那序列会变得特别长吧？
桑多涅：按单词切呢。
仁菜：按单词切……会有 OOV 问题！第一集讲过的未登录词。
桑多涅：终于说到点子上了。那为什么主流大模型都用 BPE 这种子词级别的呢。
仁菜：这个我真答不上来了。
桑多涅：那从最底下说起吧。大语言模型的本质是一个函数——输入什么，输出什么。
仁菜：输入一串整数，输出下一个整数的概率分布？
桑多涅：再查表变回文字。整个过程它看到的全是整数，不认识字符串。
仁菜：所以分词器是……人类文字和模型整数世界之间的桥。
桑多涅：这句话面试第一句就说出来，面试官就知道你抓到本质了。它做两件事——
仁菜：编码，文本变成 token ID 序列；解码，token ID 序列变回文本。
桑多涅：现在看两种朴素方案怎么死的。第一种——字符级分词，每个字母或汉字算一个 token。
仁菜：它的优点是词汇表特别小吧？英文才二十六个字母加标点。
桑多涅：那代价呢。
仁菜：序列变得非常长……一个「hello」就是五个 token。
桑多涅：一篇文章能膨胀到几千上万个。这会让什么爆掉呢。
仁菜：Attention 的计算量！第三集讲的 N 平方——序列一长就按平方膨胀。
桑多涅：还有第二个问题呢——字符本身携带的语义信息太少。
仁菜：所以模型得从一堆离散字符里，重新学出「单词」这个概念？
桑多涅：效率极低。第二种——词级分词，每个完整单词算一个 token。
仁菜：这个对英文应该可以吧，英文有空格分隔。
桑多涅：那词汇表会膨胀到多少呢。
仁菜：几十万？
桑多涅：甚至几百万——光 cat、cats、catting、catty 这种变形就要分别存。
仁菜：啊……可这还不是最严重的吧？
桑多涅：最严重的是 OOV。没见过的新词——专有名词、网络用语、拼写错误——直接没法处理。
仁菜：模型只能输出一个「未知词」标记，这个词的语义就完全丢了。
桑多涅：中文更糟。词级分词意味着要先做中文分词——哪些字组成一个词。
仁菜：分词错了下游全错……这不就是第一集那个流水线的老毛病吗！
桑多涅：所以：字符级太碎，词级太散。中间的甜蜜点是子词分词。
仁菜：subword？
桑多涅：既控制词汇表，又能处理新词，还比字符保留更多语义。BPE 是最常见的一类，但不是唯一。
仁菜：还有别的？
桑多涅：SentencePiece、Unigram、WordPiece 呢，很多模型都在用。面试里别把子词分词和 BPE 划等号。
仁菜：记下了。那 BPE 到底怎么工作的？
桑多涅：三步。第一步初始化——语料拆成最小单元，通常是单个字节或字符，每个都是一个基础 token。
仁菜：这时候词汇表就是所有字符的集合。第二步呢？
桑多涅：反复合并——统计所有相邻 token 对的频率，找最高的那对。
仁菜：比如说？
桑多涅：比如 t 和 h 经常在一起，就把它们合并成一个新 token「th」，加进词汇表。
仁菜：然后语料里所有 t、h 相邻的地方都换成 th？
桑多涅：然后继续找下一个最高频的对。比如 th 和 e 合并成 the。
仁菜：哦——！每轮合并产生一条规则，词汇表就多一个 token。那什么时候停？
桑多涅：第三步：重复到词汇表达到预设大小。GPT-2 用了五万零两百五十七，第三代 Llama 用了十二万八千。
仁菜：那我举个例子试试——「lowest」这个词，BPE 会怎么切？
桑多涅：你说说。
仁菜：可能切成「low」加「est」？因为这两个都是高频子词。
桑多涅：对。那遇到新词——「lowest」后面跟一串数字呢。
仁菜：切成 low、est，然后数字一个一个单独成 token……
桑多涅：不会出现 OOV。每个部分都是有意义的 token。这就是子词分词的核心价值。
仁菜：那中文呢？中文没空格，BPE 怎么办？
桑多涅：和英文不同。主流模型的词汇表里，常用汉字直接就是独立 token。
仁菜：为什么？
桑多涅：因为每个汉字出现频率足够高嘛，不需要再拆。
仁菜：那词呢？比如「人工智能」四个字。
桑多涅：可能被合并成单个 token，也可能是「人工」加「智能」两个。具体取决于训练数据里的频率。
仁菜：所以没有定论，看模型。
桑多涅：这就引出面试里最实用的一个数字了——中文一千个字，大约对应多少 token。
仁菜：一千个？一个字一个 token。
桑多涅：一千到一千五。
仁菜：比字数还多？！为什么？
桑多涅：汉字的 token 化效率略低于英文。英文的合并词能覆盖更多字符，中文很多时候一个字就是一个 token，标点、数字还要另算。
仁菜：那这个比例是固定的吗？我记一下就行了？
桑多涅：……不是。
仁菜：诶？
桑多涅：这只是粗估。Qwen、Llama、OpenAI、Claude 的 tokenizer 全都不一样——中英文、代码、表格混着，比例会明显变。
仁菜：那我怎么算准？
桑多涅：用目标模型的 tokenizer 跑一遍。正式算成本之前——别拿字数拍脑袋。
仁菜：……我今天上午就是拿字数拍的脑袋。
桑多涅：那你回去重算。还有一类东西你没问呢——特殊 token。
仁菜：特殊 token？不是从文本来的？
桑多涅：它们是用来给模型传递结构信息的——BOS 标记序列开始，EOS 标记序列结束。
仁菜：模型生成到 EOS 就停？
桑多涅：不然它会一直写下去。PAD 用于批量处理时对齐不同长度的序列，SEP 用于分隔不同部分。
仁菜：比如对话里区分系统消息和用户消息？
桑多涅：ChatML 格式里还有专门标记对话轮次和角色的特殊 token。模型对这些是有「意识」的。
仁菜：有意识？
桑多涅：它们的 embedding 在训练里被专门优化过——所以模型能靠这些信号理解对话结构。
仁菜：懂了。那这些东西对我们工程上到底有什么影响？
桑多涅：三个坑呢，你今天已经踩了第一个。
仁菜：API 成本估算……按 token 计费不是按字数。
桑多涅：一千汉字大约一千到一千五，一千个英文单词大约一千三。代码更低效——标点、缩进都单独成 token。
仁菜：第二个坑呢？
桑多涅：上下文窗口管理。每个模型有最大 token 限制，Claude 是二十万，Qwen 是十二万八千。
仁菜：那我确保输入不超就行了呀。
桑多涅：字数和 token 数的比例取决于语言和内容类型。中文加代码混合的内容，你以为才五万字应该不超——
仁菜：实际算成 token 已经八万了？！
桑多涅：这是新人最常见的踩坑。第三个：避免截断重要信息。
仁菜：截断……什么意思？
桑多涅：你的文档恰好卡在上下文限制边缘，tokenizer 可能会把一个词从中间硬切开。
仁菜：比如「人工智能」被截成「人工」加半个「智」字？
桑多涅：下游解析或者检索就失败了。工程上怎么处理。
仁菜：留 buffer？留几百 token 的安全余量。
桑多涅：这三个坑——面试官问「你实际踩过什么」的时候，比背 BPE 三步管用。
仁菜：那明天组会我怎么讲这道题呀？
桑多涅：先讲为什么需要它——模型只认整数，分词器是桥。这一句铺垫到位，面试官就知道你抓到本质。
仁菜：然后讲三种粒度的取舍：字符级太碎，序列长、语义少；词级太散，OOV 严重、词汇表爆炸；BPE 取中间的子词级折中。
桑多涅：最后补一句工程影响。别只讲算法啊。
仁菜：学费——我重算了。我们那批客服文档，我原来按字数估的是四十万 token，用真 tokenizer 跑完是五十三万。
桑多涅：……差了三成三。这算数据。带上模型名和文档类型一起报。
仁菜：所以我上午那个预算申请，少报了三成……
桑多涅：趁还没批下来，改。这一集给你省的钱，比你今天买的驴打滚贵多了。
仁菜：！那明天呢？
桑多涅：从零件回到整体——大模型到底是怎么训练出来的。酒酿圆子。
仁菜：终于要讲训练了！我是仁菜，我们下集见。
