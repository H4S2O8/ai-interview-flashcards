rag第13集　什么是多路召回？具体怎么做？
============================================================

仁菜：欢迎回来，我是仁菜。蜜三刀，糖浆能拉丝——今天我带方案来的，混合检索落地版！
桑多涅：第六周。念。
仁菜：三路全上！向量一路，BM25 一路，多 Query 扩展一路，最后再接 Rerank 精排——全都拉满，一个盲区都不留！另外我把 top-K 从二十调到二百，双保险！
桑多涅：停。两处都错。先说小的：top-K 调大是安慰剂。向量相似度排到尾部是很平的，前二十条和前二百条的区别，只是多塞一堆几乎无关的块进去——正确答案照样没进来，还把后面大模型的注意力稀释了。
仁菜：啊？多给点内容还不行吗……
桑多涅：不是内容不够，是路不对。「RTX4090 显卡功耗」——库里有 RTX4090，向量照样召不回：它对精确词天然不敏感，这是检索方式的固有局限，换模型、调 K 都治不了本。调大 K，是用数量蒙质量。
仁菜：那……全上三路总没错了吧！我论证过了还不行？
桑多涅：错在「全上」二字。每加一路都是真金白银：多 Query 扩展一次查询多三到五次大模型调用，BM25 要养一套分词加索引。你们客服场景预算卡着，你上集自己刚说的。
仁菜：可是盲区怎么办？
桑多涅：盲区要补，路要按业务选——行话叫多路召回，同时用几种检索方式捞候选，再合并排序。坐下，把三路各自干什么讲清楚，你再决定谁上岗。
桑多涅：第一路，向量检索：管语义，同义词、换说法都能捞——「退货」和「申请售后」在向量空间里是邻居。这是地基。
仁菜：第二路 BM25，上集讲透了：数词频加稀缺度，精确词一击必中。等等，中文跟英文不一样吧，词跟词之间没有空格——
桑多涅：所以要先分词。常用的工具叫 jieba，把句子切成词，再对每个块切词建索引，查询时同样切词算分。纯文本匹配，速度极快。你们条款库里「优先客服通道」这种词组，切完词它才认得。
仁菜：第三路多 Query 扩展，上集也讲了：改写三到五个角度，各搜各的，合并去重。但它管的是什么盲区来着？
桑多涅：视角。前两路管「词」和「意」，管不了「角度」——用户问「产品多久能送到」，文档写的是「配送时效说明」，两句话不近也不重叠，向量和 BM25 一起哑火。把问题改写成几个角度，总有一个撞上。
仁菜：懂了……那合呢？三路三份排名，怎么捏成一份？
桑多涅：RRF，倒数排名融合。分数没法比——向量相似度是零到一，BM25 是另一套量纲——归一化再加权理论上可行，实际分布差异大，不稳定还复杂。RRF 直接不看分数，只看排名：一个文档在多路里都靠前，综合分就高。
仁菜：像多位评委打分！不管每位评委的打分尺度，只看名次——三个评委都排前几的选手，综合排名不会差！
桑多涅：这个比方能用。里面还有个平滑参数，通常取六十，防止第一名的权重无限大。不用训练，计算量极小，落地成本很低。
仁菜：那我原方案里 RRF 后面接 Rerank，不行吗？
桑多涅：保留。RRF 本质是粗排，负责把三路候选捏成一份名单；最终精度靠 Rerank 深度打分——BGE 家的 reranker，第七集讲过，它俩是一个全家桶。粗排管宽，精排管准。
仁菜：等等，那我重新捋：三路不是全上，是选——
桑多涅：对。三类场景记好。知识库里型号、数字、专有名词扎堆的，比如电商、IT 文档——向量加 BM25 双路是标配，收益立竿见影。
仁菜：嗯，第二类呢？
桑多涅：用户提问风格多变的，比如你们客服——加多 Query 扩展，召回覆盖率能提一到两成。
仁菜：第三类？
桑多涅：质量要求极高、预算也扛得住的，才三路全上再接精排，把质量顶到天花板。
仁菜：所以我们客服场景的正确答案：向量加 BM25 双路打底，多 Query 扩展二期跟上，Rerank 全程在线——上集导师拍的两期方案，跟这个对上了！
桑多涅：对。你不是没学过，你是想一口气把三年的预算花进一周里。你的毛病这季第二次记档：看见好东西，就想全都要。
仁菜：记档就记档……诶学费！混合检索一期今天上线了——灰度第一天，型号类查询命中率从四成拉到七成，客服那边直接说「终于搜得到型号了」。
桑多涅：……这算数据。四成到七成，灰度第一天。带上「一期范围」三个字一起记，别把二期的功也领了。
仁菜：知道啦！那明天？
桑多涅：明天进大山。检索优化策略总览——你前面十来集学的东西，明天全部挂到一棵树上。萨其马。
仁菜：萨其马！大、大山？我把笔记全翻出来预习！我是仁菜，我们下集见。
桑多涅：预习没用。明天从零讲。
