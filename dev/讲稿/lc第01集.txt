langchain第01集　你了解过哪些 AI Agent 开发框架？
============================================================

仁菜：欢迎回来，我是仁菜。芋圆 —— 外卖，凉了，而且我点错了，点成三份。
桑多涅：……三份。
仁菜：我以为选的是大份。你别笑，我这周已经点错两次外卖了。
桑多涅：我没笑。上一季你还能排四十分钟的队买千层，这一季连份数都按不对。
仁菜：上一季我有时间。这一季公司要交付一个对外的 Agent 产品，倒排下来只剩几周，而我手上是四个月攒下来的一堆自研零件。
桑多涅：……那这季换我跟着学。
仁菜：诶？！
桑多涅：我只做研究，不做交付。工期底下人怎么取舍、什么时候放弃更优解 —— 这种样本我拿不到，你有。
仁菜：所以这次是你要跟我学咯？
桑多涅：……是我要看你怎么做。别得意，你还是每集要挨打。今天的题：你了解过哪些 Agent 开发框架。
仁菜：这个我能报一串！LangChain、LangGraph、LlamaIndex、CrewAI、AutoGen —— 反正都是封装大模型和工具调用的，用哪个都差不多嘛。
桑多涅：……你刚才那句是故意的。
仁菜：诶？什么故意的？
桑多涅：上一季最后一集，你把模型路由讲得比我顺。今天你会连三个框架分几层都不知道？
仁菜：……嘿嘿。
桑多涅：说。
仁菜：因为你拆一遍我才记得住嘛。你直接讲，我听完当天就忘；你把我打一顿，我一辈子记得那个坑长什么样。
桑多涅：……所以你是拿自己当靶子。
仁菜：这叫高效学习！所以这一季请继续打，千万别客气。
桑多涅：……这个习惯很坏。不过你那句蠢话确实值得拆 —— 你说用哪个都差不多，错在哪，你自己知道吗。
仁菜：……知道一半。它们解决的问题不一样？
桑多涅：解决的问题、抽象层次、适用场景，三样都不同。LangGraph 为什么会出现？LlamaIndex 为什么长期强调数据和上下文增强？这两个为什么答不出来，报再多名字也只是词汇量，不是选型能力。
仁菜：……那我从哪儿开始想呢。
桑多涅：从一个更基础的地方开始。假设你不用任何框架，自己实现一个能查资料、调接口、记上下文的 Agent，要做多少事。
仁菜：这个我熟啊！接入模型、定义工具协议、实现 Agent 循环、把工具结果重新交给模型再让它接着想。然后是状态、重试、超时、流式输出、人工确认、运行追踪……我上个月两天就做出来一个能跑的。
桑多涅：两天做出演示不难。难的在后面 —— 你那个东西跑到第十几步的时候，进程挂了会怎样。
仁菜：……从头再来。
桑多涅：出错了呢。你怎么知道是第几步、哪个工具、什么参数出的问题。
仁菜：……我加了日志。但日志只有一长串模型输出，还原不出来当时发生了什么。
桑多涅：这就是这道题的钥匙。框架的价值不是替你省那两天，是让你在第十几步之后还能恢复、出错之后还能定位。省代码只是副产品。
仁菜：……那既然三个框架都在抽象这些，不还是差不多吗？
桑多涅：抽象的重点不同。LangChain 偏通用组件和快速集成，LangGraph 偏状态与流程控制，LlamaIndex 偏数据与检索。三个框架在解三个不同层面的问题，所以这题不要比谁更强，要说清在什么业务约束下哪个更合适。
仁菜：那先说 LangChain 吧。它不就是把多个 Prompt 串成 Chain 吗？
桑多涅：那是早期定位。现在它提供模型、消息、Prompt、工具、结构化输出、中间件和 Agent 这些通用抽象，再加上大量模型供应商、向量数据库和外部工具的集成。它最大的价值就两条：集成范围广，开发速度快。
仁菜：这个对我们太重要了……我们要切不同模型，还要接搜索和数据库。
桑多涅：那你自己写这些协议适配，花了多久。
仁菜：……光模型切换那一层，我写了三天。换第三家的时候又改了一天半。
桑多涅：那三天半就是它替你省掉的样板代码。但它有边界 —— 高层抽象更适合常见的 Agent 模式。业务一旦出现复杂循环、精细分支、长时间暂停、断点恢复，就该下沉到 LangGraph。
仁菜：LangGraph 是怎么表达工作流的呀？这个我是真不知道。
桑多涅：三个东西：State、Node、Edge。State 保存共享状态，Node 执行模型或者工具，Edge 决定下一步跑哪个节点。它重点解决循环、条件分支、并行执行、持久化、暂停恢复和人工介入。
仁菜：这不就是一张图吗……
桑多涅：举个例子你就懂了。一个报销 Agent：先读单据，再做合规检查；金额超过限制的时候暂停，等主管审批；审批通过才能调付款工具。这个流程你全塞进一个 Agent 循环里，暂停等审批那一段怎么表达。
仁菜：……我得自己写一个状态机，还得把状态持久化下来。主管三天后点了同意，它还能从那一步接着往下跑。
桑多涅：那就是你在手写 LangGraph 的一小块。用图结构表达，比塞进一个循环清晰得多。
仁菜：……我上个月真写过一个。八十行。
桑多涅：记着这个数。这一季你会反复遇到它。现在关键问题来了 —— LangChain 和 LangGraph 是什么关系。
仁菜：竞品呗。两个框架二选一。
桑多涅：……你又来了。
仁菜：嘿嘿。
桑多涅：这句在面试里说出来立刻扣分。现在 LangChain 的 Agent 高层接口，就运行在 LangGraph 之上。
仁菜：……运行在它之上？那它俩是上下层！那我打个比方 —— LangChain 是常用组件加几条修好的路线，LangGraph 是支撑这些路线的道路系统？
桑多涅：可以。简单 Agent 优先用 LangChain，需要精细控制的时候再下沉到 LangGraph。它俩既有职责差异，也经常组合使用。
仁菜：那第三个，LlamaIndex 呢？我猜它是另一个 LangChain。
桑多涅：很多人这么理解，然后就会忽略它最有辨识度的能力 —— 在私有数据之上构建 AI 应用。数据连接、文档解析、切分、索引、检索、重排、结构化数据访问。
仁菜：……这些词我上一季全讲过一遍。
桑多涅：所以你现在最有体会。让 Agent 查企业知识库，真正困难的是工具调用循环吗。
仁菜：不是。资料进系统那一刻就开始难了 —— PDF 里的表格要正确解析，多种数据源要统一接入，文档还要切分建索引。用户开始提问之后，还要过滤和重排召回结果，还得确保不同用户只能看到自己有权限的数据。
桑多涅：所以问题是怎么长出来的。
仁菜：沿着整条数据链路一路长出来的。不是多注册一个搜索工具就能解决。
桑多涅：这正是 LlamaIndex 更擅长的方向 —— 企业知识库、文档 Agent、研究助手、复杂 RAG。但它也提供 Agent、Memory、多 Agent 模式和 Workflow，别把它说窄了。
仁菜：那我到底选哪个呀？
桑多涅：……你又来了。
仁菜：……这次不是故意的。
桑多涅：那更糟。三个不一定三选一 —— 你想想一个企业知识库 Agent 该怎么搭。
仁菜：呃……LlamaIndex 处理文档、建索引、提供检索结果，然后把这项检索能力包装成一个 Tool，交给 LangChain 的 Agent 决定什么时候调用！
桑多涅：外围还有查询改写、答案校验、人工审核、失败恢复呢。
仁菜：那就让 LangGraph 负责这些步骤怎么衔接。
桑多涅：三者分别解决数据、Agent 组装、流程控制，而不是在同一层重复造轮子。
仁菜：……在同一层重复造轮子。
桑多涅：怎么。
仁菜：没什么。我在想我那堆自研零件，有几个是在同一层重复造的。
桑多涅：……那是这一季的题。还有一句你得记住：是否需要同时引入三者，取决于项目复杂度。只是简单工具调用，不必为了技术栈完整就引入 LlamaIndex；只是普通知识库问答，也不一定需要复杂的图工作流。
仁菜：……为了技术栈完整而引入。这个错误我能想象，而且我觉得它比不用框架还贵。
桑多涅：说得对。那你报的另外两个呢。
仁菜：OpenAI Agents SDK 和 CrewAI。它俩什么定位呀？
桑多涅：前者适合以 OpenAI 模型为主的轻量 Agent，后者擅长用角色和任务表达多 Agent 协作。通用 Python Agent 岗位，优先掌握 LangChain、LangGraph、LlamaIndex，再按公司技术栈补。
仁菜：那这道题我明天怎么讲呢。
桑多涅：先讲框架到底解决了什么 —— 不是省代码，是十几步之后还能恢复、出错还能定位。再讲三个框架各自偏什么：通用组件、流程控制、数据检索。LangChain 和 LangGraph 是上下层不是竞品，这句必须说。最后落到组合，和取决于项目复杂度。
仁菜：就这些？
桑多涅：还有一句。面试官问你了解哪些框架的时候，最强的答法不是报名字。
仁菜：……那是什么？
桑多涅：说你放弃过哪个，为什么。选了什么谁都会说；说得出你为什么否掉一个，才证明你真比较过。
仁菜：那我今天正好有一个！我们评估过 CrewAI。它的角色任务模型特别好看，我当时真的很想用 —— 但我们的流程是固定的审批链，不是多个角色自由协作。用它等于把一个简单问题包装成复杂问题。
桑多涅：……这算数据。带上你们的流程形态一起说。
仁菜：那明天讲什么呀。
桑多涅：从盘点进到具体。LangChain 的核心概念，Chain 到底是什么，为什么这么设计。
仁菜：这个我看过源码 ——
桑多涅：那你明天会更难受。看过源码的人，最容易觉得这个我自己能写。红豆沙。
仁菜：……好。诶，那三份芋圆你带一份走吧，我一个人吃不完。
桑多涅：……我不吃凉的。
仁菜：那我明天热一份给你。
桑多涅：……随你。我是仁菜，我们下集见 —— 这句是你的词。
仁菜：……我是仁菜，我们下集见！
