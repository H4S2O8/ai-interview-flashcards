llm第02集　讲讲 Transformer 架构基本原理？Encoder 和 Decoder 是什么？
============================================================

仁菜：欢迎回来，我是仁菜。炒瓜子——论斤称的那种，我带了一整袋，够嗑一晚上。
桑多涅：你昨天不是要去看架构图吗。
仁菜：看了……看了两个小时。图我能描下来，但你要问我它为什么长这样，我一个字答不上来。
桑多涅：所以我说别带图。今天这一集，没有图能替你想明白。预算还剩多少。
仁菜：一分没动呢！还在评估阶段。
桑多涅：那正好，先把钱花在脑子上。导师问你什么了。
仁菜：问 Transformer 的基本原理。我说是 Google 提的新架构，核心是 Attention，效果比 RNN 好很多；Encoder 是编码器，Decoder 是解码器。
桑多涅：停。「编码器」「解码器」——那是中文翻译。我问的是它们在做什么，不是字面意思。
仁菜：……
桑多涅：再说，Attention 凭什么比 RNN 好。RNN 到底有什么致命缺陷。
仁菜：RNN 太慢了吧？Attention 能并行计算。
桑多涅：方向对了一半——你只说了「快」，没说「准」。
仁菜：还有「准」的问题？
桑多涅：RNN 还有一个更致命的：长距离信息会衰减。第一个词的信息传到第八百个词，基本就没了。
仁菜：啊……那 Attention 怎么解决的？
桑多涅：你先说 RNN 为什么慢——它是怎么处理序列的。
仁菜：从左到右逐个处理每个词——第 N 步必须等第 N 减一步算完才能开始。
桑多涅：……所以呢。
仁菜：所以用不上 GPU 的并行能力！训练大型 RNN 会极慢。
桑多涅：这是第一个。第二个，长距离。序列很长的时候，比如一千个词，理论上 RNN 能记住早期信息。实践中呢。
仁菜：实践中……记不住？
桑多涅：梯度在反向传播时会指数级衰减。网络很难学到「第一个词和第八百个词之间的关系」——LSTM 用门控机制缓解过，但根本问题没解决。
仁菜：然后二零一七年 Transformer 出来了。
桑多涅：Google 那篇《Attention is All You Need》——一个架构一举解决这两个问题。核心叫 Self-Attention，自注意力。
仁菜：自注意力……「自」是什么意思？
桑多涅：先别急着抠字。核心思路是：让序列里每个 token 都能直接关注任意其他位置的 token，算出「我和它的相关程度」，再按相关程度把别人的信息加权聚合过来。
仁菜：那怎么算「相关程度」？
桑多涅：三个向量。Q 是 Query，查询——代表「我想找什么」；K 是 Key，键——「我有什么标签」；V 是 Value，值——「我的实际内容」。
仁菜：三个字母我背下来了，但它们的关系我没画面。
桑多涅：那就想你们公司嘛。你手上一件事要办，这是 Q——你要找的条件。
仁菜：每个同事门口挂着职责牌？
桑多涅：那是 K。而这个人手上真正的东西、能给你的信息，是 V。
仁菜：所以我拿我的需求去比对所有人的职责牌，算出每个人跟这件事有多相关——
桑多涅：然后按相关度，把他们手上的东西加权取过来。这就是注意力。
仁菜：哦——！那 Q、K、V 是从哪儿冒出来的？模型凭空生成的吗？
桑多涅：问到点子上了，这是面试最爱追的一步。它们不是凭空生成的，是把输入的 embedding 通过三个独立的线性投影矩阵算出来的。
仁菜：三个矩阵……分别叫 W Q、W K、W V？
桑多涅：对。而且注意——Q、K、V 都是从同一个输入 X 算出来的。
仁菜：同一个输入？那不就是……输入既当提问的人，又当被查的人？
桑多涅：这就是「自注意力」里那个「自」字的意思。区别于 Cross-Attention 那种「Q 来自一边、K 和 V 来自另一边」的形式。
仁菜：那为什么非要做三次变换？直接让 Q、K、V 都等于 X 不行吗？
桑多涅：不做变换，模型就学不到「该从什么角度提问」「该用什么标签匹配」「该返回什么内容」这三件事的差异。
仁菜：三个独立的矩阵，等于给了模型三倍的自由度……
桑多涅：模型容量大幅提升。还有个工程细节：每个头的维度通常等于总维度除以头数。
仁菜：举个数呗？
桑多涅：你自己算不出来吗。
仁菜：……我怕算错，你说。
桑多涅：总维度五百一十二、八个头，那每个头就是六十四维。
仁菜：为什么要这么配？
桑多涅：这样多头的总参数量和单头版本基本一致——不额外增加计算开销。
仁菜：懂了懂了。那 Q、K、V 有了之后呢？
桑多涅：代进注意力公式。但公式里有一步，面试官最爱问——Q 点乘 K 之后，要除以维度的平方根。
仁菜：为什么？这看着像个魔法数字。
桑多涅：它不是随便加的。假设每个头是一百二十八维，Q 和 K 都是一百二十八维的向量，点积就是一百二十八个数相加。
仁菜：嗯……
桑多涅：如果每一维都是均值零、方差一的随机数，那点积的方差就等于一百二十八，标准差是根号一百二十八，约等于十一点三。
仁菜：所以点积的数值会散得很开……
桑多涅：散布在负三十到正三十这种范围。这些数过 softmax，会发生什么。
仁菜：softmax 是把一堆数变成概率……数值差这么大的话，最大的那个概率会接近一？
桑多涅：其他的接近零——输出几乎变成 one-hot 分布。
仁菜：那有什么问题吗？看起来挺果断的。
桑多涅：梯度消失。softmax 的梯度里有一项是 p 乘以一减 p——p 接近零或者接近一，梯度都接近零。
仁菜：……整个 Attention 层的反向传播信号被压扁了。
桑多涅：模型训不起来。除以维度的平方根之后，点积的方差被压回一，softmax 输出分布合理，梯度能正常传播。
仁菜：那能不能用别的办法替代？我觉得可以在前面加个 Layer Norm——
桑多涅：业界试过。Pre-LN 那种做法是在 Attention 之前先把输入归一化，后面点积天然不会爆炸——但严格说，那是「在之前做归一化」，不是真的替换掉这一步。
仁菜：那让模型自己学一个缩放参数呢？
桑多涅：也试过——实测效果差不多，但多了可学习参数，反而不如一个固定常数简洁。
仁菜：还有别的路吗？
桑多涅：早期有人直接把维度限制得很小，让点积自然不爆炸——但那等于直接限制模型容量，不划算。
仁菜：所以现在主流都用平方根这个方案？
桑多涅：GPT、LLaMA、Qwen 全都没改——一个被八年实践验证过的、简单且数学上合理的选择。这类「为什么不用别的」的问题，答得出来才像自己想过。
仁菜：记下了。那多头呢？为什么要多个头？
桑多涅：单组 Q、K、V 只能学到一种关联关系。但语言里的关联是多维度的——你举个例子。
仁菜：「我」和「吃」是主谓关系？
桑多涅：「苹果」和「吃」是宾动关系；「苹果」和前文的「苹果树」是指代关系。
仁菜：这些不同类型的关联，需要不同的头来捕捉！
桑多涅：所以把 Q、K、V 投影到多个不同的子空间——八个头，或者三十二个头，每组独立算一遍注意力，最后把所有头的输出拼起来。
仁菜：每个头专注一种关联，整体表达能力更强。……不过我突然想到一个问题。
桑多涅：说说看。
仁菜：注意力只看「谁跟谁相关」，它看谁在前谁在后吗？
桑多涅：不看。它的计算是对称的——
仁菜：那「我打你」和「你打我」，对它来说岂不是一样的？！
桑多涅：可能得到一样的结果。所以必须显式地给每个 token 注入位置信息——位置编码。
仁菜：那位置编码怎么做？
桑多涅：sin/cos、RoPE、ALiBi，好几种方案，各有设计哲学和长上下文外推能力，是一个独立的研究方向。第四集整集讲它。
仁菜：那今天我只要知道「Transformer 靠加位置编码来感知词序」就够了？
桑多涅：够了。别贪——这个板块最容易死在一次想吃透太多。
仁菜：……你今天怎么这么客气。
桑多涅：我在省时间。往下。
仁菜：……你这句话我记下了。那一个 Transformer 块里，除了注意力还有什么？
桑多涅：前馈网络，FFN。结构很简单，两层全连接加一个激活函数。
仁菜：那么简单？它干嘛的？
桑多涅：对每个位置独立做非线性变换，补注意力层学不到的东西——注意力本质上是线性加权。
仁菜：所以非线性是 FFN 引入的……
桑多涅：还有一件事更有意思。研究表明 FFN 层储存了大量的事实知识。
仁菜：事实知识？就是「北京是首都」那种？
桑多涅：可以理解成模型的记忆仓库。这句话在面试里说出来，比背结构强。
仁菜：记下了。那 Encoder 和 Decoder 到底是什么？我到现在还没答上导师那一问。
桑多涅：现在你有工具了。三种架构——先说 Encoder-only，代表是 BERT。
仁菜：BERT 是双向的对吧？每个 token 能同时看前后文。
桑多涅：没有遮蔽，全都能看。所以呢，它擅长什么。
仁菜：理解类任务！文本分类、命名实体识别、语义相似度——它的预训练目标是 MLM，随机遮词让模型猜。
桑多涅：第二种，Decoder-only，代表是 GPT、Claude、Qwen。它用因果掩码。
仁菜：因果掩码……每个 token 只能看它前面的，不能提前看到后面的？
桑多涅：单向。这种设计天然适合什么呢。
仁菜：生成！因为生成本来就是一个字一个字往后写，本来就看不到后面。
桑多涅：预训练目标是预测下一个 token，也就是昨天说的 CLM。第三种，Encoder-Decoder，代表是 T5、BART。
仁菜：这个是两个都要？
桑多涅：Encoder 双向理解输入，Decoder 单向生成输出，Decoder 通过 Cross-Attention 去读 Encoder 的输出。
仁菜：哦——Cross-Attention，就是你刚才说的「Q 来自一边、K 和 V 来自另一边」！
桑多涅：它适合「输入和输出是不同文本」的任务——翻译、摘要、问答。但预训练目标相对复杂，超大规模训练不如 Decoder-only 简洁。
仁菜：那导师最后那问就是这个：为什么现在主流大模型全选了 Decoder-only？
桑多涅：这是面试里最容易被追的点。根本原因只有一句——预测下一个 token 这个目标极其统一。
仁菜：所有任务都能表达成「续写」这一件事，不用区分理解任务和生成任务，一套目标搞定一切。
桑多涅：更关键的是第二条。这个目标可以直接在海量无标注文本上做自监督训练。
仁菜：可是 BERT 的 MLM 也不用标注啊？
桑多涅：MLM 确实也无标注——但训练效率不如 CLM 适合 scale up。
仁菜：第三条呢？
桑多涅：随着规模增大，这个简单目标下涌现出的能力越来越强——从会续写文本，逐渐学会数学、推理、代码、跨语言迁移。
仁菜：所以 Decoder-only 就赢了。那另外两种是不是就没人用了？
桑多涅：没有啊。检索、分类、嵌入、翻译、摘要，这些场景它们仍然有价值。
仁菜：那区别到底在哪？
桑多涅：如果你的目标是做一个通用的对话和生成模型，Decoder-only 更容易 scale up，也更符合「一个模型续写所有任务」这个统一接口。就这么简单。
仁菜：明白了。那明天组会我怎么讲这道题？
桑多涅：一条主线，三段。RNN 卡在哪两点——不能并行、长距离衰减。
仁菜：Attention 怎么把这两点都破了——每个位置直接连到任意位置，全部并行算，不存在信息衰减。
桑多涅：三种架构打了一圈，为什么是 Decoder-only 赢到现在。别背「Attention is all you need」那种口号，面试官听腻了。
仁菜：学费！今天扒了训练机的配置：八卡，单卡显存八十 GB，跑一轮完整训练的机时报价，按小时算是四百二。
桑多涅：……这算数据。八卡、八十 GB、四百二每小时，带上卡型一起报。预算表你自己算一下能跑多久。
仁菜：我算了——所以我今天一分都不敢花……
桑多涅：下一集，多头注意力的局限，还有 MQA、GQA、Flash Attention 怎么救它。今天你嗑的瓜子，明天换姜撞奶。
仁菜：局限？多头不是刚被你夸完吗？！
桑多涅：我夸过吗。
仁菜：……你说「表达能力更强」。
桑多涅：那不叫夸，那叫陈述事实。
桑多涅：……每样东西都有代价。这句话你什么时候不用我提醒了，这季就没白上。
仁菜：行吧行吧，我今晚先把瓜子嗑完。我是仁菜，我们下集见。
