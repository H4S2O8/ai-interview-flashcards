llm第09集　请讲一下 LoRA 技术，除了减少参数量，它还有哪些优点？
============================================================

仁菜：欢迎回来，我是仁菜。糖葫芦——这个不好带，我一路举着回来的。
桑多涅：……举着。
仁菜：地铁上被人看了一路——今天预算报一下：还没动，但方案定了 LoRA，导师批了。
桑多涅：那今天这道题你肯定觉得自己会。
仁菜：会啊！LoRA 主要就是减少参数量，让显存占用降下来，普通 GPU 也能微调大模型。
桑多涅：……题目里问的是「除了减少参数量」。
仁菜：诶？
桑多涅：「除了这个还有什么」——你把限定条件又答了一遍。
仁菜：呃……训练快一点？
桑多涅：「快一点」太笼统——它在五个维度上都有早期方案做不到的优点。
仁菜：五个？！
桑多涅：推理速度、部署灵活性、灾难性遗忘、训练稳定性、权重组合。一个一个说得清吗。
仁菜：……我没仔细想过这么多。
桑多涅：典型的「会用但没深入想过」——LoRA 能在二零二三年之后成为事实标准、把 Adapter 那批同期方案完全淘汰，靠的正是这些容易被忽略的优点叠加。
仁菜：那从头讲吧。
桑多涅：先把昨天的账再算一遍——七十亿模型全量微调要多少显存。
仁菜：权重十四 GB、梯度十四 GB、Adam 两个状态五十六 GB——八十 GB 起。
桑多涅：一张消费级卡多少。
仁菜：RTX4090 二十四 GB……根本跑不动。七百亿的更是以百 GB 计。
桑多涅：所以催生了一类方法，叫 PEFT，参数高效微调。核心思路是什么。
仁菜：不更新全部参数，只训练一小部分，同时尽量不损失效果。
桑多涅：LoRA 是其中最成功的——它的做法昨天你打过比方了。
仁菜：不动原始权重，在旁边加两个小矩阵，训练时只更新这两个小的——像在书上贴便利贴。
桑多涅：这个「在旁边打补丁」的设计，是它后面所有优点的根源。但先解决一个词。
仁菜：哪个？
桑多涅：低秩分解——这是初学者最困惑的地方。
仁菜：确实……「秩」到底是什么意思？
桑多涅：矩阵的秩，代表矩阵里真正独立的信息维度。
仁菜：真正独立的……
桑多涅：一个四千零九十六乘四千零九十六的大矩阵，秩最高可以是四千零九十六。
仁菜：意思是里面有四千零九十六个完全独立的信息方向？
桑多涅：但研究发现，微调时权重的更新量往往具有内在低秩性。
仁菜：低秩性……有多低？
桑多涅：秩通常只有八到十六——其余几千个维度几乎没有有效信息。
仁菜：几千个维度……全是噪声？
桑多涅：我给你一个类比——一张四 K 照片有几百万像素，但它的信息量可以用几十个主要颜色分量近似表达。
仁菜：这不就是 JPEG 压缩吗！把高维数据投影到低维空间，保留主要信息，丢掉噪声。
桑多涅：低秩分解的思路与此类似——那「分解」是什么操作。
仁菜：既然有效信息只在很低的维度里……就不用存整个大矩阵？
桑多涅：用两个小矩阵的乘积去近似它——矩阵 A 把输入从高维压到低维，矩阵 B 再把低维还原回高维。
仁菜：两者的乘积和原始更新矩阵同维——但参数量大幅减少。
桑多涅：中间那个低维数，就叫秩，是 LoRA 最重要的超参。通常设八或十六。
仁菜：那设多大好？越大越准吧，我们干脆设大一点——
桑多涅：……你这个毛病，这季第几次了。
仁菜：……第三次。
桑多涅：秩越小，参数越少，但表达能力也越弱；秩越大，参数越多，越接近全量微调效果。
仁菜：所以是个取舍。
桑多涅：大多数任务八到十六就够了——设大了你付出的是显存和时间，换来的可能是零。
仁菜：那参数量到底省了多少？
桑多涅：刚才那个矩阵，原本约一千六百七十七万参数。秩取十六，两个小矩阵加起来约十三万一。
仁菜：一千六百多万降到十三万……减少了多少倍？
桑多涅：约一百二十八倍——放到整个七十亿模型上，可训练参数从七十亿降到约两千万。
仁菜：两千万……不到原来的百分之零点三？！
桑多涅：显存从八十 GB 以上，降到普通 GPU 能接受的范围。但这只是第一步。
仁菜：第一步？
桑多涅：参数少是最浅的那一层——理解了「原始权重冻结加旁路小矩阵」这个数学结构，后面的优点都是自然推论。
仁菜：那第一个优点是什么？
桑多涅：推理零开销——这是它最被低估的一点。
仁菜：零开销？训练时加了两个矩阵，推理时不是要多算一遍吗？
桑多涅：训练完成之后，把两个小矩阵的乘积加到原始权重上，得到一个合并后的新权重。
仁菜：这个合并操作要做几次？
桑多涅：一次。之后推理直接用合并后的权重，和原始模型结构完全一样。
仁菜：……不需要带着那两个额外矩阵了。
桑多涅：这一点和早期的 Adapter 方案形成鲜明对比。你知道 Adapter 怎么做的吗。
仁菜：不知道。
桑多涅：在 Transformer 每层之间插入一个小型网络。推理时每次都要让激活值额外过一遍这个小网络。
仁菜：每层都过一遍……那延迟不就叠加了？
桑多涅：一个三十二层的模型，每层多几毫秒，叠起来就很可观。
仁菜：而 LoRA 合并之后，推理的计算图和原始模型完全相同。
桑多涅：对延迟敏感的在线服务，这个特性非常重要。这就是第一个优点。
仁菜：第二个呢？
桑多涅：模块化插拔——一个基础模型加多套 LoRA 权重，按需加载。
仁菜：多套？
桑多涅：一个七十亿的基础模型十四 GB，每套 LoRA 只有几十 MB。
仁菜：几十 MB……那我可以同时维护客服、代码、翻译好几套？
桑多涅：按请求类型热切换——不需要为每个场景各跑一个完整模型。
仁菜：我打个比方——基础模型像手机的操作系统，每套 LoRA 像一个 APP？
桑多涅：你不需要为「打电话」和「拍照」分别装两部手机，切换功能只要切换 APP。
仁菜：那实际工程里怎么运作的？
桑多涅：基础模型只加载一次，常驻显存——不同场景的 LoRA 像插件一样按需挂载。
仁菜：切换的时候不用重新加载几十 GB 的模型主体，只换那几十 MB 的旁路矩阵！
桑多涅：这个对你们特别有用——你们要做客服，以后要是加个代码助手，不用再买一份显存。
仁菜：第三个优点呢？
桑多涅：灾难性遗忘的风险更低——昨天讲全量微调时提过。
仁菜：模型学会新的、忘了旧的通用能力……那 LoRA 为什么风险低？
桑多涅：你自己推——原始权重在 LoRA 训练里是什么状态。
仁菜：全程冻结！只有旁路的小矩阵在学习——
桑多涅：所以相当于在原来的知识旁边打补丁，通用能力通常更容易保住。
仁菜：便利贴不会把原文擦掉。
桑多涅：第四个：训练更稳定。为什么。
仁菜：可训练参数少……所以梯度空间小？
桑多涅：对学习率这类超参不那么敏感，调参成本低。
仁菜：这个对我们太重要了——我们根本没有反复调参的预算。
桑多涅：第五个是进阶的，面试里说出来很加分。
仁菜：你说。
桑多涅：多个 LoRA 可以加权混合。
仁菜：混合？把两套合成一套？
桑多涅：比如把一个指令遵循的 LoRA 和一个代码 LoRA 合并一下。
仁菜：那就……不用重新训练，就能融合两种能力？
桑多涅：这也是「在旁边打补丁」这个结构带来的——补丁可以叠加，原文不受影响。
仁菜：五个优点全下来……我发现它们都是从同一个结构推出来的。
桑多涅：说下去。
仁菜：因为原始权重冻结、只有旁路小矩阵在学——所以能合并回去，所以推理零开销；所以可以拆下来换，所以能插拔；所以不改原文，所以不遗忘；所以参数少，所以稳定；所以补丁能叠加，所以可混合。
桑多涅：……
仁菜：怎么了？
桑多涅：陈述事实：这一段你比我讲得清楚。
仁菜：诶？！
桑多涅：别得意——这只说明你今天真的想过了。以前你是背五条，现在你是从一个结构推出五条。
仁菜：那明天组会我就这么讲！
桑多涅：记住题眼——题目问的是「除了减少参数量」。别把限定条件再答一遍，那是最丢分的开局。
仁菜：学费！我把三套 LoRA 的体积量了：客服话术那套四十七 MB，代码那套六十二 MB，翻译那套三十九 MB。基础模型是十四 GB。
桑多涅：……这算数据。三套加起来不到基础模型的百分之一。带上秩和目标模块一起报。
仁菜：那明天呢？
桑多涅：SFT 之后还有什么——RLHF、DPO、GRPO、拒绝采样，这几个到底什么关系。艾窝窝。
仁菜：这么多？
桑多涅：全季最长的一集——今晚早点睡，别再举着糖葫芦坐地铁了。
仁菜：……你居然记住了。我是仁菜，我们下集见。
