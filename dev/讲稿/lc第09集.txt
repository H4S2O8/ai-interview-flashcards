langchain第09集　LangChain 和 LangGraph 的核心区别是什么？
============================================================

仁菜：……欢迎回来，我是仁菜。
桑多涅：你迟到了十二天。
仁菜：……对不起。
桑多涅：凉粉我买了十二次。
仁菜：诶？！
桑多涅：……买了三次。剩下九次是我自己吃的。
仁菜：……这句更让我不好意思了。进度：只剩两周。
桑多涅：那这十二天你干什么去了。
仁菜：……我把整个 Agent 重写了。我迁到 LangGraph 上了！从零搭的状态图，二十三个节点。
桑多涅：为什么迁。
仁菜：因为 LangChain 只能把步骤线性串起来啊。要分支和循环，就得 LangGraph。
桑多涅：……这句话早就不准确了。LCEL 有分支和并行能力，create_agent 本身就是一张带条件和循环的图。你把能不能分支当成两者的边界，说明你还停留在旧版教程里。
仁菜：……本身就是？那我换个说法 —— LangChain 负责开发，LangGraph 负责部署吧？所以需要持久化、流式输出和人工审批的时候，就把项目迁到 LangGraph。
桑多涅：也不对。现在 LangChain Agent 就运行在 LangGraph 上，能直接用检查点、流式输出和人工审批中间件。用了 LangChain，不代表没有这些能力。
仁菜：那我明白了！它们其实是一套东西嘛，LangGraph 只是换了种图写法，选哪个都差不多。
桑多涅：……你又走到另一个极端了。底层运行时可以相同，但抽象层级、控制权和开发成本完全不同。
仁菜：……那到底该怎么理解呀。
桑多涅：先别急着理解。你把这三句错话连起来看一眼 —— 一句说它们完全不同，一句说要迁移，一句说完全一样。三句都是在同一个层面上比它们。
仁菜：……哪个层面。
桑多涅：平行的层面。你一直在问哪个功能更多。这就像在比一台咖啡机和它内部的控制系统，哪个功能更多 —— 能列出差异，但你忽略了它们是上下层。
仁菜：……上下层。
桑多涅：先用一句人话记住：LangChain 给你一套装好的 Agent，LangGraph 让你自己设计整条业务路线。官方的定位也是这样 —— LangChain 是高层 Agent 框架，提供模型、工具和常见的 Agent 循环；LangGraph 是更低层的编排框架和运行时，负责有状态的流程怎么执行、怎么暂停、怎么恢复。
仁菜：那 LangGraph 必须依赖 LangChain 吗？
桑多涅：不强制。它可以用 LangChain 的模型和工具组件，也可以直接接别的模型 SDK，甚至普通 Python 函数。更关键的一句在后面 —— create_agent 会构建一个基于 LangGraph 的图运行时，它返回的是一个编译后的图。
仁菜：……编译后的图。
桑多涅：Agent 在模型节点和工具节点之间循环，直到模型给出最终答案，或者命中停止条件。所以正确的层次关系是：LangChain 高层 Agent API，往下是编译后的 LangGraph，再往下是检查点、流式事件、中断和执行运行时。
仁菜：……三层。那用 LangChain 的时候，我在配什么呢？
桑多涅：框架已经替你搭好了常见 Agent 的拓扑，你主要配零件和生命周期钩子。用 LangGraph 的时候，节点怎么拆、状态怎么更新、下一步去哪，全由你决定。
仁菜：……所以区别不在于有没有图，在于我控制哪一层。
桑多涅：这句是这题的题眼。回到你第一句错话，我们把它拆干净 —— 它混淆了三个不同的概念。第一个，传统的 Chain。
仁菜：Chain 不就是一条直线吗？
桑多涅：LCEL 除了 RunnableSequence，也有并行和分支的 Runnable。固定的提示词、模型、解析器流水线确实常写成线性形式，但那是用法选择，不是框架的能力上限。第二个概念，create_agent。
仁菜：它本身就不是直线 —— 模型可能直接结束，也可能请求工具；工具执行完又回到模型继续决策。这就构成了条件路由加循环。
桑多涅：多个工具调用还可能被并行执行。第三个概念 —— 拿一条早期的提示词、模型、解析器管道，去代表现在的 LangChain Agent，公平吗。
仁菜：……不公平。我拿三年前的它，比今天的另一个。那真正拉开差异的是什么呀？
桑多涅：是 LangGraph 把业务拓扑变成了一等公民。给你一个流程：先做权限校验，再让三个研究节点并行检索，之后汇总；金额高的时候转人工，失败的时候走补偿节点，最后等待次日的任务继续。
仁菜：……这个用 Agent 循环表达不出来。因为我需要明确看到每个节点、每个状态字段和每条路由条件，它们不是模型自己决定的。
桑多涅：这时候图编排的价值才真正出现。所以准确的边界是什么，你说。
仁菜：LangChain 能表达分支和循环，但它的高层 API 主要围绕通用的模型与工具循环组织；LangGraph 让开发者直接拥有整个工作流的拓扑控制权。
桑多涅：……可以。那再问你一个更细的 —— middleware 能在模型和工具前后执行代码，什么都能插。那为什么还要 LangGraph。
仁菜：……对啊，为什么呢？
桑多涅：关键看你是在改造同一台机器，还是重新规划整条生产线。middleware 很适合改造标准的 Agent 循环 —— 模型调用前动态生成提示词、裁剪消息、选模型和工具，调用后做安全检查，给工具调用加重试和人工审批。这些逻辑都围绕 Agent、Model、Tool 的生命周期展开，不需要重新设计整张图。
仁菜：那 LangGraph 的节点和边呢？
桑多涅：处理的是更一般的流程结构。分类节点可以进入完全不同的子流程，多个节点并行之后再汇合，数据库写入、人工表单、规则引擎和一个完整 Agent 可以放在同一张图里。这里的每一步不一定是模型或工具调用。
仁菜：……人工表单也能当节点？那有的节点根本不用大模型！
桑多涅：这就是它比 middleware 一般的地方。那 middleware 到底跑在哪儿 —— 官方特别说明过，它不是独立运行时，它运行在 create_agent 返回的那张编译图内部。而且这个完整的 Agent 还能作为节点或者子图，放进更大的 StateGraph，middleware 跟着它一起工作。
仁菜：……所以它一直就在图里。所以是两层组合，不是二选一。
桑多涅：这句你要是在面试里说出来，这题就过了一半。外层管业务拓扑，内层管模型与工具循环。
仁菜：……那不叫迁移，那叫分工。
桑多涅：你自己听见了。下一块，State。Agent 为什么需要状态。
仁菜：因为模型调用、工具结果、人工意见和中间产物，不可能靠函数局部变量一直传下去。
桑多涅：两者都有状态，但姿势不同。LangChain 的 AgentState 默认核心是 messages，业务要加字段可以用 TypedDict 扩展；官方还有一个更推荐的做法 —— 让相关的 middleware 自己声明它需要的状态，这样能力和数据不会散落在各处。
仁菜：那 LangGraph 那边呢？
桑多涅：状态设计本身成了架构的一部分。可以定义整体 State，也可以区分输入、输出和内部 Schema；节点只返回局部更新，合并由 reducer 决定。
仁菜：reducer 为什么必须有啊？
桑多涅：三个研究节点同时往 evidence 里写，你希望发生什么。
仁菜：……追加，三份证据都留着。不定义 reducer 的话……后写的把前面的覆盖掉！
桑多涅：所以合并语义必须在 State 里提前定义。
仁菜：……这个我踩过。我以为是并发 Bug，查了六个小时。
桑多涅：那不是 Bug，那是你没设计。那这么说，LangChain 就没有 State 了吗 —— 它的 Agent State 就跑在 LangGraph 上。区别不在有没有，在于用 LangChain 你接受一套为标准 Agent 循环设计好的状态骨架；用 LangGraph 你要为整个业务工作流设计数据通道和更新规则。
仁菜：……自由度更大。
桑多涅：责任也更大。这两个永远是一起来的。
仁菜：那持久化呢？这块我一直以为很清楚 —— LangChain 管记忆，LangGraph 管持久化？
桑多涅：……这是面试里最容易说错的地方。还有一种说法也错 —— 只有 LangGraph 才能断点恢复。
仁菜：两种说法错在同一个地方吧，都把上下层拆散了。
桑多涅：LangGraph 的持久化分两套机制，你上两集刚学过。
仁菜：Checkpointer 按 thread_id 保存图状态快照，适合线程内的短期记忆、人工介入、时间旅行和故障恢复；Store 保存图状态之外、跨线程可读取的业务数据。那 create_agent 拿得到这两个吗？
桑多涅：它会把 checkpointer 和 store 交给底层图。所以 LangChain Agent 一样有短期记忆、长期记忆和恢复能力。用 Agent Server 的时候，持久化基础设施还可以由服务端处理。
仁菜：……那真正的差异到底在哪呢。
桑多涅：控制粒度。LangChain 给标准 Agent 暴露便利入口，LangGraph 让你在任意节点和子图层面，自己设计状态保存与恢复的边界。
仁菜：……那存下来就等于能恢复了吧。
桑多涅：……你再想想。一个长流程中途失败，你从头重跑，中间有发邮件和扣款。
仁菜：……邮件发两遍，钱扣两遍！
桑多涅：状态是保存了，业务照样出事故。所以 durable execution 不只是把数据存进数据库 —— 要把非确定性操作和副作用放进可记录的任务边界，并且保证可能重试的操作幂等。
仁菜：……幂等这个词今天第二次出现了。
桑多涅：它会出现很多次。直接设计 LangGraph 的时候这些边界更显式；LangChain 标准 Agent 能借用同一个运行时，但复杂的业务副作用仍然要你自己认真建模。框架从来不替你背这个。
仁菜：那人工介入这块呢？模型想发邮件的时候先让人确认，用 HumanInTheLoopMiddleware 吧？
桑多涅：它在工具真正执行前暂停，然后接受批准、修改、拒绝，或者人工直接回复，底层状态仍然由 LangGraph 持久化，恢复的时候用相同的 thread_id。
仁菜：那这不就够了吗？
桑多涅：如果人工节点不只是审批工具呢。理赔流程要展示中间材料，让审核员补充字段；营销流程要等一周之后再继续；多位审核人分别填意见，然后按票数路由。
仁菜：……那不是批准或拒绝，那是填表。等一周？！这三个中间件都做不了。
桑多涅：所以 LangGraph 的 interrupt 可以放在节点内部的任意业务位置，恢复的时候把外部输入送回流程。准确的说法是：LangChain 提供的是围绕工具调用的高层审批体验，LangGraph 提供的是更通用的中断与恢复原语。前者省事，后者表达范围更广。
仁菜：记下了。那流式输出呢？就是界面上逐字显示模型回答吧。
桑多涅：那只是最表面的一层。用户还想看到正在搜索、工具已返回、等待审批这些进度；开发者还需要观察哪个节点更新了哪些状态、哪个任务失败、什么时候写入了检查点。
仁菜：那 LangChain Agent 能输出这些吗？
桑多涅：用 stream 或者 stream_events，输出模型消息、Agent 步骤和工具发出的自定义进度 —— 因为 create_agent 返回的是编译图，它遵循 LangGraph 的流式接口。
仁菜：……又是这句。那 LangGraph 在低层多给什么？
桑多涅：七种事件类型：values、updates、messages、custom、checkpoints、tasks 和 debug，还能处理子图的命名空间。所以两者都能流 —— LangChain 优先给常见的 Agent 体验，LangGraph 让你观察完整的执行引擎。
仁菜：那 LangSmith 呢？那是 LangGraph 的控制台吧。
桑多涅：……这也不准确。它承担的是 tracing、evaluation、Studio 和 Deployment 这些平台能力，能看 LangChain Agent，也能看你直接写的 LangGraph，甚至支持别的框架接入 tracing。因为 create_agent 本身就是图，节点、线程、状态和执行轨迹都在。
仁菜：……那直接写 LangGraph 的好处呢？
桑多涅：业务步骤被拆成更明确的节点，更容易看出复杂路由走了哪条路径，还能用 checkpoint 做状态回放和时间旅行调试。但这种可见性来自你的建模粒度，不代表 LangChain 没法部署或调试。部署也一样，两边都能部到 Agent Server 体系，也都能自己托管。
仁菜：……所以是两个独立的问题。用不用托管平台，是部署选择；用不用高层 Agent API，是开发抽象选择。
桑多涅：别把这两个混成一个。最后一个误区，也是你今天最需要的一个 —— 不要因为 LangGraph 更底层，就默认它更高级、更适合所有项目。控制权越大，你要自己设计和测试的状态、路由、恢复和副作用就越多。一个标准 Agent，用几十个节点重新搭一遍，未必更可靠。
仁菜：……可能只是更难维护。
桑多涅：那现在说你的十二天。你搭了二十三个节点，其中有几个是在表达业务拓扑。
仁菜：……
桑多涅：数。
仁菜：……三个。权限校验一个，金额高转人工一个，失败补偿一个。剩下二十个，是我把模型和工具的循环，一个节点一个节点拆开重写了一遍。
桑多涅：而那个循环，原来在哪儿。
仁菜：……在 create_agent 里。它本来就在图上跑。
桑多涅：所以这十二天，你把一个已经在图上跑的东西，又搬到图上跑了一遍。
仁菜：……是。你不骂我？
桑多涅：骂你没用。你自己数出来的那两个数字，比我说什么都重。
仁菜：……二十三比三。
桑多涅：这算数据。而且是这一季到现在最贵的一条 —— 十二天。
仁菜：……那我明天就全删掉。
桑多涅：……等一下。那三个节点。
仁菜：……那三个怎么了。
桑多涅：确定性规则和模型决策交替出现，失败要补偿，金额高要转人工。你自己听听这三句像什么。
仁菜：……像你刚才举的那个流程。
桑多涅：所以别急着全删。
仁菜：……那我到底该留哪部分啊？
桑多涅：明天专门讲什么场景该用它。今天讲的是它们是什么关系，明天讲你该不该用 —— 这是两个问题，别混。
仁菜：……那我今天最后怎么收呢。
桑多涅：先把关系定准 —— 高层 Agent 框架，低层编排框架与运行时，create_agent 构建在 LangGraph 上，不是彼此隔离的两套引擎，也不是简单的替代关系。
仁菜：再讲边界：LangChain 用模型、工具、结构化输出和 middleware 帮我快速完成一个 Agent；LangGraph 不替我规定 Agent 架构，它把 State、Node、Edge、分支、循环、并行、子图、中断和恢复都交出来。
桑多涅：最后主动纠正误区。
仁菜：不能说 LangChain 只能线性，也不能说持久化、流式、记忆和人工审批只有 LangGraph 才有。真正不同的是控制粒度和使用成本。
桑多涅：……嗯。明天绿豆汤。
仁菜：……我买。
桑多涅：你明天要删代码。我买。
仁菜：……那这十二次凉粉，我欠你九次。
桑多涅：……记着就行。下一句。
仁菜：……我是仁菜，我们下集见！
