llm第13集　大模型的参数：温度值、Top-P、Top-K 分别是什么？各个场景下的最佳设置是什么？
============================================================

仁菜：欢迎回来，我是仁菜。钵仔糕——我买了两种，红豆的和椰奶的，你挑。
桑多涅：……红豆。预算。
仁菜：还是百分之六——但今天我要花一点了，我得把参数扫一遍。
桑多涅：那先说你现在怎么理解这三个参数。
仁菜：温度高输出更有创意，温度低就稳定。Top-P 和 Top-K 我听说过，但平时没怎么调。
桑多涅：「更有创意」是结果，没说原理——温度具体怎么影响概率分布的。
仁菜：呃……
桑多涅：为什么调高就更有创意。
仁菜：这个我真答不上来。
桑多涅：那 Top-P 和 Top-K 呢，都是截断长尾，区别在哪。
仁菜：Top-K 是固定保留前 K 个词，Top-P 是按累积概率截断？
桑多涅：方向对了。那我问你一个实战问题——同时把温度调高、Top-P 调低，会有什么后果。
仁菜：呃……我没试过这种组合。
桑多涅：典型的「会用 API 但没真的理解参数关系」。这三个从来不是各调各的。
仁菜：那是什么关系？
桑多涅：温度负责整体平滑度，Top-P 和 Top-K 负责候选范围。前者乘后者，才决定最后的生成风格。
仁菜：乘……所以它们是叠加的？
桑多涅：先把每个讲清楚再回来说组合。昨天讲过底层机制——模型每生成一个 token 在做什么。
仁菜：计算词汇表里所有词的概率分布，典型五万到十五万个。
桑多涅：举个具体的——「今天天气真」，下一个词的分布长什么样。
仁菜：「好」可能百分之七十、「不错」百分之十五、「热」百分之八、「冷」百分之五……
桑多涅：还有「猫」百分之零点零零一——这些极低概率的词，就是长尾。
仁菜：那贪心就是永远选「好」。
桑多涅：输出完全确定，但过于保守，长了还会陷入复读。所以有了这三个采样调节参数。第一个，温度。
仁菜：这个名字为什么叫温度？
桑多涅：不是随便取的，背后真有物理意义。数学上它做的是——采样前对概率分布做缩放。
仁菜：怎么缩放？
桑多涅：每个词的 logit，也就是未归一化的分数，除以温度值，然后再做 softmax 得到最终概率。
仁菜：除以温度……那温度小于一的话，等于把所有分数放大？
桑多涅：分数之间的差距被放大——分布会怎样。
仁菜：变得更尖！高概率的更高，低概率的接近零。
桑多涅：这就是「冷水」——冷水让分子运动变慢、状态趋于稳定。模型几乎只选最有把握的词。
仁菜：输出非常稳定，但也非常单调。那温度高呢？
桑多涅：除以一个大于一的数，分数之间的差距被压扁。
仁菜：分布变得更均匀——原本概率很低的词也有机会被选中了！
桑多涅：热水，分子运动加快、趋于混沌——输出更有创意、更多样。
仁菜：但也更可能出错或者偏离主题——那有没有特殊的值？
桑多涅：两个临界点——温度等于一是什么。
仁菜：除以一……概率分布完全不变？那就是模型原始的采样。
桑多涅：温度等于零呢。
仁菜：除以零？！那不是——
桑多涅：工程上等价于退化成贪心解码，永远选概率最高的那个。
仁菜：哦——！所以昨天那个问题的答案是这个。输出完全确定，相同输入永远相同输出。
桑多涅：温度解决的是「分布的松紧」——但还有另一个维度可以控制。
仁菜：候选词的数量？
桑多涅：这就是 Top-K 和 Top-P 要解决的。温度的参数名就是 Temperature，直接这么写。先说 Top-K，思路特别直觉。
仁菜：每次采样前，只保留概率最高的 K 个词，其余全部置零，然后在这 K 个里按比例采样？
桑多涅：比如设五十，就是每一步只从概率最高的五十个词里选。K 越小越保守，越大范围越广。
仁菜：那它主要解决什么问题？
桑多涅：避免采到长尾噪声词——词汇表里那十万多个词大部分都是无用的。
仁菜：长尾里偶尔抽到一个……
桑多涅：一句话就毁了——但 Top-K 有个明显的问题。
仁菜：什么问题？
桑多涅：K 是固定的——你举个例子想想为什么这不好。
仁菜：呃……我问模型「中国的首都是」，它对「北京」的概率应该特别高吧？
桑多涅：可能高达百分之九十九——剩下所有词加起来才百分之一。
仁菜：那这时候 Top-K 等于五十，意味着候选池里有四十九个概率极低的离谱词……
桑多涅：硬要从五十个里选，合理吗。
仁菜：不合理。那反过来呢？
桑多涅：你让模型「写一首关于秋天的诗」，前五十个词的概率会怎样。
仁菜：应该都很分散？每个词都有合理的可能性。
桑多涅：这时候五十够吗。
仁菜：可能不够！说不定第五十一个词比第五十个更有诗意，硬截断在五十反而错过了。
桑多涅：所以固定 K 的本质问题是什么。
仁菜：它不知道当前上下文的概率分布有多尖锐、还是多平坦！
桑多涅：要解决这个，就需要更智能的截断方式。Top-P。
仁菜：昨天说它是自适应的——每步累加概率到 P 为止，从这个「核」里采样。
桑多涅：它的正式名字叫 Nucleus Sampling，核采样——按概率从高到低排列，累加到超过阈值就停，只保留这个核里的词。
桑多涅：那用刚才两个例子验证一下——首都那题，Top-P 设零点九。
仁菜：「北京」自己就百分之九十九，一个词就超过零点九了——所以候选池里只有它一个！
桑多涅：写诗那题呢。
仁菜：分布很平，得累加很多个词才到零点九……可能取几十个上百个。
桑多涅：所以它做到了 Top-K 做不到的什么事。
仁菜：它跟着当下这一步的确定程度自动伸缩！分布尖就少取，分布平就多取。
桑多涅：这就是为什么它比 Top-K 更受欢迎。现在回到我一开始那个实战问题。
仁菜：温度调高、Top-P 调低，会怎样？
桑多涅：你自己推——温度调高是在干什么。
仁菜：把分布压平，让更多词有机会……
桑多涅：Top-P 调低呢。
仁菜：把候选池缩小……
桑多涅：所以。
仁菜：……一个在放，一个在收？那不是互相打架吗！
桑多涅：它们是叠加约束的关系——同时调，反而互相干扰，你根本分不清效果是哪个参数带来的。
仁菜：那工业界怎么做？
桑多涅：只调温度——Top-P 保持零点九左右，Top-K 不设置。
仁菜：这是谁定的规矩？
桑多涅：OpenAI、Anthropic 的官方文档都建议，通常只调 temperature 或者 top_p 其中一个。开源模型要以对应推理框架和模型卡的建议为准。
仁菜：总之别一上来三个一起拧。
仁菜：就调一个？
桑多涅：调一个你才知道调的是什么——这条实战经验，比背三个定义值钱。
仁菜：那温度具体怎么设？
桑多涅：按任务分——代码生成、精确问答，你觉得多少。
仁菜：要可复现……零到零点二？
桑多涅：而且这一档 Top-P 保持一点零，不做限制——温度已经把分布压死了，再截一刀没意义。
桑多涅：创意写作呢。
仁菜：零点八到一点二？
桑多涅：日常对话。
仁菜：零点五到零点七就够了。……这些数我记一下。
桑多涅：记是要记。但记住它们是起点，不是答案——你还是得在自己的场景上跑一遍。
仁菜：为什么？
桑多涅：不同模型的分布锐度本来就不一样。同样零点七，在两个模型上可能是两种风格。
仁菜：那各家 API 的默认值呢？照抄行不行。
桑多涅：别把某个产品某个版本的默认值当成行业固定标准。模型一更新，默认策略也会变。
仁菜：又是一个不能直接抄的数……
桑多涅：这一季你已经碰到第三次了——那明天组会怎么讲。
仁菜：先讲底层——每步从概率分布里采样。然后温度管「分布的松紧」，Top-K 和 Top-P 管「候选范围」。
桑多涅：Top-P 比 Top-K 强在哪。
仁菜：自适应——固定 K 不知道当前分布有多尖。
桑多涅：最后那句实战经验别漏。
仁菜：只调温度，Top-P 保持零点九，Top-K 不设置——因为同时调是叠加约束，会互相干扰。
桑多涅：这一句说出来，面试官就知道你真调过。
仁菜：学费！我把客服场景的温度扫了一遍：零点二的时候，三十条里有五条整句重复；零点七，重复零条但跑题两条；一点零，跑题六条。
桑多涅：……这算数据。三个点位、三十条样本、两类错误。那你选哪个。
仁菜：零点七——但我想再在零点四和零点六之间补两个点。
桑多涅：……那你自己会调参了。明天讲一个能直接帮你省钱的东西——KV Cache 和 Prompt Caching。
仁菜：这个第三集提过！
桑多涅：那集讲的是它怎么撑爆显存——明天讲它怎么替你省钱。双皮奶。
仁菜：省钱我最爱听！我是仁菜，我们下集见。
