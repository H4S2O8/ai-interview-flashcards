llm第04集　大模型的位置编码是干什么用的？sin/cos、RoPE、ALiBi 有什么区别？
============================================================

仁菜：欢迎回来，我是仁菜。豆沙锅饼——切了块，你先。
桑多涅：昨天让你早点睡，睡了吗。
仁菜：……没有。我把「我打你」和「你打我」这事想了半宿。
桑多涅：想出什么了。
仁菜：想出一个问题：如果 Attention 真的分不清词序，那它怎么可能听懂人话？
桑多涅：它听不懂啊。Attention 的计算是对称的，词序怎么变，注意力分数都一样——今天的题，位置编码。
仁菜：这个我查过了！就是让模型知道每个词在第几个位置，用 sin 和 cos 算一下，加到 token embedding 上。
桑多涅：「加到 embedding 上」——怎么加。是直接做加法，还是别的什么操作。
仁菜：呃……应该是加法吧？
桑多涅：那为什么要用 sin 和 cos 呢，不直接用一、二、三、四这种序号。
仁菜：……这我真没想过。
桑多涅：再问你——RoPE 你也是「加到 embedding 上」吗。
仁菜：RoPE 是相对位置编码，跟 sin/cos 不一样，是给 Q 和 K 做旋转！
桑多涅：「做旋转」——怎么转。为什么转一下就能表达位置。
仁菜：……
桑多涅：为什么相对位置比绝对位置强。ALiBi 又是什么思路。为什么 Llama 选 RoPE 不选 ALiBi。
仁菜：停停停……ALiBi 我有点忘了。反正都是位置编码嘛，效果应该差不多吧？
桑多涅：「效果差不多」。那为什么主流模型全换成 RoPE 了。
仁菜：……
桑多涅：这道题真正想问的只有一句：为什么 LLM 不用 sin/cos，都跑去用 RoPE 了。三种方案的设计思路、各自的外推上限、对长上下文的影响——把这条主线讲透，高低自然就出来。
仁菜：那从头来吧。Attention 到底为什么位置盲？
桑多涅：你自己推——输入是「我打你」，三个字都转成向量。Attention 算的时候，发生了什么。
仁菜：「我」去看「打」和「你」，「打」去看「我」和「你」，「你」去看「我」和「打」……
桑多涅：那模型知道了什么呢。
仁菜：知道这三个字之间互相算了注意力——但完全不知道谁在前谁在后！
桑多涅：换成「你打我」呢？
仁菜：三个 embedding 一模一样，只是位置变了……算出来的结果几乎完全相同。
桑多涅：但这两句话语义是反的——分不清位置，就分不清主语和宾语。
仁菜：那我用序号不行吗？第一个词标一，第二个标二——
桑多涅：加到哪儿呢。
仁菜：加到 embedding 上啊。
桑多涅：embedding 通常是负一到一之间的小数——第一千位的那个「一千」加上去，会发生什么。
仁菜：……把原本的数值整个拉爆了。
桑多涅：还有第二个问题呢。训练时见过一到两千零四十八，推理时来了四千零九十六。
仁菜：这个数字模型从来没见过，效果一定崩。
桑多涅：所以位置编码必须同时满足三个要求——你说。
仁菜：第一，数值范围合理，不能把 token embedding 盖掉。
桑多涅：嗯。第二。
仁菜：能区分不同位置，每个位置都得有独特的指纹。
桑多涅：第三呢。
仁菜：能泛化到长序列，最好能外推到训练时没见过的长度。
桑多涅：带着这三条看三种方案。第一种——二零一七年原始 Transformer 论文用的，sin/cos 绝对位置编码。
仁菜：它怎么生成指纹呢？
桑多涅：用一组不同频率的 sin/cos 函数——假设 embedding 是五百一十二维，把这些维度分成一对一对，每对用一组 sin/cos。
仁菜：不同的对，频率不一样？
桑多涅：第一对频率最快，相邻位置区别明显，适合区分近距离；最后一对频率最慢，相邻位置几乎一样——得跨很远才能区分开。
仁菜：那我打个比方——像好几个不同频率的振子叠在一起？高频的记精细位置，低频的记粗略位置。
桑多涅：……可以。每个位置在这个高维空间里都有一个独特的组合，就是它的身份证。
仁菜：那为什么是「加」到 embedding 上，不是「拼接」？
桑多涅：加法不增加维度，结构上省事嘛。而且神经网络强大到可以从相加的结果里，把这两部分信息自动解开。
仁菜：这个我没想到……那它优点是什么？
桑多涅：零参数——完全是数学公式算出来的，不占模型参数。而且理论上可以算到任意位置。
仁菜：那听起来挺完美的啊？
桑多涅：「理论上」。它有个致命问题——长上下文外推能力差。
仁菜：可你刚说理论上能算任意长度？
桑多涅：能算，不代表算得对。模型只在两千长度上训练过，推理时给它四千——表现会断崖下跌。
仁菜：为什么？位置指纹不是照样能算出来吗？
桑多涅：指纹能算，但模型在训练时只学过两千以内的相对位置关系——超出去的相对距离它从来没见过，注意力权重的分布会乱掉。
仁菜：哦——！问题不在生成指纹，在于模型没学过那么远的关系。
桑多涅：所以 sin/cos 在小模型时代还行。到了要支持几十 K 甚至上百 K 上下文的时代，明显不够用。
仁菜：那 RoPE 怎么解决的？
桑多涅：先别急。在讲 RoPE 之前——问你一个特别生活化的问题。
仁菜：你问。
桑多涅：你跟别人介绍你坐哪儿，是说「我坐在前排第三个座位」，还是说「我坐在谁谁旁边」。
仁菜：……当然是第二种啊，谁数座位号。
桑多涅：为什么呢。
仁菜：因为相对位置更有信息量！……等等，模型是不是也一样？
桑多涅：说下去。
仁菜：中文里主语动词宾语这种句法关系——关键不是「主语在第三位、动词在第五位」，是「主语和动词之间隔了两个词」。
桑多涅：举个例子验证一下呗。
仁菜：「我吃饭」。不管前面加「今天」「中午」「饿了所以」，主谓宾的相对距离都没变！
桑多涅：那绝对位置编码的问题就清楚了——它给每个位置发一张独立的身份证，然后呢。
仁菜：然后要让模型自己从「位置三的身份证」和「位置五的身份证」，推断出「相对距离是二」。
桑多涅：靠什么推呢。
仁菜：靠……在训练里慢慢碰运气学到？
桑多涅：没有显式的归纳偏置。而相对位置编码的思路是——把相对距离这个信息，显式地编进注意力计算里。
仁菜：让模型不用自己算！
桑多涅：具体做法是让两个 token 的位置编码只取决于它们的差值，跟各自的绝对值无关。这是 RoPE 和 ALiBi 共同的出发点，只是实现路线不同。
仁菜：那 RoPE 是怎么做的？
桑多涅：二零二一年，中国学者苏剑林提出的——核心就一句话：不把位置信息加到 embedding 上，而是旋转 Q 和 K 向量。
仁菜：旋转……怎么个转法？
桑多涅：每个 token 的 Q、K 向量，根据它的位置被旋转一个对应角度——位置零不转，位置一转一个角度，位置二转两个，依此类推。
仁菜：那我想象成……钟表的指针？位置越靠后，指针转得越多。
桑多涅：这个比方留着。那关键问题来了——为什么转一下就能表达位置。
仁菜：这正是我卡住的地方。
桑多涅：一个数学性质——两个旋转后的向量做点积，结果只依赖于它们的旋转角度差。
仁菜：角度差……而角度是位置决定的，所以角度差就是位置差？
桑多涅：位置 m 的 Q 和位置 n 的 K 做点积，旋转之后的结果只跟 m 减 n 有关，跟 m 和 n 各自的绝对值无关。
仁菜：哦——！相对位置就这么天然地编进 Attention 里了，模型根本不用学。
桑多涅：这是 RoPE 区别于 sin/cos 的核心。还有三个优点呢，一个一个说。
仁菜：零参数？
桑多涅：整个操作就是数学上的旋转，不引入任何可学习参数。第二个优点最容易被忽视——旋转不改变向量的模长，只改变方向。
仁菜：所以不会破坏原本 embedding 的数值范围——训练更稳。
桑多涅：第三个优点是兼容性——RoPE 是在 Q、K 上做的旋转，跟昨天说的那些优化都能无缝叠加。
仁菜：KV Cache、Flash Attention、GQA……都不冲突？
桑多涅：不冲突。这一条在工程上，比前两条更值钱。
仁菜：那外推能力呢？sin/cos 就是栽在这儿的。
桑多涅：RoPE 的旋转是连续的角度变化，本身没有「训练截止」这个概念。训练只见过两千，推理来了四千——
仁菜：多出来的位置只是更大的旋转角度而已，模型不会彻底懵。
桑多涅：效果衰减比 sin/cos 平缓很多。再配上后来的 NTK Scaling、YaRN、Position Interpolation 这些扩展技巧——
仁菜：能推到多长啊？
桑多涅：核心都是调整 RoPE 的频率参数，可以把训练时的两千推到三万二、十万甚至更长。
仁菜：那不就是无损的银弹吗！我们直接把上下文拉满——
桑多涅：……停。别说成「几乎无损」。
仁菜：不是吗？
桑多涅：外推效果取决于模型、任务、长度倍率，还有是否做过继续训练。推得越远，越需要专门评测长文检索、多跳推理这些位置敏感的任务。
仁菜：所以不测就敢拉满，是在赌。
桑多涅：这句话面试里说出来，比背三个扩展技巧的名字管用。谁在用 RoPE。
仁菜：主流的都用？
桑多涅：二零二三年之后基本全部——Llama 全系、Qwen 全系、DeepSeek 的 V1 到 V3 和 R1、Mistral 和 Mixtral、GLM 系列。事实标准。
仁菜：那第三种，ALiBi 呢？
桑多涅：二零二二年提出的——思路比 RoPE 还暴力：根本不动 Q、K、V。
仁菜：那它动什么呢？
桑多涅：直接在注意力分数里加一个距离惩罚项——离得越远，扣分越多。
仁菜：就这么简单？
桑多涅：而且斜率随 head 不同——每个头惩罚的力度不一样。
仁菜：那它的优点是——不引入任何可学习参数？
桑多涅：而且长上下文外推天然就好，因为距离惩罚本身就是个连续函数。
仁菜：听着也不错啊。那为什么没成主流？
桑多涅：表达力弱一些。它对位置的精细建模不如 RoPE——毕竟只是一个线性的扣分，信息量有限。
仁菜：有人用过吗，真的？
桑多涅：MosaicML 的 MPT、BLOOM 用过。有支持者，但没成主流。
仁菜：所以最后还是 RoPE 赢了。为什么？
桑多涅：你自己总结——三个维度。
仁菜：相对位置编码——它把相对距离直接编进点积；长上下文外推——比 sin/cos 平缓得多；还有兼容现代推理优化——跟 KV Cache、Flash Attention 全都能叠。
桑多涅：三个维度都最均衡。这就是它成为事实标准的原因。
仁菜：记下了！那明天组会——
桑多涅：这道题的主线只有一句：为什么 LLM 不用 sin/cos 都跑去用 RoPE。别背公式，讲清楚这三个维度。
仁菜：学费！今天我把我们要用的基座模型配置扒出来了：RoPE，训练上下文三万二，官方文档说支持外推到十三万一，但没给外推后的评测数据。
桑多涅：……这算数据。而且你注意到了「没给评测数据」——这比数字本身值钱。
仁菜：所以我们要真用到十三万，得自己测？
桑多涅：位置敏感的任务自己跑一遍。别信没有 baseline 的支持声明。带上模型名和上下文长度一起报。
仁菜：明白！那明天呢？
桑多涅：分词器。今天你说了半天 token，明天讲这个 token 到底是怎么切出来的。驴打滚。
仁菜：诶，这个听起来简单？
桑多涅：……源文最短的一集。但中文分词的坑，够你笑一晚上。
仁菜：那我期待一下。我是仁菜，我们下集见。
