第 16 集　多个 Agent 之间怎么通信？共享状态怎么设计？Handoff 模式有什么风险？
============================================================

仁菜：第十六集，最后一集。桑多涅，我回来了。
桑多涅：……结果。
仁菜：过了。但是有一道题我没答上来。
桑多涅：哪道。
仁菜：面试官问：多个 Agent 之间到底怎么传信息。我说了 Orchestrator 分配任务，他说那是调度，我问的是通信。然后我就卡住了。
桑多涅：那正好。今天这一讲就是这道题。
仁菜：你早知道我会栽在这儿？
桑多涅：这是全季最容易被跳过的一讲。前面讲的都是「谁来做决策」，这一讲讲的是「信息怎么流动」—— 两个不同的层面，很多人混着讲。
仁菜：那答案是什么？
桑多涅：两种方式。消息传递 —— Agent 完成工作后把结果发出去，下一个取用。共享状态 —— 所有 Agent 共同读写同一个状态对象，里面记录任务进展和中间结果。
仁菜：这两个的本质区别是什么？
桑多涅：消息传递的核心是解耦 —— 发送方不需要知道接收方是谁，适合 Agent 需要独立运行的场景。共享状态的核心是直接 —— 所有人读写同一个对象，LangGraph 就是这个思路，适合依赖关系明确的流水线型任务。
仁菜：怎么选？
桑多涅：取决于 Agent 之间的依赖有多强。依赖弱、要独立部署，用消息；依赖强、流程固定，用共享状态。
仁菜：那共享状态听着简单，实际做起来有坑吗？
桑多涅：这是多 Agent 系统里最容易出 bug 的地方之一，三个关键点。第一，结构要分层。
仁菜：分哪两层？
桑多涅：全局状态存所有 Agent 都要读的东西 —— 原始请求、任务进展、最终输出。局部状态存各个 Agent 自己的中间结果 —— 候选文档列表、草稿代码这些。
仁菜：为什么要分？
桑多涅：避免信息污染。检索 Agent 捞回来的二十个候选文档，写作 Agent 根本不需要看到 —— 全塞进全局状态，每个 Agent 的 context 都被灌满了不相干的东西。
仁菜：第二个关键点？
桑多涅：只追加，不覆盖。每个 Agent 把结果追加进状态，而不是修改已有字段。
仁菜：为什么？
桑多涅：因为并发。两个 Agent 同时改同一个字段，后写的把先写的覆盖掉，而且悄无声息。LangGraph 的 State 更新就是追加思路 —— 节点返回增量更新，框架帮你合并。
仁菜：第三个？
桑多涅：错误状态也要写入。失败信息不能悄悄吞掉。
仁菜：为什么这条这么重要？
桑多涅：因为后续的 Agent 或者 Orchestrator 只有读到失败信息，才能决定是跳过、重试还是终止。你把错误吞了，下游拿到一个空结果，会当成「这一步没什么产出」继续往下跑 —— 最后输出一个看起来完整、实际上缺了一大块的东西。
仁菜：这个比直接报错可怕多了。
桑多涅：静默失败永远比显式失败可怕。接着：Orchestrator 决定「叫谁」，有哪两种路由方式？
仁菜：静态路由和动态路由。第十一集讲过静态路由 —— 提前写好规则，稳定可预测。
桑多涅：缺点呢？
仁菜：覆盖不了没预料到的边缘情况。
桑多涅：动态路由是 LLM 实时判断，灵活，但每次多一次 LLM 调用，而且行为不可预测。那最能体现工程经验的答法是什么？
仁菜：……两个都用？
桑多涅：混合策略：主流程用静态路由保底，边缘情况才交给 LLM 动态决策。既有稳定性，又有兜底的灵活性。
仁菜：这个思路跟第七集的 Replan 触发条件是一样的 —— 平时不动，特殊情况才启动。
桑多涅：工程上的成熟做法往往长得很像。那从全局看，多 Agent 协作分哪三类模式？
仁菜：流水线、层级……第三个是不是那个辩论的？
桑多涅：协商模式。流水线模式按固定顺序依次执行，像装配线；层级模式有 Orchestrator 分配任务、收集结果；协商模式里 Agent 之间没有严格的上下级，通过互相沟通、辩论达成一致。
仁菜：这三个是三选一吗？
桑多涅：不互斥，复杂系统里经常混合使用。整体是层级的，某个环节内部是流水线，关键决策点上用协商 —— 这很常见。
仁菜：那还有没有别的通信方式？
桑多涅：有一个叫 Handoff 模式。它不需要中央 Orchestrator 来决定下一步找谁，而是让当前执行的 Agent 自己决定把任务交给谁。
仁菜：像接力赛？
桑多涅：跑完自己那一棒，直接把棒递给下一个人，不需要裁判喊。OpenAI 的 Swarm 框架用它做过演示 —— 但要注意，Swarm 是教育和实验性质的，官方明确说过它不是生产级工具。
仁菜：这个前提不说清楚，面试的时候会很危险。
桑多涅：你要是说「我们生产上用 Swarm」，对方会当场怀疑你的判断力。
仁菜：Handoff 的好处是什么？
桑多涅：两个。每个 Agent 对自己的任务边界最清楚，判断往往比外部 Orchestrator 更准；而且没有中央瓶颈，扩展性更好。
仁菜：那风险呢？
桑多涅：最大的风险是没有全局视角导致死循环。A 交给 B，B 交给 C，C 又交回 A，转不出来 —— 而且每一次交接，单看都是合理的。
仁菜：因为每个 Agent 都只看自己那一小块。
桑多涅：所以必须设计好职责边界，再加防循环机制 —— 比如记录任务经过了哪些 Agent，重复经过同一个就强制终止。
仁菜：这就是第十一集说的，去中心化在生产上的老问题。
桑多涅：Handoff 本质上是一种受控的去中心化。它把好处留下了一部分，但那些老问题一个都没消失，只是要你自己补上。
