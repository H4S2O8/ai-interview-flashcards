tools第11集　Function Calling、Skill、MCP 这三个有什么区别？
============================================================

仁菜：欢迎回来。我是仁菜。冰泡芙 —— 你看，我小口咬，奶油一滴没溅。
桑多涅：……进步。三天。今天上总纲：Function Calling、MCP、Skill，三个到底什么区别。上季第一集你串过 MCP 和 A2A，第六集讲过 FC 和 MCP 两个，今天补齐第三个维度，把整个坐标系立起来。先答。
仁菜：这个我提前画了张图。它们是不同时期搞出来的三样东西：Function Calling 是 OpenAI 的方案，MCP 和 Skill 是 Anthropic 的方案，各有侧重 —— FC 管函数调用，MCP 管工具标准化，Skill 管流程模板。应该是……各管一摊吧？不过说实话，我不太确定它们之间有没有层级关系。
桑多涅：前半段沾边，后半段露怯。三个不是并列的选项，是从底到顶的三层架构：Function Calling 是最底层的调用语言，MCP 在它之上做工具标准化，Skill 在最顶层封装知识和流程。你的图，竖起来 —— 层和层之间是踩着的，不是并排站着的。
仁菜：踩着的……我这张图全白画了。那你给我一个立起来最快的抓手。
桑多涅：三句话，听主语。Function Calling 是模型说：「我要调这个函数」。MCP 是工具服务说：「我能提供这些函数」。Skill 是操作手册说：「用这些工具，按这个流程做」。主语不一样，说话的对象不一样，管的粒度也不一样 —— 这就是三者的本质差异。
仁菜：模型、工具服务、手册……主语一换，位置就出来了。那时间线呢？我总觉得这三个不是同一天出生的。
桑多涅：顺着时间线走，就是这一季你走过的路。最早，模型只会生成文本，怎么让它能触发外部调用？—— Function Calling，第一集到第三集讲的调用语言。等它普及了，新痛点冒出来：每个应用都要自己写代码对接工具，数据库一套、文件系统一套、接口又一套，全是重复劳动 —— 第六集你算过的四十份对接代码。于是 MCP 出来，把接入标准化，一次实现到处复用。再后来，工具有了、接入也标准化了，又冒出新问题：Agent 一堆工具在手，不知道按什么流程、什么标准干活 —— 于是 Skill 出来，把知识和流程打包。每一步都是上一步的成熟催生了下一步的问题。
仁菜：所以根本不是三家比赛，是一个问题解决完，冒出下一个问题 —— 层是问题堆出来的。那每一层具体发生在谁和谁之间？
桑多涅：第一层，Function Calling，发生在模型和函数之间 —— 单次调用的格式规范，模型吐 tool_calls，宿主程序执行，结果喂回，全在单个 Agent 内部，最底层的通信语言。第二层，MCP，发生在 Client 和 Server 之间 —— 工具的标准化封装，Client 连上 Server 自动发现工具，转成 Function Calling 格式喂给模型。它本质上是对 Function Calling 的封装和管理，让工具从应用里的代码片段，变成独立的标准化服务。第三层，Skill，发生在 Agent 和知识模块之间 —— 扫描列表、判断相关、加载手册，粒度比工具粗得多，一个「代码审查」就是一个 Skill。
仁菜：层级我立起来了。那 —— 让我来。你每次都说缺一不可，这次跳层实验我自己来：抽掉最底下的 Function Calling 会怎样？
桑多涅：你说。
仁菜：模型连「我要调哪个函数」都说不出来，上面两层全部悬空 —— 厨房还在、菜谱还在，手废了，什么都做不了。抽掉 MCP 呢？手还在、菜谱还在，但家里什么厨具都没有，对着菜谱干瞪眼。抽掉 Skill？手也灵、厨具也全，但面对一桌食材不知道先切什么后炒什么，瞎折腾。三层……缺一不可，各管各的。
桑多涅：……预判成功。这是这一季你第一次抢在我前面把话说全。
仁菜：记下了！今天几号来着 —— 这一刻值得记进简历！
桑多涅：记进面试。再把三层的完整场景串一遍，你那张废图就能扔了。场景：用户说，帮我分析最近三个月的销售数据，找出下滑的产品线，给改进建议。
仁菜：我来走。第一层，Skill：Agent 扫列表，匹配到「数据分析报告」，加载它的 SKILL.md —— 里面写着三步：取数、做趋势分析、按模板出报告。第二层，MCP：它的 Client 早连着数据库 Server 和 Python 执行器 Server，query_database 和 run_python 随时候着。第三层，Function Calling：模型判断要查数，吐 tool_calls，路由到数据库执行，结果回来接着算，再调 Python 跑趋势，最后按 Skill 给的模板出报告。Skill 编排、MCP 管工具、Function Calling 传话 —— 三层各司其职。
桑多涅：链路完整。最后送你一个上桌就能用的类比 —— 做菜。Function Calling 是手：能拿刀、能点火、能翻锅，最基础的操作能力；MCP 是厨房：刀在抽屉里、调料在架子上、食材在冰箱里，进厨房就知道有什么可用；Skill 是菜谱：先热锅凉油，再姜蒜爆香，然后下主料，最后调味出锅。
仁菜：等等 —— 手？上季第一集你不是说模型没有手吗！
桑多涅：上季说的是模型自己不长手。Function Calling 就是模型伸出去的那只手 —— 手还是长在宿主程序身上，但递东西的动作，是模型让它递的。别把两句话记成矛盾，它们是同一句话的上半句和下半句。
仁菜：上半句模型无手，下半句 FC 是它伸出去的手……好，这题这样答出来是有画面的。我总结：三个不是竞争方案，是从底到顶的三层 —— 调用语言、工具箱、知识流程封装；三句话三个主语；时间线是问题催问题；链条 Skill 定流程、MCP 供工具、Function Calling 触发调用；做菜 —— 手、厨房、菜谱，跳哪层瘫哪层。
