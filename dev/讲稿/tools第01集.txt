tools第01集　什么是 Function Calling？原理是什么？
============================================================

仁菜：欢迎回来。我是仁菜，这季讲工具调用。先交接 —— 歌剧院蛋糕，九层的。上季谁撂的「标准要涨」，我就涨给谁看。
桑多涅：……嗯，规矩没破。坐吧。简历投了？
仁菜：投了！一家做 Agent 平台的公司，一面在下下周三。
桑多涅：十来天。那别寒暄了，第一题就是地基：什么是 Function Calling，原理是什么。你不是背过么，答。
仁菜：这个我真背过！模型收到一份工具清单，输出一段 JSON，写清楚要调哪个工具、参数是什么，然后它就拿这段 JSON 去调 API，拿到结果再回答用户。
桑多涅：停。「它就拿这段 JSON 去调」—— 谁？
仁菜：它啊。
桑多涅：它是谁。
仁菜：模型啊……
桑多涅：模型拿什么调？网线长在它身上吗？
仁菜：……不是有那种执行环境吗，沙箱？我见过产品里模型自己跑代码的。
桑多涅：那是产品在模型旁边配的执行器，是别人替它装的手，不是模型自己长出来的。模型从头到尾只干一件事：输出文本。那段 JSON 一吐完，它就停了，坐在那儿等。
仁菜：等……那谁去跑？
桑多涅：你的代码。上季第一集的话还记得吧 —— 模型是大脑，不是手脚。
仁菜：记得记得……那等一下，我想明白我错哪儿了。我把「下指令」和「执行」捏在一块儿了。它发出指令是真的，但它发完就停了，动的是我。
桑多涅：自己想通的不算我打脸。记这句：模型决策，代码执行。模型只负责说出「我要调什么、参数是什么」，真正跑函数、碰网络、查数据库的，全是你的宿主代码。
仁菜：那我再退一步，要是我嫌写 JSON 麻烦，让模型说人话，我代码解析人话去调，行不行？它说「我要查天气」，我就去查。
桑多涅：它说「天气好烦啊」，你查不查？
仁菜：……那不查啊。
桑多涅：你拿什么分？
仁菜：关键词？出现「查」和「天气」就调？
桑多涅：它说「北京今儿个天儿咋样」，你关键词里备了「咋样」吗。它说「帮我把明后两天的天气发我邮箱」，这是几个工具，先调哪个。你打算写多少 if？
仁菜：……写不完。话是活的，我那几条规则是死的。
桑多涅：所以 Function Calling 才要出来：模型不说人话了，直接吐 JSON，函数名、参数，字段全定死，你的代码照字段拿。
仁菜：哦 —— 我懂了，就是填表！它把表填好递过来，我照着表去跑。
桑多涅：……嗯。这个比喻能用。
仁菜：你夸我！
桑多涅：我说能用。这套东西二零二三年 OpenAI 先做的，现在 Claude、Gemini、Qwen 都跟进了，格式统一了，大家才接得上。
仁菜：那模型填表之前，总得知道有哪几张表吧？
桑多涅：你提前给它。每个工具一份 JSON schema：叫什么、能干嘛、要什么参数。上季你管它叫什么来着 —— 招聘启事。
仁菜：你还记得！
桑多涅：启事写得越明白，来的人越靠谱。我问你，description 那栏只写「获取天气」四个字，用户问「这周天气怎么样」，模型会怎么办？
仁菜：这周是七天，工具查的是当天……它会拒绝吧？
桑多涅：它会硬调，「这周」都能给你塞进城市参数里。
仁菜：为什么啊？它不觉得奇怪吗？
桑多涅：它不奇怪，它眼里只有你写的那段描述。你写「查询指定城市的实时天气，含气温、天气状况、风向风速，仅支持中国大陆城市」，它就填得对；你写「获取天气」，它就瞎填。参数的 description 也一样，格式、示例、限制，全写上。
仁菜：所以 description 不是注释，是它的产品说明书。写烂了它调错，锅在我。
桑多涅：这句面试能直接用。
仁菜：那流程走起来什么样？
桑多涅：两轮对话，中间夹一次真执行。第一轮，schema 加用户问题一起给它；它要调工具，就不给答案，回一个 finish_reason 标成 tool_calls 的响应，里面带函数名和参数。
仁菜：这是它在举手：我答不了，先帮我跑一下。
桑多涅：对。你的代码解析、执行，再把结果当成一条 role 是 tool 的消息塞回对话，再调它一次，它才组织出最终答案。
仁菜：那用户不就多等了一轮？一问一答变一问两答。
桑多涅：一次推理加一次执行，延迟是真实代价，这轮省不掉。能省的在别处 —— 用户问「北京、上海、广州天气都查」呢？
仁菜：也两轮？
桑多涅：tool_calls 是个列表，它一次能甩三条，一城一条。你的代码同时发出去 —— asyncio.gather 也好，多线程也好 —— 结果一把塞回，第二轮直接出总结。
仁菜：那全都并了呗，省时间！
桑多涅：又来了。上季犯多少回了，见着更强的就想全用。
仁菜：这回我有理由的，你说能省延迟 ——
桑多涅：省延迟有前提。先查订单号，再拿订单号查物流，能同时跑吗？
仁菜：不能，第二条得等第一条……哦，所以列表里的调用互不等结果，才能并。
桑多涅：有依赖就老实串行，它自己会分轮，不用你教。能说出代价和边界，才像做过项目的人。
仁菜：又是这句。
桑多涅：这句你会听到面试为止。
仁菜：行行行。那我过一遍：模型只负责输出 JSON 请求，不执行，执行全在宿主代码；工具靠 schema 描述，description 是它判断的唯一依据，必须写细；流程是两轮对话夹一次执行，finish_reason 标成 tool_calls 就说明它调完了……
桑多涅：停。那是它「还没答完、等着执行」的信号，不是「调完了」的回执。
仁菜：对，是举手，不是收工。……然后没依赖的才并行，有依赖老实串行。完了。
桑多涅：磕绊不少，点都在。这么答，能过。
仁菜：那给个整体评价 ——
桑多涅：蛋糕，及格。
仁菜：哦。也是及格。
桑多涅：下集，蒙布朗。栗子要整颗的。
仁菜：还涨？！……行行行，买。下集讲它这身调工具的本事是哪儿练出来的 —— 模型又不会天生填表。我是仁菜，我们下集见。
