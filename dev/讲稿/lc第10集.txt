仁菜：……欢迎回来，我是仁菜。现在是晚上十一点四十。
桑多涅：绿豆汤在你右手边。已经不烫了。
仁菜：……诶？你什么时候来的。
桑多涅：九点。你戴着耳机没听见。
仁菜：……你坐了两个半小时？！
桑多涅：我在等你删。
仁菜：……等我删？
桑多涅：这一季我跟你换的东西，不是甜点。
仁菜：……那是什么呀。
桑多涅：这个样本。
仁菜：……什么样本。
桑多涅：一个人在工期里，把自己写了十二天的东西亲手删掉。
仁菜：……
桑多涅：我做研究，不做交付。这种数据我自己拿不到。
仁菜：……所以你是来看我删的。
桑多涅：我不帮你写。我只看。
仁菜：……说得可真难听。
桑多涅：进度。
仁菜：只剩十三天——二十三个节点，我删到第十一个了。
桑多涅：停一下。
仁菜：……又错了吗。
桑多涅：昨天我让你别急着全删——你现在在删哪几个。
仁菜：……全部。我想干脆回到 create_agent，一个都不留。
桑多涅：……
仁菜：怎么了嘛。
桑多涅：昨天你从一个极端跑到另一个极端。今天你又要跑回来了。
仁菜：……
桑多涅：昨天讲的是它们是什么关系——今天只回答一个问题。
仁菜：……哪个问题。
桑多涅：你该不该用。
仁菜：那我先问一句——LangGraph 的优势，是不是就是多了一张流程图，复杂项目用它看起来更高级？
桑多涅：……图不是装饰。
仁菜：诶？
桑多涅：State、节点边界、并行汇合、检查点、中断与恢复，全都要进入执行语义。
仁菜：……执行语义。
桑多涅：只画一张图，解决不了可靠性问题。
仁菜：那它的核心优势该怎么说呢。
桑多涅：把复杂 Agent 的运行过程，变成显式、可持久化、可观察、可恢复的业务状态机。
仁菜：……四个词。
桑多涅：这一句就是这题的答案骨架，后面全是它的展开。
仁菜：那我还是想不清什么时候该用它呀。
桑多涅：先问一句话就够了——这个系统最难的是让模型会用工具，还是让整个任务可靠地走完一条复杂路线。
仁菜：……我们的呢。
桑多涅：你自己答。你那三个留下来的节点是干嘛的。
仁菜：权限校验、金额高转人工、失败补偿。
桑多涅：这三个，模型能替你决定吗。
仁菜：……不能。这三个错一次就是事故。
桑多涅：那你先别删——我们从头讲一遍为什么。
仁菜：……好。
桑多涅：标准工具调用 Agent，一复杂就容易让人失去控制。为什么。
仁菜：……因为工具变多了？
桑多涅：因为模型通常既在理解问题，又在决定下一步做什么。
仁菜：……两件事压在同一个地方。
桑多涅：两三个工具的时候没问题。加上权限校验、并行取证、质量评估、人工审批和失败补偿之后呢。
仁菜：……那就得把所有规则都写进 Prompt。
桑多涅：那等于什么。
仁菜：……等于把业务流程交给一个概率模型临场发挥！
桑多涅：所以 LangGraph 的核心价值，是让确定性规则和模型决策各自待在合适的位置。
仁菜：哪些交给模型呢。
桑多涅：需要判断的步骤交给 Agent。
仁菜：哪些不交。
桑多涅：权限、金额阈值、审批顺序和结束条件，写成节点与边。
仁菜：……那模型还有自主性吗。
桑多涅：有。但自主性被放在明确的护栏里。这句话很重要，你记一下。
仁菜：……记下了。那 State、Node、Edge 到底该怎么理解呀。
桑多涅：拿采购流程比——State 是什么。
仁菜：……一张单子？
桑多涅：一张不断被补充的申请单。
仁菜：那 Node 呢。
桑多涅：预算检查、合规检查这些办事窗口。
仁菜：Edge 就是……材料下一步送到哪里！
桑多涅：这就是 StateGraph 最核心的三个角色。那如果预算和合规同时往申请单里写结果呢。
仁菜：……谁也不能覆盖谁。
桑多涅：所以要谁来管。
仁菜：Reducer——规定怎么合并更新。
桑多涅：基础懂了，两个高级原语就好理解了。一个节点既要改状态又要改道，用什么。
仁菜：……不知道。
桑多涅：返回 Command。
仁菜：那另一个呢。
桑多涅：运行时才知道要派出多少个研究任务，用 Send 动态分发。
仁菜：……运行时才知道数量。
桑多涅：先理解它们解决的问题，比一次背下所有类名重要。
仁菜：那这比多一张流程图，到底多在哪呀。
桑多涅：图结构会直接决定执行。
仁菜：……决定什么呢。
桑多涅：哪些节点能并行，哪些必须等前置任务完成。
仁菜：还有呢。
桑多涅：哪份状态会被保存，恢复后从哪里继续。
仁菜：……所以它们不再只是文档上的约定。
桑多涅：这就是显式的意思——显式状态还有一个工程好处，你想得到吗。
仁菜：……想不到。
桑多涅：可以把输入、输出和内部状态分开。
仁菜：……分开有什么用呢。
桑多涅：外部请求只提交用户问题——内部节点维护证据、风险分、重试次数和审批意见。
仁菜：最后只返回对外结果。
桑多涅：所以复杂流程的中间变量不必全部塞进消息历史。
仁菜：……也不必让每个节点看到所有数据！
桑多涅：……你今天反应快。
仁菜：……因为这个我正在受苦。我那二十三个节点全共享一份大状态。
桑多涅：那就说到责任了——自由度大，责任也大。
仁菜：……State 字段怎么设计、并行写入怎么合并、节点边界切多细，全是我的事。
桑多涅：LangGraph 不会因为你用了图，就自动让流程合理。
仁菜：……错误的 State 设计照样会状态膨胀、并发覆盖、难以维护。
桑多涅：这句你是从经验里说的，还是从我这儿听的。
仁菜：……经验。上周三我调了六个小时。
桑多涅：那就对了。下一块，编排 API。你只知道 StateGraph 吧。
仁菜：……还有别的？
桑多涅：还有 Functional API。两者共享同一套运行时能力，但编程方式不同。
仁菜：什么时候用 Graph API 呢。
桑多涅：复杂分支、并行汇合、多 Agent 路由，或者团队需要直观看清每条路径。
仁菜：那 Functional API 呢。
桑多涅：如果团队已经有一大段普通 Python 流程，只是希望增加检查点、任务恢复和人工暂停。
仁菜：……等一下。
桑多涅：怎么。
仁菜：……再说一遍。
桑多涅：已经有一大段普通 Python 流程，只想增加检查点、任务恢复和人工暂停。
仁菜：……那不就是我那个数据处理段吗！
桑多涅：那段多长。
仁菜：四百多行——我这十二天一直在想怎么把它拆成节点。
桑多涅：怎么写。
仁菜：……我不知道。你说。
桑多涅：入口用 entrypoint 标。有副作用或者非确定性的操作，用 task 标成可记录任务。
仁菜：那流程本身呢。
桑多涅：仍然可以写普通的 if、for 和函数调用。
仁菜：……不用拆成节点。
桑多涅：不用。
仁菜：……
桑多涅：怎么了。
仁菜：……我这十二天里，有四天在做一件根本不需要做的事。
桑多涅：……喝汤。
仁菜：……嗯。
桑多涅：而且两者也不是二选一。
仁菜：……还能混着用？
桑多涅：外层多 Agent 调度用 StateGraph，某个数据处理节点内部再调 Functional API 工作流。
仁菜：……那我的结构就出来了。
桑多涅：面试时能说出这一层，说明你理解的不是某套固定模板。
仁菜：……而是怎么按复杂度选表达方式。
桑多涅：下一块——一个 Agent 跑几十秒，进程挂了怎么办。
仁菜：让用户重试呗。
桑多涅：跑几小时呢。期间已经查了数据库、调了外部服务，还在等审批。
仁菜：……重新从第一步开始。
桑多涅：那会怎样。
仁菜：……浪费 Token。
桑多涅：还有。
仁菜：……重复发邮件！重复创建订单！
桑多涅：所以 persistence 会在图执行过程中保存 checkpoint，按 thread_id 组织线程状态。
仁菜：……那服务重启了呢。
桑多涅：从已保存状态恢复——官方把 durable execution 作为核心能力。
仁菜：那它重点是落盘吧。
桑多涅：……不只是落盘。
仁菜：那是什么呀。
桑多涅：把任务结果、状态快照和恢复位置，一起纳入运行时。
仁菜：……三样。那 Checkpointer 和 Store 我知道，前天讲过。
桑多涅：那你用一句话说清它们各回答什么问题。
仁菜：……Checkpointer 回答这次任务走到哪里。
桑多涅：Store。
仁菜：以后其他任务还要记住什么。
桑多涅：……这个说法比官方文档还清楚。真实项目经常同时用，不是二选一。
仁菜：那有了 Checkpointer，是不是就绝对不会重复执行了！
桑多涅：……你自己听听。
仁菜：……我又来了。
桑多涅：这句话在面试里说出来，反而暴露你对恢复机制理解不够。
仁菜：……为什么呢。
桑多涅：恢复的时候，节点里的代码可能重新执行。
仁菜：……整个节点重跑？
桑多涅：从旧 checkpoint 重放时，后续的模型调用和 API 请求也会再次发生。
仁菜：……那外部副作用怎么办呀。
桑多涅：必须有幂等保护——业务幂等键、upsert、发送记录，或者先查后写。
仁菜：……四种手段。
桑多涅：复杂节点还应该把非确定性操作和副作用划分成更清楚的恢复边界。
仁菜：……所以框架给的是基础设施。
桑多涅：它不能替业务自动发明幂等语义——这句是加分句。
仁菜：记下了。那人工介入这块呢？昨天讲过一点。
桑多涅：昨天讲的是它和中间件的区别——今天讲它为什么值得。
仁菜：……好。
桑多涅：Agent 进了生产系统，完全自治往往不是终点。哪些动作要人看一眼。
仁菜：退款、付款、删库、发正式邮件、发布内容。
桑多涅：还有一类更麻烦。
仁菜：……什么呢。
桑多涅：要等人工补充材料、修改状态，甚至等几天之后再继续。
仁菜：……几天。
桑多涅：interrupt 可以放在节点内部任意位置。触发的时候，运行时保存状态。
仁菜：然后呢。
桑多涅：把一个可序列化的中断载荷交给外部系统。流程可以一直等。
仁菜：那怎么恢复呀。
桑多涅：用相同的 thread_id，加一个 resume 命令。
仁菜：外部输入去哪儿了呢。
桑多涅：成为 interrupt 的返回值。
仁菜：……就在那一行接住了。
桑多涅：这比只支持确认或取消灵活在哪。
仁菜：审核员可以批准、拒绝，还可以改金额、补证据、给反馈。
桑多涅：后续路由呢。
仁菜：根据这份输入决定去哪。
桑多涅：多级审批怎么办。
仁菜：……拆成多个节点？
桑多涅：让每个角色只看到自己需要的信息。
仁菜：……这个我们业务真的需要。财务和法务看的不是一份东西。
桑多涅：那什么时候不必用它。
仁菜：……如果只是对几个敏感工具做批准、编辑或拒绝。
桑多涅：那 HumanInTheLoopMiddleware 通常更省事。LangGraph 的优势出现在哪。
仁菜：审批对象不是一个标准工具调用的时候。
桑多涅：还有。
仁菜：暂停点要嵌进更长的业务工作流的时候。
桑多涅：还有一个坑必须主动说，不说会被追问。
仁菜：……什么坑呀。
桑多涅：节点恢复时，会从节点开头重新执行。
仁菜：……不是从 interrupt 那一行继续？
桑多涅：不是。
仁菜：……那中断之前的副作用！
桑多涅：也要幂等。还有两条 —— interrupt 的调用顺序不要随意改变，中断载荷要保持可序列化。
仁菜：……三条一起记。
桑多涅：下一块——传统脚本失败了，开发者一般只有两个选择。
仁菜：整段重跑，或者……手工改数据库。
桑多涅：改完呢。
仁菜：……祈祷流程能继续。
桑多涅：LangGraph 把失败处理变成工作流的一部分。官方文档拆成可组合的三层。
仁菜：第一层是什么呢。
桑多涅：Retry Policy，按异常类型和退避策略重试。
仁菜：第二层。
桑多涅：Timeout，限制单次尝试的时间。
仁菜：第三层。
桑多涅：Error Handler，在重试耗尽之后接管错误。
仁菜：接管了能干嘛呀。
桑多涅：处理函数可以返回 Command，一边更新错误状态，一边把流程送往降级、补偿或者人工处理节点。
仁菜：……失败也有路线。
桑多涅：那并行节点失败会怎样。
仁菜：……全部重来？
桑多涅：同一步里已经成功完成的节点，结果会被保存。
仁菜：……所以恢复的时候只重试失败的那部分！
桑多涅：这对并行抓多个数据源特别有价值。为什么。
仁菜：……不然一个慢接口失败，其他已经成功的请求也要重新付一次钱。
桑多涅：……嗯。那时间旅行解决的是另一个问题。
仁菜：什么问题呢。
桑多涅：通过状态历史找到旧 checkpoint，可以从旧位置重新执行。
仁菜：……还能改状态吗。
桑多涅：可以先修改旧状态，再分出另一条轨迹。
仁菜：那它适合什么呀。
桑多涅：复现 Agent 为什么走错路，尝试不同的人工决策，或者修正错误的中间状态。
仁菜：……那不就等于时光倒流吗！
桑多涅：……又夸大了。
仁菜：诶？
桑多涅：它不是把程序时光倒流之后原样播放录像。
仁菜：……那会发生什么。
桑多涅：checkpoint 之前的节点跳过，之后的节点重新执行。
仁菜：……所以模型输出、网络响应和外部副作用可能不一样。
桑多涅：它提供的是可定位、可重放、可分叉的调试基础。
仁菜：……不是自动撤销现实世界已经发生的操作。
桑多涅：这句必须说——说了，面试官知道你真用过。
仁菜：……那并行和汇合呢。深度研究那类为什么适合图呀。
桑多涅：因为它往往不是一个 Agent 从头想到尾。你说说它是什么样。
仁菜：……先拆主题，再并行搜索多个来源。
桑多涅：然后。
仁菜：交叉验证、合并证据。
桑多涅：发现空白呢。
仁菜：继续补搜，最后统一写报告。
桑多涅：所以 Graph API 支持把一个任务拆成多条并行分支，再把结果汇合回来。
仁菜：那数量不确定的时候呢。
桑多涅：运行时才能确定，就用 Send 动态创建分支。
仁菜：并行更新同一个字段呢。
桑多涅：必须通过 Reducer 明确合并方式。
仁菜：……不能指望最后写入者碰巧正确。
桑多涅：那子图解决什么。
仁菜：……模块化？
桑多涅：一个完整的 create_agent 返回的本来就是图，可以直接作为外层 StateGraph 的节点或子图。
仁菜：……那不同团队呢。
桑多涅：可以分别维护研究、合规、财务这些子图。
仁菜：父图要知道内部细节吗。
桑多涅：只要约定好输入输出状态，就不必知道。
仁菜：……那子图的记忆呢。
桑多涅：需要显式选择——一次性子任务，让每次调用都从新状态开始。
仁菜：要连续记忆的呢。
桑多涅：才让子图在同一线程的多次调用之间积累状态。
仁菜：完全无状态更简单吧。
桑多涅：更简单，但也不能依赖中断与可靠恢复能力。
仁菜：……那多 Agent 是不是效果一定更好呀？
桑多涅：……你猜。
仁菜：……不一定。
桑多涅：角色越多，提示词、上下文交接、错误定位和 Token 成本越高。
仁菜：那什么时候单 Agent 就够呢。
桑多涅：很多交接场景，用单 Agent 加 middleware 会更简单。
仁菜：那子图什么时候才值得引入。
桑多涅：角色需要不同工具、不同状态结构、独立生命周期。
仁菜：还有呢。
桑多涅：确实需要并行，或者要跨团队维护。
仁菜：……记下了。那流式这块，昨天讲了事件类型，今天讲什么呀。
桑多涅：今天讲它为什么是产品问题——复杂 Agent 常常不是慢在最后回答。
仁菜：……那慢在哪。
桑多涅：搜索、文件处理、子 Agent 调用和人工等待。
仁菜：那前端只显示一个转圈图标的话……
桑多涅：用户不知道系统卡住了，还是仍然在工作。
仁菜：……那能显示什么呢。
桑多涅：正在查询政策库——已完成五个来源里的三个。等待财务审批。
仁菜：……这三句我一听就懂了。
桑多涅：因为 streaming 不只有模型 Token。还有每步 State 更新、模型消息、自定义进度、checkpoint 和任务状态。
仁菜：那直接用 LangGraph 的好处呢。
