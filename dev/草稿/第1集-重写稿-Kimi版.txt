第一集：什么是 Agent？与大模型有什么本质不同？
（播客稿｜仁菜 × 周老师｜目标：听完本集无需再看原文）

仁菜：欢迎收听《Agent 面试课》，我是仁菜，一个在 Agent 方向摸爬滚打的研究生。这一季十六集，我们把 Agent 面试高频题一题一集讲透，目标很明确：听完每一集，原文就不用再翻了。第一集先上最经典的一道：什么是 Agent？它跟大模型到底有什么本质不同？今天请来的还是面试官周老师。

周老师：我是周老师。这道题几乎场场必问，开口翻车的概率也最高。仁菜，你今天专业对口，先别急着当主持人，先当一回考生，咱们把面试现场演一遍。

仁菜：行，放马过来。Agent 嘛，我给个标准答案：就是给大模型加了插件，比如 ChatGPT 的插件功能，能联网搜索、调用 API 啥的。

周老师：停。插件是 Agent？那照你这么说，ChatGPT 开了搜索功能，它就是 Agent 了？你说的只是工具调用，跟 Agent 差远了。

仁菜：啊这……那我改口：Agent 就是能调用工具的大模型，给它配几个工具函数，它就能做更多事了。这总行了吧？

周老师：还是不行，还是停在工具调用。我问你，Agent 最核心的是什么？你有没有提到「自主」这两个字？

仁菜：自主……就是它自己决定调哪个工具？

周老师：还不够。真正要答出来的是：自主规划、多步执行、感知结果再调整。你给它一个目标，它自己把任务拆成多步，一步一步做，每一步的结果反馈回来，再指导下一步怎么走。这是一个闭环，这才是和普通调工具的本质区别。

仁菜：懂了，三连跪。大家记住我血的教训：答这道题先抓一个核心词，自主闭环。那简要回答的标准开场怎么说？这次我好好记笔记。

周老师：可以这样说：我理解 Agent 本质上是一个能自主完成目标的 AI 系统，它跟传统 AI 最核心的区别在于「自主性」和「能行动」。传统 AI 是你问一个问题它回答一个问题，每次都是独立的、被动响应；而 Agent 有自己的规划能力，你给它一个复杂目标，它会自己拆成多步，通过调工具、访问记忆、感知环境，一步一步执行，直到完成。它不只是输出文字，而是真的能做事。

仁菜：我用我自己的话复述一遍，你听听对不对：普通大模型是个答题的，Agent 是个干活的。

周老师：话糙理不糙。那进入详细解析。要理解 Agent，得先搞清楚普通大模型的局限在哪。仁菜你天天调 API，你先说说，直接调 GPT 的 chat 接口，它本质上是个什么东西？

仁菜：嗯……一个特别贵的 autocomplete？开玩笑。它就是一问一答，你给它输入，它给你输出，完事。

周老师：对，它本质上是个「问答机器」。就算是多轮对话，它也只是在当前上下文里被动响应你。它不会主动去做任何事，也不知道自己上一步做了什么、下一步该做什么。你可以把它想象成一个只会答题的人，你说一句它答一句，但你让它「自己去查个资料再来向你汇报」，它完全做不到。

仁菜：那它的局限咱们一层一层拆。第一层我先猜：知识被冻结？训练数据有截止日期，你问它今天的天气、最新的股价，它完全不知道，因为它没有任何途径获取实时信息。

周老师：可以啊，这个猜得准。就像一个人毕业之后再也不看新闻了，你问他今天发生了什么，他只能给你讲课本上的知识。

仁菜：这不就是我期末考完的状态吗，知识原封不动还给老师。好，第二层。

周老师：第二层更本质：它不能行动。你让它帮你发邮件、帮你查数据库、帮你执行一段代码，它只能告诉你「你可以这样做」，但它自己做不到。因为它本质上就是一个文本生成器，所有输出都是一串文字，仅此而已。

仁菜：也就是说，它能给你写出一封完美的邮件正文，但点那个「发送」按钮的事，它是真做不了。就像我嘴上说改论文，手从来没动过。

周老师：这个类比我不予评价。第三层：没有持续状态。每次调用之间它是完全失忆的，除非你手动把之前的对话塞进去，不然它根本不记得上一轮说了什么，更别说跨任务去记住你的偏好了。

仁菜：金鱼记忆啊。所以哪怕我只想让它干一件稍微复杂点的事，比如先查资料再整理成报告，它也干不了——第二步还没开始，它已经把第一步忘了。

周老师：对。这三个局限一环扣一环：知识是死的，手脚是没有的，记忆也是断的。加在一起，普通大模型只能做一问一答，稍微复杂、需要多步骤协作的任务，它完全无能为力。

仁菜：短板清楚了。那 Agent 特别在哪？我猜核心就是你刚才说的那个闭环。

周老师：对。Agent 的核心运作闭环是：感知，到规划，到行动，再到感知。你给它一个目标，比如「帮我调研竞品然后整理成报告」，它不是直接输出一段文字了事，而是先拆任务：我要搜索哪些关键词、访问哪些网站、怎么组织内容，然后一步一步执行，每一步的结果再反馈回来，指导下一步怎么做。

仁菜：这不就是我跑实验的日常吗：看结果、调方案、再跑一轮。欸，照这么说，我是不是也算一个 Agent？

周老师：你最多算一个需要导师催进度的 Agent。这个闭环背后，有三件核心的事在支撑，一件一件讲。第一件，工具调用，英文 Tool Use，这是让 Agent 从「说话」变成「做事」的关键。Agent 能调搜索引擎、代码执行器、数据库、各种 API。

仁菜：等等，我有个傻问题。模型调工具，是它自己伸出手去点按钮、发请求吗？

周老师：这问题一点不傻，这恰恰是最容易误解的地方。不是模型自己执行，而是模型告诉你该调什么、参数填什么，你的代码去真正执行，执行结果再反馈给模型。记住这句话：模型始终只是大脑，不是手脚。

仁菜：那为什么工具调用一上来，前面那几个局限就破了？

周老师：你对着看。知识被冻结？接上搜索引擎，模型就能获取实时信息。不能行动？接上邮件 API、代码执行器，模型就能真正做事。就好比一个人原来只能用嘴说话，现在给他配上了手、脚和各种工具，能力上限瞬间拔高一个量级。

仁菜：原文里有个例子我特别喜欢，配了查天气和发邮件两个工具，还有代码。代码没法念，周老师你把它口述一遍，我来拆。

周老师：好。假设你给 Agent 配两个工具。一个叫 get weather，获取指定城市的当前天气，参数只有一个，城市名。另一个叫 send email，发送邮件，参数是收件人、主题、正文。注意一个关键细节：这份工具定义里没有一行真正执行的逻辑，只有名字、描述、需要哪些参数。

仁菜：所以它本质上就是一份「技能说明书」，告诉模型我有哪些能力、需要传什么，对吧？

周老师：对。然后你对 Agent 说：帮我查一下北京天气，然后发邮件给老板。它不是一次性编一段话，而是分两步真正执行。

仁菜：我猜猜这两步。第一步，调用 get weather，城市填北京，拿到结果：晴天，十五度。第二步，调用 send email，收件人填老板邮箱，主题「今日天气」，正文「北京今天晴天，十五度」。对不对？

周老师：全对。每一步都是真实发生的，不是假装。模型读了说明书，自己决定调哪个工具、参数填什么，把决策以 JSON 格式告诉你，真正执行的还是你的代码。「决策和执行分离」，这是理解工具调用最核心的一点，面试说出来很加分。

仁菜：小本本记下了。光有做事的能力还不够，第二件是记事，记忆机制。传统大模型每次对话都失忆，除非手动传上下文。那 Agent 怎么解决的？是不是把所有聊天记录一股脑全塞回去？

周老师：那上下文早撑爆了，不现实。Agent 系统通常设计两层记忆。短期记忆，是当前任务执行过程中的中间状态，比如第一步搜到了什么、第二步计算结果是多少，存在上下文里，保证 Agent 不会做到一半忘了前面发生了什么。长期记忆是跨任务的，比如用户偏好、历史操作记录，通常用向量数据库来存，需要的时候做语义检索拿回来——需要啥拿啥，不是全塞。

仁菜：明白了，短期记忆是它的工作台，长期记忆是它的笔记本，用的时候翻，不是把整本糊脸上。有这两层，它做复杂任务才能保持连贯，不会走着走着忘了目标是什么。

周老师：总结得不错。第三件，多步推理和自我纠错。这件经常被忽略，但它是 Agent 区别于简单自动化脚本的关键。

仁菜：自动化脚本我知道，一步出错全盘崩。Agent 不一样在哪？

周老师：Agent 执行过程中某一步失败了，它不会直接崩掉，而是能感知到失败、分析原因、换一种方式重试。比如用关键词 A 搜索没找到有用信息，它会自己换关键词 B 再搜一次；调用某个 API 报错了，它会看报错信息，调整参数重新调用。

仁菜：这不就是我跑实验挂了看 traceback 再改参数吗……还有吗？

周老师：更进一步，它完成某一步之后还能回头审视：我做的这步对不对？结果和预期一致吗？要不要调整后续计划？这种「边做边反思」的能力，让 Agent 面对复杂、不确定的任务时，远比死板的自动化流程好得多。它像一个真正在思考的执行者，碰到障碍会绕路走，而不是一条路走到黑。

仁菜：三件事齐了。我来自告奋勇收个尾：同样是「帮我发一封天气播报邮件」，普通大模型只能告诉你「你可以这样写代码」；而 Agent 会真的去调天气 API、拿到数据、组织邮件内容、再调邮件发送接口，整个过程自动完成。本质区别一句话：从生成文字，到执行任务！

周老师：说得比我好，这句可以直接拿去面试用。下一个常见追问：Agent 概念其实很早就有，为什么到二零二四、二零二五年才真正火起来？

仁菜：这个我真好奇，按理说工具调用这事儿，早年也不是没人想过。

周老师：因为三个条件最近几年才同时成熟。第一，大模型能力跨过了「能用」的门槛。早期语言模型理解能力有限，你让它做任务拆解、判断下一步该调哪个工具，它根本做不好。从 GPT-4、Claude 3 这一代开始，推理能力、指令遵循有了质的飞跃，它真能读懂复杂指令、做出合理的多步决策了。

周老师：第二，工具调用的标准化。OpenAI 在二零二三年推出 Function Calling，让模型能以结构化的 JSON 格式输出工具调用请求，各家厂商很快跟进。有了统一协议，开发者才能方便地给模型接外部能力，不然每接一个工具都要自己写一套解析逻辑，工程成本太高。

仁菜：也就是说在那之前大家都在手搓解析，太苦了。第三个条件我来猜：生态？框架什么的？

周老师：对，配套生态的完善。LangChain、LlamaIndex 这些框架把 Agent 开发门槛大幅降下来，向量数据库解决了长期记忆怎么存，各种 API 服务让可调用的工具越来越丰富。三个条件凑齐，Agent 才从论文概念变成工程实践，才有了现在的爆发。

仁菜：一句话总结：脑子够用了，接口统一了，轮子造齐了。接下来是我最想听的，MCP 和 A2A——我面试真被问过，当场说串了。

周老师：那你今天正好掰回来。Agent 火起来之后冒出两个新问题：Agent 越来越多，它们之间怎么协作？工具越来越多，怎么统一管理？这两个问题各催生一个协议。先说 MCP，Anthropic 在二零二四年底提出的，全称 Model Context Protocol，模型上下文协议。

仁菜：在没有 MCP 之前是不是很惨？每个 Agent 框架接每个工具都要写一套适配代码，M 个框架乘 N 个工具，就是 M 乘 N 套适配逻辑。

周老师：对，工程成本非常高。所以 MCP 定义了一套标准的 JSON-RPC 协议，工具提供方按标准暴露能力，变成一个 MCP Server；任何支持 MCP 的 Agent 通过内置的 MCP Client，就能直接发现和调用这些工具，不用再写适配代码。

仁菜：这不就是 Agent 工具世界的 USB-C 吗！而且这么一来，适配从 M 乘 N 变成 M 加 N——框架做一遍 Client，工具做一遍 Server，齐活。

周老师：触类旁通，这个推论完全正确。架构上再记三层：最外层是 Host，用户直接交互的 AI 应用，比如 Claude Desktop、Cursor；中间是 Client，负责和 MCP Server 建立连接、管理通信；最里层是 Server，真正暴露工具能力的服务。

仁菜：生态这块我来抢答：二零二五年十二月，Anthropic 把 MCP 正式捐给了 Linux 基金会旗下新成立的 Agentic AI Foundation，简称 A A I F。基金会由 Anthropic、Block、OpenAI 共同创立，Google、Microsoft、AWS、Cloudflare、Bloomberg 都表态支持。现在已经有数千个公开的 MCP Server 可用了。

周老师：功课做得挺足。那 A2A 你接着说，别跟 MCP 讲成一层。

仁菜：我试试。A2A 是 Google 二零二五年四月推的，全称 Agent to Agent，Agent 间通信协议。MCP 解决「Agent 怎么调工具」，A2A 解决「Agent 怎么和另一个 Agent 协作」。多 Agent 系统里，大家来自不同厂商、不同框架，得有个办法互相发现能力、协调任务、传中间结果。核心设计叫 Agent Card，每个 Agent 一张名片，写清它能做什么、正在做什么、需要什么输入，别的 Agent 读了名片就知道怎么跟它协作。

周老师：不错。再补一个时间点：二零二五年六月，Google 把 A2A 捐给了 Linux 基金会维护，SAP、Salesforce、ServiceNow 这些大厂都在接入。

仁菜：所以两个协议是互补不是竞争：MCP 管 Agent 和工具的连接，让每个 Agent 方便地「伸手拿工具」；A2A 管 Agent 和 Agent 的通信，让不同 Agent 方便地「互相说话合作」。未来大概率两个协议同时存在、各管一层。面试把这层定位和区别讲清楚，非常加分。

周老师：可以出师了。最后面试总结。回到开头的现场，仁菜考生一共踩了三个典型的雷，自己数数？

仁菜：我数，我数还不行吗。第一个雷，把 Agent 等同于插件或工具调用——工具调用只是 Agent 能力的一部分，不是 Agent 本身。第二个雷，停在「能调工具」，没点出自主性——关键不是「有工具」，而是「自己决定用不用、什么时候用、用哪个」。第三个雷，忽略执行闭环——感知、规划、行动、再感知，这个循环才是 Agent 区别于普通大模型的核心机制。三个雷我踩得整整齐齐，一个没落。

周老师：踩得这么标准，也算一种天赋。那正面回答，这道题必须点出三件事：第一，Agent 有自主规划能力，给它复杂目标，它能自己拆成多步；第二，它能行动，通过工具调用跟外部世界真实交互；第三，它有闭环，每步结果反馈回来指导下一步，不是一次性生成完就结束。另外补一句容易混的：模型本身只是「大脑」，工具的真正执行是你的代码，模型只负责决策。这些说全，这道题就答透了，原文也真的可以合上了。

仁菜：感谢周老师手下留情。第一集到这里，下一集我们拆 Agent 的四个核心组件。我是仁菜，我们下集见！
